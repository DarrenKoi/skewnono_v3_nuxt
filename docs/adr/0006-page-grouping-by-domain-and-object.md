# 페이지는 도메인으로 갈라지고, 그 안에서 대상으로 묶입니다

내비게이션의 최상위는 **도메인 분기**입니다 — E-Beam Metrology / 스큐보아 / AFM / Thickness 는 탭 행을 공유하지 않습니다. 그 아래 E-Beam 안에서만 페이지를 **대상**(장비 · 레시피 · 측정)으로 묶되, 그룹은 클릭 단계가 아니라 **순서와 칸막이**로 표시합니다. 계열(CD-SEM/HV-SEM/VeritySEM/Provision)과 성숙도(검증/실험실)는 **위치가 아니라 축**입니다 — 계열은 FAB 과 같은 스코프 컨트롤이고, 성숙도는 배지와 `hiddenOnCloud` 행 플래그입니다.

시안(눌러볼 수 있는 형태): <https://claude.ai/code/artifact/efa6c9ea-321d-4439-9ed2-f5bae1a1be35>

## 왜 지금 구성이 틀렸는가

현재 그룹의 실제 소속 규칙은 페이지의 의미가 아니라 **URL 모양**입니다. 기능 탭은 `/ebeam/<tool>/<fab>/…` 로 라우팅되는 페이지, 실험실은 장비와 관련되나 fab 라우팅이 아니거나 미검증인 페이지, App 정보는 장비와 무관한 페이지입니다. 사용자는 라우팅을 볼 수 없으므로 라벨이 이미 사실과 어긋나 있고, 코드가 그 어긋남을 스스로 남겨 두었습니다.

| 흔적 | 무엇을 말하는가 |
| --- | --- |
| 실험실 한 서랍에 Mag/Pixel(안정된 계산기) · 라이브 알람(운영 중) · TTTM·PM(미검증) · 채팅(대화형) | 공통점이 "기능 탭에 못 들어간다" 하나뿐입니다 |
| 라이브 알람에 `hiddenOnCloud` 가 없음 | 프로덕션까지 나가는 감시 보드가 '실험실' 라벨을 달고 배포됩니다 |
| 채팅의 `separated: true` | 그룹 안에 칸막이가 필요하다는 것은 그룹이 틀렸다는 뜻입니다 |
| 탭 순서가 장비 → 레시피 → 레시피 → 장비 → 측정 → 측정 | 같은 대상인 H/W 관리와 장비 상태가 레시피 두 장 건너에 있습니다 |
| 스큐보아 컴포넌트 70개 · 13,207줄 (나머지 e-beam 기능 전부 56개보다 큼) | 탭 한 칸이 앱 하나를 가리키고 있습니다 |
| `intro.vue` 가 `common/ebeam/lab/afm/admin` 5분류를 따로 발명 | 앱이 스스로를 세 가지로 다르게 설명하고 있습니다 |

## 확정된 구성

E-Beam 기능 탭 **7칸, 3그룹**. `DESIGN.md` 가 적어 둔 "탭 4–7개" 상한 안에 들어오고, 그룹은 칸막이로만 표시하므로 어디든 한 번에 갑니다.

| 그룹 | 탭 | 서브탭 |
| --- | --- | --- |
| 장비 | 장비 상태 | 장비 리스트 · 스토리지 · H/W 관리 · 미연결 장비 |
| 장비 | 라이브 알람 | — |
| 장비 | 장비 튜닝 ᴮᴱᵀᴬ | TTTM · PM 플래닝 |
| 레시피 | Recipe 현황 | TAT · Align Fail · Meas Fail |
| 레시피 | Recipe 검색 | 검색 · 레시피 비교 · Lateral · Recipe Open |
| 측정 | 측정 이력 | — |
| 측정 | 디바이스 통계 | 통계 · 디바이스 비교 · 측정 규칙 |

이동하는 페이지는 다음과 같습니다. 페이지가 새로 생기거나 사라지지 않고, 소속만 바뀝니다.

| 페이지 | 오늘 | 제안 | 이유 |
| --- | --- | --- | --- |
| 라이브 알람 | 실험실 ▾ | 장비 | 운영 중인 감시 화면입니다 |
| TTTM · PM 플래닝 | 실험실 ▾ | 장비 › 장비 튜닝 ᴮᴱᵀᴬ | 이어지는 두 질문이므로 한 탭의 두 서브탭입니다 |
| H/W 관리 | 독립 탭 | 장비 상태 › 서브탭 | 장비 리스트 · 스토리지와 대상이 같습니다 |
| 측정 이력 | Recipe 검색 › 서브탭 | 측정 | `pageIdentity` 가 이미 별도 기능으로 셉니다 |
| 미연결 장비 | 랜딩 하단 버튼 | 장비 상태 › 서브탭 | 장비 목록의 반대쪽 절반입니다 |
| Mag/Pixel · 채팅 | 실험실 ▾ | 도구 ▾ | 스코프가 없어 어디서나 열립니다 |
| 스큐보아 | E-Beam 기능 탭 | 독립 도메인 | 어휘는 공유하나 셸이 다릅니다 |
| AFM · Thickness | 랜딩 카드 | 독립 도메인 | 조인할 데이터가 없습니다 |

## 분기 판정 규칙

"커지고 있다"는 분기의 근거가 아닙니다. 근거는 두 가지이며, 서로 **다른 것을 허락합니다**.

| 근거 | 판정 | 해당 | 얻는 것 |
| --- | --- | --- | --- |
| 다른 도메인 | 장비 · 레시피 · 측정 어휘를 공유하는가? | AFM, Thickness | 자체 라우트 · 백엔드 기능 폴더 · 시각 언어. 공유는 앱 크롬뿐 |
| 다른 상호작용 모델 | "헤더 + 탭 행 + 스크롤 페이지"에 들어가는가? | 스큐보아 | 자체 셸만. 어휘·라우트는 공유하고 되돌아오는 길을 남김 |

이 구분에는 실질적 결과가 있습니다. 스큐보아는 웨이퍼 → 레시피 → 장비로 넘겨줘야 하지만 AFM 은 그럴 대상이 없습니다. 반례로, Recipe 검색은 서브탭이 다섯 개가 되어도 분기하지 않습니다 — 어휘를 공유하고 페이지 셸에 들어갑니다. "다른 스타일을 갖고 싶다"는 증상이지 기준이 아닙니다. 큰 기능은 전부 언젠가 자기 스타일을 원합니다.

## 결과로 따라오는 제약

- **탭은 7칸이 상한입니다.** 여덟 번째가 필요해지면 그룹을 클릭 단계로 올리는 게 아니라, 어느 탭이 다른 탭의 서브탭인지를 다시 묻습니다.
- **미검증 페이지를 숨기는 일은 계속 `hiddenOnCloud` 행 플래그가 합니다.** 서랍은 애초에 숨기는 장치가 아니었고, 배지로 바꿔도 프로덕션 가시성은 그대로입니다.
- **계열은 스코프이므로 지원하지 않는 조합은 흐려집니다.** 백엔드는 같은 결정을 이미 내렸습니다 — 계열은 경로 축이 아니라 `providers/` 축이며, `ebeam/<vendor>/<feature>/` 는 중복 슬러그로 앱이 뜨지 않습니다(`_runtime/office_registry.py`).
- **도메인 전환은 헤더에서 가능해야 합니다.** 현재 `toolTypeHref` 는 랜딩 페이지만 호출하므로 CD-SEM → HV-SEM 이동에 홈을 한 번 거칩니다. 실험실이 비운 메뉴 슬롯이 이 자리입니다.
- **내비게이션 사실이 `.vue` 안에 있으면 테스트되지 않습니다.** `npm test` 는 `node --test "app/**/*.test.ts"` 이고 컴포넌트 마운팅 하네스가 없습니다. `FeatureTabs.vue` 의 `features[]` 가 무방비인 것은 판단이 아니라 **파일 확장자** 때문입니다.
- **디바이스 통계의 셸 분리는 아직 결정하지 않았습니다.** 이미 fabless 라우트에 `hideFabSidebar` 를 들고 있어 세 번째 후보로 보이지만, ADR 0002(담당자·임원이 같은 URL 을 공유)가 이 페이지를 구속합니다. 분리하더라도 URL 은 하나로 유지되어야 하며, 별도 판단이 필요합니다.

## 목록 여섯 개 — 위험은 균등하지 않습니다

같은 페이지 목록이 여섯 곳에 있으나, 실제로 노출된 것은 두 개뿐입니다.

| 목록 | 방어 | 재편 시 |
| --- | --- | --- |
| `utils/headerNav.ts` | 테스트 12개가 그룹 구성을 못 박음 | **시끄럽게 깨집니다** — 방어가 작동하는 것 |
| `utils/pageIdentity.ts` | `__fixtures__/pageIdentityContract.json` 로 프런트↔백엔드 대조 | 라우트가 조용히 못 움직임 |
| `utils/features.ts` | `features.test.ts` | 이미 `toolTypes` · `scope` 축의 주인 |
| `utils/activity.ts` | `activity.test.ts` | 슬러그가 안 바뀌면 무변 |
| `components/nav/FeatureTabs.vue` | **없음** | 세 번의 과거 사고와 같은 형태의 위험 |
| `pages/intro.vue` | **없음** | 자체 5분류를 따로 들고 있음 |

`utils/features.ts` 는 이미 제안된 테이블의 절반 이상입니다 — `FEATURE_SLUGS`(목록), `FEATURE_TOOL_TYPES`(계열 축, 주석이 "the ONE statement of the fact" 라고 적고 있음), `FABLESS_FEATURES` · `SINGLE_FAB_FEATURES`(스코프 축). 빠진 것은 `label` · `icon` · `group` · `domain` · `maturity` 뿐이고, 그것들이 정확히 테스트되지 않는 `.vue` 안에 있습니다. 따라서 안정화 작업은 **새 테이블을 만드는 일이 아니라 이미 있는 테이블의 빈 칸을 채우는 일**입니다.

이 재편의 완료 조건은 "테이블이 생겼다"가 아니라 **"내비게이션 사실이 `.vue` 파일 안에 하나도 없다"** 로 둡니다. grep 으로 확인 가능하므로 다음 세션이 판단할 필요가 없습니다.

이를 위해 컴포넌트 테스트 하네스를 세우지는 않습니다. `.vue` 를 테스트 가능하게 만드는 것보다 `.ts` 로 옮기는 쪽이 훨씬 싸고, 지금 필요한 것은 후자뿐입니다.

## 실행 순서

**축을 정하기 전에 테이블을 설계할 수 없고, 축을 두 번 정해서도 안 됩니다.** 오늘의 축(`group: 'lab' | 'account'`)으로 먼저 추출하면 만들자마자 `domain` 을 더하고 모든 행을 다시 키잉하게 됩니다. 그래서 순서는 "안정화 → 결정 → 이동"이 아니라 **"결정 → 새 컬럼으로 추출 → 이동"** 입니다. 결정은 이 ADR 로 끝났으므로 추출이 이제 열렸습니다.

| 단계 | 내용 | 선행 조건 |
| --- | --- | --- |
| 0 | VeritySEM · Provision 온보딩 | — |
| 1 | 탭 순서 재정렬 + 실험실 해체(도구 ▾ 신설, 라이브 알람 승격, TTTM·PM 배지화) | 0 완료 |
| 2 | `label`·`icon`·`group`·`domain`·`maturity` 를 `utils/features.ts` 로 추출, `FeatureTabs.vue` 가 거기서 렌더 | 1 |
| 3 | 도메인 분기 — 스큐보아 `layouts/skewvoir.vue`, AFM·Thickness 셸, 측정 이력 라우트 이동 | 2 |

**1단계를 VeritySEM · Provision 이후로 미루는 것은 사용자 결정입니다(2026-08-28).** 계열이 넷 다 실재하는 상태에서 재편하면 `enabledToolTypes` 모델이 4계열에서 버티는지 먼저 검증됩니다. 대가는 새 계열 트리에 페이지 래퍼가 먼저 쌓인다는 점이나, 라우트 파일이 얇은 래퍼이므로(예: `recipe-status.vue` 11줄, 공유 View 컴포넌트 호출) 감당 가능한 크기입니다.

1단계와 2단계 사이에는 의존이 없습니다. 탭 재정렬은 배열의 순열이라 아무것도 조용히 사라질 수 없고, 실험실 해체는 테스트가 잘 된 `headerNav.ts` 안에서 일어납니다. 2단계를 실제로 요구하는 것은 3단계입니다 — 그때 `domain` 축을 다섯 소비자가 동시에 합의해야 하고 라우트가 실제로 움직입니다.

## 되돌리기 어려운 이유

도메인 분기는 프런트엔드에서 끝나지 않습니다. AFM · Thickness 가 자체 도메인이 되면 백엔드 기능 폴더와 `_logging/feature_map.py` 의 슬러그가 따라 움직이고, 활동 로그의 30일 랭킹 윈도우에 옛 슬러그로 쓰인 행이 남습니다(`home` · `cdsem` 이 은퇴 후에도 라벨을 남겨 둔 것과 같은 이유). 되돌리려면 같은 이동을 반대 방향으로 한 번 더 해야 합니다.

URL 이동은 더 오래 남습니다. 측정 이력이 `recipe-search/meas-hist` 에서 나오면 forward 된 링크가 일제히 옛 경로를 가리키고, `pm-tune` → `pm-planning` 때처럼 아이덴티티 별칭을 영구히 들고 가게 됩니다(`utils/pageIdentity.ts` 의 `IDENTITY_ALIASES`). 2026-08-17 의 `pm-tune` 우회는 되돌리는 데 47개 파일 수정이 들었습니다(2026-08-27). 이동은 한 번에, 별칭을 남기며 합니다.
