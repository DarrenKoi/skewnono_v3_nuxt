# AFM raw 파일 후속 질문 — Home → Office

- 작성일: 2026-10-02입니다.
- 수신자: 각 AFM 장비에서 파일을 추출·정제하여 적재하는 Office agent입니다.
- 목적: 세 차례 회신으로 raw 파일의 모습은 대부분 알게 되었습니다. 남은 빈칸
  15개를 채우려는 질문서입니다.
- 관계: 첫 질문서 [`to-questionnaire-afm.md`](to-questionnaire-afm.md)를 **대신하지
  않습니다**. 그쪽 5절의 적재 명세(Redis·MinIO의 위치·형식·스키마)는 ETL이 끝난 뒤
  받기로 한 그대로입니다. 이 문서는 raw 파일에 대한 질문만 담습니다.
- 회신 기한: 날짜 기한은 없습니다. 아는 것부터 부분 회신해 주시면 됩니다.
- 회신 현황: 2026-10-02에 15문항과 P1·P2 모두 답을 받았습니다. 답과 그 반영은
  [`office-data-findings.md`](office-data-findings.md)의 4차 회신에 있습니다.

지금까지의 회신 원문은 [`office-data-findings.md`](office-data-findings.md)에,
정리본은 `docs/datatables/afm/afm_raw_files.txt`에 있습니다.

## 1. 답하는 방법

질문마다 **Home의 현재 가정**을 적어 두었습니다. 가정이 맞으면 `맞음` 한 단어면
충분합니다. 다르면 실제 값을 적어 주십시오.

```text
Q1: 맞음
Q4: <실제 파일명 한 건을 그대로>
Q9: 미정
Q15: 미실측
```

- 아직 모르는 것은 `미정`, 해당 사례를 보지 못한 것은 `미실측`으로 구분해 주십시오.
- 추정은 추정이라고 표시해 주십시오.
- **이름과 값은 한 글자씩 그대로** 옮겨 주십시오. 대소문자·공백·밑줄·괄호·단위
  표기가 그대로 웹의 키가 됩니다. 2차 회신의 `COMPLITED`가 3차에서 `COMPLETED`로
  확정된 것처럼, 철자 하나가 값 비교를 바꿉니다.
- 파일명·헤더처럼 긴 것은 실제 한 건을 그대로 적는 편이 설명보다 정확합니다.

## 2. 먼저 답해 주시면 좋은 질문

웹 쪽 설계가 이 넷에 가장 크게 달려 있습니다.

| 번호 | 한 줄 요약 | 달라지는 것 |
| --- | --- | --- |
| Q9 | Site ID가 없는 recipe의 위치 키 | 위치 하나의 profile·이미지를 찾는 방법 |
| Q6 | MAPC01 측정 한 건의 식별 파일 | 목록 행과 상세를 잇는 키 |
| Q7 | Profile의 단위 | Heatmap의 축 표기와 응답 형식 |
| Q11 | Summary block과 Data의 관계 | 요약 표와 측정 포인트 표의 구조 |

## 3. 질문

### 3.1 장비와 파일명

#### Q1. MAP608의 fab

- 질문: MAP608은 어느 fab의 장비입니까.
- 가정: `PKG`입니다. 근거는 과거 `tool_info.txt`뿐이며, 회신으로 확인된 것은
  `MAPC01=R3`, `5EAP1501=M15` 둘입니다.
- 쓰임: 장비 선택 화면이 fab별로 장비를 묶습니다.
- 답 형식: fab 이름 하나.

#### Q2. MAPC01의 lot ID

- 질문: MAPC01은 파일명의 lot 자리가 `NA`입니다. lot ID를 어디에서 얻습니까.
- 가정: 얻을 수 없다고 보고 `NA`로 둡니다.
- 쓰임: 목록의 lot 열과 lot ID 검색입니다. `NA`라면 MAPC01은 lot으로 검색할 수 없습니다.
- 답 형식: `Info 섹션의 <key 이름>` / `SAMPLE_ID 안에 포함` / `다른 파일 <이름>` /
  `얻을 수 없음` 가운데 하나.

#### Q3. MAP608 파일명의 두 시각

- 질문 (가): 첫 번째 시각은 무엇입니까.
- 질문 (나): 오래된 파일은 뒤 시각 자리가 `NA`입니다. 그 측정의 시작 시각은 어디에서
  얻습니까.
- 가정: (가) 의미를 모르는 채 목록의 시각으로 씁니다. (나) 첫 번째 시각을 대신 보여 줍니다.
- 쓰임: 목록의 측정 시각과 측정 간 시계열 비교의 가로축입니다.
- 답 형식: (가) `저장 시각` / `측정 종료 시각` / 기타. (나) `Info 섹션의 <key 이름>` /
  `얻을 수 없음`.

#### Q4. 5EAP1501 파일명의 생략된 부분

- 질문: 회신의 `#YYMMDD#HHMMSS#RECIPE#SAMPLE_ID#LOT_ID#NA#...csv`에서 `...`에는
  무엇이 옵니까.
- 가정: 아무것도 없다고 보고 `#NA#.csv`로 끝냅니다.
- 쓰임: 파일명이 측정의 키입니다.
- 답 형식: 실제 파일명 한 건을 그대로.

#### Q6. MAPC01 측정 한 건의 식별 파일

- 질문 (가): MAPC01의 data CSV는 파일명이 무엇입니까. 회신의 MAPC01 형식은
  `..._Info.csv`로 끝납니다.
- 질문 (나): data CSV가 없는 recipe에서는 측정 한 건을 `_Info.csv`로 식별합니까.
  `_Info.csv`는 recipe와 무관하게 항상 있습니까.
- 가정: `_Info.csv`가 항상 있고 그것이 측정의 키입니다. data CSV의 이름은 모릅니다.
- 쓰임: 웹은 파일명 하나를 측정의 키로 삼아 목록 행과 상세를 잇습니다.
- 답 형식: (가) 실제 data CSV 파일명 한 건. (나) `맞음` 또는 실제 규칙.

### 3.2 측정 위치와 파일의 연결

#### Q9. Site ID가 없는 recipe의 위치 키

- 질문: `Site ID` 컬럼이 없는 recipe에서는 측정 위치 하나와 그 profile·이미지 파일을
  무엇으로 잇습니까.
- 가정: `0001` 같은 순번으로 잇는다고 보았으나 근거가 없습니다.
- 쓰임: 상세 화면에서 위치를 고르면 그 위치의 Heatmap과 이미지를 엽니다.
- 답 형식: `Site ID` 없는 recipe의 Data 행 한 줄(헤더 포함)과, 같은 측정의 profile
  파일명 한 건.

#### Q10. MAP608·5EAP1501 파일명의 Site ID

- 질문: profile·이미지 파일명에 Site ID가 들어가는 것이 MAPC01만의 규칙입니까,
  세 장비 공통입니까.
- 가정: 세 장비 공통입니다.
- 쓰임: Q9와 같습니다.
- 답 형식: `맞음` 또는 MAP608의 profile 파일명 한 건과 5EAP1501의 이미지 파일명 한 건.

#### Q12. Site X·Site Y의 값

- 질문: `Site X`·`Site Y`의 값은 Site ID 안의 X·Y 숫자와 같습니까. 단위는 무엇입니까.
- 가정: 같은 정수이며 die 번호입니다. 예를 들어 `0002_X002_Y-001`이면 `2`, `-1`입니다.
- 쓰임: 측정 포인트 표의 좌표 열입니다.
- 답 형식: `맞음` 또는 Site ID 하나와 그 행의 `Site X`·`Site Y` 실제 값, 그리고 단위.

### 3.3 측정 상세 표

#### Q5. 묶어 적은 컬럼 표기

- 질문 (가): `1~51_Minimum (nm)`은 `1_Minimum (nm)`부터 `51_Minimum (nm)`까지
  컬럼 51개입니까.
- 질문 (나): `Ref_Range/Left_TRIM_H (nm)`은 `Ref_Range (nm)`와 `Left_TRIM_H (nm)`
  두 컬럼입니까. `ROUGHNESS_RANGE/Ra/Rq (nm)`도 같은 식으로 셋입니까.
- 가정: 둘 다 그렇게 읽었습니다.
- 쓰임: 요약 표·측정 포인트 표의 열과 시계열 비교의 측정 항목입니다.
- 답 형식: `맞음` 또는 실제 헤더 한 줄.

#### Q14. 단위 없이, 또는 잘려서 전달된 컬럼

- 질문 (가): `Line1_Residue_H`에도 `(nm)`가 붙습니까.
- 질문 (나): `SITE19_21_..`의 전체 컬럼 이름은 무엇입니까.
- 가정: (가) `Line1_Residue_H (nm)`입니다. (나) 모릅니다. 임시로 `SITE19_21_H (nm)`로 둡니다.
- 쓰임: 웹은 이름에 `nm`가 든 컬럼만 측정값으로 다룹니다. 단위가 없으면 그 컬럼이
  표와 그래프에서 빠집니다.
- 답 형식: 두 recipe의 실제 헤더 한 줄씩.

#### Q11. Summary block과 Data의 관계

- 질문 (가): Summary block이 여럿일 때(`Profile_LEFT_UL` + `Profile_RIGHT_UL`)
  Data 섹션도 block마다 나뉩니까.
- 질문 (나): block마다 측정 컬럼이 같습니까.
- 질문 (다): 한 block은 측정 위치마다 Data 행을 하나 냅니까.
- 가정: 셋 다 그렇습니다. 즉 위치 9곳·block 2개인 측정은 Data가 18행입니다.
- 쓰임: 요약 표의 행 수, 측정 포인트 표의 구성, Summary와 Data를 맞춰 보는 방법입니다.
- 답 형식: `맞음` 또는 block이 둘인 파일의 섹션 순서와 각 섹션의 행 수.

#### Q13. 숫자가 아닌 Method_ID

- 질문: `Method_ID`가 숫자인 recipe가 있다고 하셨습니다. 그렇지 않은 recipe에서는
  어떤 값입니까.
- 가정: Summary block 이름과 같은 method 명 문자열입니다.
- 쓰임: Data 행이 어느 Summary block에 속하는지 가리는 키로 쓰려 합니다.
- 답 형식: 숫자인 recipe의 실제 값 한 건과, 숫자가 아닌 recipe의 실제 값 한 건.

#### Q15. point가 하나인 측정의 Summary

- 질문: point가 하나뿐인 측정에서 Summary의 `STDEV`와 `RANGE`는 어떤 값입니까.
- 가정: 둘 다 `0`입니다.
- 쓰임: 요약 표와 시계열 비교가 빈 값을 0으로 그리면 안 됩니다.
- 답 형식: `0` / 빈 값 / `NaN` / 그 행이 없음 가운데 실제로 본 것.

### 3.4 Profile

#### Q7. Profile의 단위

- 질문: 단위가 파일마다 다르다고 하셨습니다(um / nm / pm / Pixel). ETL이 단위를
  하나로 통일합니까, 아니면 파일별 단위를 함께 적재합니까.
- 가정: 정해진 것이 없습니다. 현재 웹의 profile 응답은 `x`, `y`, `z` 숫자뿐이라
  단위를 실을 자리가 없습니다.
- 쓰임: Heatmap의 축·색 범례 표기입니다. 단위가 섞인 채 숫자만 오면 서로 다른 측정을
  같은 눈금으로 읽게 됩니다.
- 답 형식: `통일 — X·Y·Z 각각 <단위>` 또는 `함께 적재 — <필드 이름>`. `Pixel`인 축을
  길이로 바꿀 수 있는지도 알려 주십시오.

#### Q8. 1D profile의 적재 형식

- 질문: 1D profile(N×1)은 2D와 같은 형식으로 적재됩니까.
- 가정: 같은 X·Y·Z 행 목록이고 Y가 한 값으로 고정됩니다.
- 쓰임: 1D는 Heatmap이 아니라 선 그래프로 그려야 하므로 웹이 둘을 구분해야 합니다.
- 답 형식: `맞음` 또는 1D 파일의 헤더(Data Size·Surface Size)와 본문 첫 두 줄.

## 4. 회신에서 "남은 미정"으로 적어 주신 두 가지

확인되는 대로 알려 주십시오.

| 번호 | 내용 | 쓰임 |
| --- | --- | --- |
| P1 | `Valid`가 FALSE인 실물의 표기(`FALSE` / `False` / `0` / 빈 값)와, `<측정명>_Valid` 컬럼이 있는지 | 유효 point 수 집계 |
| P2 | 파일명과 Info의 시각이 어느 시간대인지 | 목록 정렬과 시계열. 사내 다른 원천에서 KST 값에 UTC 표기가 붙은 사례가 있었습니다. |

## 5. 회신 방법

- 회신은 [`office-data-findings.md`](office-data-findings.md)에 이어 붙입니다. 이
  저장소에 쓸 수 없으면 1절의 형식으로 전달해 주시면 Home이 옮겨 적습니다.
- 답이 앞선 회신과 달라지면 달라졌다고 적어 주십시오. 바뀐 부분만 다시 보내면 됩니다.
- 비밀번호·토큰 등 자격 증명 값은 적지 않습니다.
- 여기에 없지만 화면을 잘못 해석하게 만드는 예외를 보셨다면 함께 적어 주십시오.
  지금까지 가장 도움이 된 회신이 그런 예외들이었습니다.
