# AFM 화면 구현 후속 질문 — Home → Office

- 작성일: 2026-10-03입니다.
- 수신자: 각 AFM 장비에서 파일을 추출·정제하여 적재하는 Office agent입니다.
- 목적: 2026-10-03에 AFM 측정 검색·측정 상세 화면을 새로 만들면서, 지금까지의 회신만으로는
  정할 수 없어 **가정으로 구현한 곳**이 생겼습니다. 그 가정을 확인하려는 질문서입니다.
- 관계: 앞선 두 질문서 [`to-questionnaire-afm.md`](to-questionnaire-afm.md),
  [`to-questionnaire-afm-2.md`](to-questionnaire-afm-2.md)를 **대신하지 않습니다**.
  번호는 2차 질문서의 Q15에 이어 Q16부터 붙였습니다. 첫 질문서 5절의 적재 명세
  (Redis·MinIO의 위치·형식·스키마)는 ETL이 끝난 뒤 받기로 한 그대로입니다.
- 회신 기한: 날짜 기한은 없습니다. 아는 것부터 부분 회신해 주시면 됩니다.

지금까지의 회신 원문은 [`office-data-findings.md`](office-data-findings.md)에,
정리본은 `docs/datatables/afm/afm_raw_files.txt`에 있습니다.

## 1. 새 화면이 데이터에 기대는 것

질문의 배경이 되는 화면 동작입니다. 질문마다 어느 동작에 쓰이는지 적어 두었습니다.

- **측정 검색**: 목록을 Recipe·Lot·기간(전체 / 오늘 / 3일 / 7일)으로 거릅니다.
  기간은 **오늘 날짜에서 거꾸로** 셉니다. 각 행은 날짜·Recipe·Lot·Slot·측정 구분을 보여
  줍니다.
- **측정 상세**: 왼쪽에 측정 포인트 목록과 Site 지도를 두고, 고른 포인트 하나에 대해
  측정값, 그 값과 block 평균(MEAN)의 차이, State·Valid, 분석 이미지를 보여 줍니다.
  분석 이미지를 누르면 그 이미지의 포인트가 선택됩니다.

## 2. 답하는 방법

질문마다 **Home의 현재 가정**을 적어 두었습니다. 가정이 맞으면 `맞음` 한 단어면
충분합니다. 다르면 실제 값을 적어 주십시오.

```text
Q16: 맞음
Q21: <block이 둘인 파일 한 건의 Data 섹션을 그대로>
Q23: 가능 — 컬럼 이름 Block
Q27: 미실측
```

- 아직 모르는 것은 `미정`, 해당 사례를 보지 못한 것은 `미실측`으로 구분해 주십시오.
- 추정은 추정이라고 표시해 주십시오.
- **이름과 값은 한 글자씩 그대로** 옮겨 주십시오. 대소문자·공백·밑줄·괄호·단위
  표기가 그대로 웹의 키가 됩니다.
- 파일명·헤더처럼 긴 것은 실제 한 건을 그대로 적는 편이 설명보다 정확합니다.

## 3. 먼저 답해 주시면 좋은 질문

웹이 지금 **추측으로 메우고 있는** 곳입니다. 추측이 틀리면 화면이 오류 없이 틀린 값을
보여 줍니다.

| 번호 | 한 줄 요약 | 틀리면 생기는 일 |
| --- | --- | --- |
| Q21 | block마다 Data 행이 같은 point를 한 행씩 갖는지 | 값이 엉뚱한 block 평균과 비교됩니다 |
| Q23 | Data 행에 block을 실어 줄 수 있는지 | Q21·Q22의 추측이 영구히 남습니다 |
| Q25 | 이미지 파일명에서 위치 키를 읽는 규칙 | 이미지를 눌러도 포인트가 선택되지 않거나 다른 포인트가 선택됩니다 |
| P2 | 시각의 시간대 | 오전 9시 전에 '오늘' 필터가 비거나 하루 어긋납니다 |

## 4. 질문

### 4.1 측정 목록

#### Q16. 목록 행의 Slot

- 질문: 목록 각 행의 Slot 번호는 어디에서 얻습니까.
- 가정: MAP608·5EAP1501은 파일명의 SAMPLE_ID(`<lot>.<nn>`)의 `<nn>`, MAPC01은
  파일명의 SLOT 자리입니다. SAMPLE_ID가 `<lot>.<nn>` 꼴이라는 것 자체가 실측 예
  몇 건에서 짐작한 것입니다.
- 쓰임: 목록과 측정 상세의 LOT·SLOT 표시입니다. 측정 상세의 Info에는 Slot이 따로
  없어서, 지금은 목록에서 넘어온 경우에만 Slot을 보여 줍니다.
- 답 형식: 장비별 출처(`파일명의 <자리>` / `Info의 <key>` / 기타)와 실제 값 한 건.
  SAMPLE_ID가 `<lot>.<nn>`이 아닌 예를 보셨다면 함께 적어 주십시오.

#### Q17. 측정 구분 값

- 질문: Info에 `Measurement` key가 있습니까. 있다면 어떤 값들이 나옵니까.
- 가정: 있으며 `1`, `standard`, `repeat2`, `profile`, `roughness` 같은 짧은
  문자열입니다. 이 값들은 Home이 지어낸 것입니다.
- 쓰임: 목록 각 행과 측정 상세 머리에 badge로 보여 줍니다.
- 답 형식: `없음` 또는 key 이름과 실제로 본 값 전부.

#### Q18. 측정이 목록에 나타나기까지의 시간

- 질문: 장비에서 측정이 끝난 뒤 웹이 읽는 목록에 그 측정이 들어오기까지 얼마나
  걸립니까(ETL 주기).
- 가정: 정해진 것이 없습니다.
- 쓰임: 기간의 '오늘'은 오늘 측정된 것만 보여 줍니다. 적재가 하루에 한 번이면 '오늘'은
  늘 비어 있으므로 기본값이나 이름을 바꿔야 합니다.
- 답 형식: 주기(`실시간` / `N분마다` / `하루 1회 HH:MM` / 미정).

#### Q19. 목록의 규모

- 질문: 장비별로 하루 측정 건수, 고유 Recipe 수, 그리고 3개월 보존 시 목록의 총 행
  수는 대략 얼마입니까.
- 가정: 장비당 하루 수 건~수십 건, Recipe 수십 개, 총 수천 행 이하입니다.
- 쓰임: 웹은 목록 전체를 한 번에 받아 브라우저에서 거릅니다. '보이는 N건 모두 담기'도
  이 크기를 전제로 합니다. 수만 행이면 서버에서 거르도록 바꿔야 합니다.
- 답 형식: 장비별 숫자 셋(추정이면 추정이라고).

#### Q20. 목록에서 비어 있을 수 있는 칸

- 질문: 목록 행의 날짜·시각·Recipe·Lot·Slot·측정 구분 가운데 비어 있을 수 있는 칸이
  있습니까. 있다면 빈 칸은 어떻게 적재됩니까.
- 가정: MAPC01의 lot이 파일명에서 `NA`인 것 말고는 모두 채워져 있고, lot은 Info의
  `Lot ID`로 채웁니다.
- 쓰임: 빈 칸은 화면에서 빈 값으로 보이고, 날짜가 없는 행은 기간 필터에서 빠집니다.
  `NA`라는 글자가 그대로 오면 Lot 검색에 `NA`가 걸립니다.
- 답 형식: 칸 이름별 `항상 있음` / `빈 문자열` / `NA` / `null`.

### 4.2 block

2차 회신에서 "block은 순서로만 맞춘다"는 것과 "중단된 뒤쪽 block은 측정 컬럼 없이
STOPPED 행만 남고 Summary가 비어 있다"는 것을 확인했습니다. 웹은 Data 행을 위에서부터
읽다가 **같은 point가 다시 나오면 다음 block이 시작된다**고 봅니다. 아래 셋은 그 읽기가
맞는지에 대한 질문입니다.

#### Q21. block마다 Data 행의 point 집합

- 질문: 한 파일에 block이 여럿일 때, 모든 block의 Data가 같은 point들을 한 행씩
  갖습니까. 중단된 block에서는 측정하지 못한 point의 행이 빠집니까, STOPPED 행으로
  남습니까.
- 가정: 모든 block이 같은 point를 같은 순서로 한 행씩 가지며, 중단된 block도 모든
  point의 행을 STOPPED로 남깁니다.
- 쓰임: 포인트 하나의 값을 block별로 나누고, 각 값을 그 block의 MEAN과 비교합니다.
  앞 block에 없던 point만으로 이루어진 뒤 block이 있으면 웹은 둘을 한 block으로
  잘못 읽습니다.
- 답 형식: `맞음` 또는 block이 둘 이상인 파일 한 건의 Data 섹션(행 순서 그대로, 측정값은
  지워도 됩니다).

#### Q22. Summary가 없는 block의 위치와 block 이름의 중복

- 질문 (가): Summary가 비어 있는 block은 항상 마지막 쪽에만 있습니까, 가운데에도
  올 수 있습니까.
- 질문 (나): 한 파일 안에서 두 block이 같은 method 명을 가질 수 있습니까.
- 가정: (가) 마지막 쪽에만 옵니다. (나) 없습니다.
- 쓰임: n번째 Data block을 n번째 Summary block과 짝짓습니다. 가운데 block의 Summary가
  비면 그 뒤의 짝이 모두 하나씩 밀립니다. 이름이 겹치면 두 block이 하나로 합쳐 보입니다.
- 답 형식: (가) `마지막 쪽에만` / `가운데에도` / 미실측. (나) `없음` / 실제 예 한 건.

#### Q23. Data 행마다 block을 실어 주는 것이 가능한지 (요청)

- 질문: 적재할 때 Data 행마다 그 행이 속한 block(method 명이나 순번)을 컬럼으로
  넣어 줄 수 있습니까. raw CSV에서는 각 section 앞의 이름 줄이 그 정보입니다.
- 가정: 지금은 없다고 보고 Q21·Q22의 규칙으로 추측합니다.
- 쓰임: 이 컬럼이 있으면 Q21·Q22의 추측이 필요 없어지고, 중단된 block도 `Block 2`
  대신 제 method 명으로 보여 줄 수 있습니다.
- 답 형식: `가능 — 컬럼 이름 <이름>, 값은 <method 명 / 순번>` / `불가 — 이유`.

### 4.3 위치와 이미지

#### Q24. Site 배치

- 질문 (가): Site ID를 기록하는 recipe에서 `Site X`·`Site Y`의 범위는 실측으로
  어디까지입니까.
- 질문 (나): `Site Y`가 커지면 웨이퍼의 위쪽(notch 반대쪽)입니까.
- 질문 (다): 한 Site에 point가 가장 많은 실측 예는 몇 개입니까.
- 가정: (가) X·Y 모두 -3 ~ 2입니다(36 point를 6 × 6으로 놓은 것). (나) 위쪽입니다.
  (다) 2개입니다. 셋 다 실측 근거가 없습니다.
- 쓰임: 측정 상세 왼쪽의 Site 지도입니다. 지도의 위아래가 웨이퍼와 반대면 사용자가
  포인트를 거꾸로 짚습니다.
- 답 형식: (가) X·Y 각각의 최소~최대. (나) `위쪽` / `아래쪽` / 미정. (다) 숫자.

#### Q25. 분석 이미지 파일명에서 위치 키를 읽는 규칙

- 질문: 장비별로 align·tip·capture·Height 이미지의 실제 파일명을 한 건씩 알려 주십시오.
- 가정: 모든 이미지 이름이 **그 측정의 data 파일명에서 `.csv`를 뺀 것**으로 시작하고
  `_<위치 키>_<종류>.webp`로 끝납니다. MAPC01은 목록 파일명이 `_Info.csv`로 끝나지만
  이미지 이름에는 `_Info`가 없다고 보았습니다. 위치 키는 Site ID가 있으면
  `<Site ID>_<4자리>`, 없으면 `<4자리>`입니다. MAPC01·5EAP1501의 위치 키 앞부분은
  실측 예가 없습니다.
- 쓰임: 이미지를 누르면 그 포인트로 이동합니다. 이름이 이 꼴이 아니면 웹은 포인트를
  알 수 없는 이미지로 두며(누르면 크게 보기만 됨), 다른 포인트로 잘못 이동하지는
  않습니다.
- 답 형식: 장비 × 종류별 실제 파일명(없는 종류는 `없음`).

#### Q26. 적재 후 파일 목록의 값과 이미지의 위치 키 (요청 포함)

- 질문 (가): 적재된 목록의 파일 목록 필드(`profile_dir_list`, `tiff_dir_list`,
  `align_dir_list` 등)에 들어가는 값은 파일명입니까, MinIO의 전체 key(경로 포함)입니까.
- 질문 (나): 이미지마다 위치 키(Point No 또는 Site ID + point 번호)를 따로 실어 줄 수
  있습니까.
- 가정: (가) 파일명입니다. (나) 없다고 보고 Q25의 규칙으로 파일명에서 읽습니다.
- 쓰임: 경로가 붙어 오면 Q25의 "data 파일명으로 시작한다"는 읽기가 모두 실패하고, 모든
  이미지가 포인트를 잃습니다. 위치 키가 따로 오면 파일명을 읽을 필요가 없습니다.
- 답 형식: (가) `파일명` / `전체 key — 예: <한 건>`. (나) `가능 — 필드 이름 <이름>` /
  `불가`.

#### Q27. 이미지의 수

- 질문 (가): Result(Height) 이미지는 point마다 한 장입니까. 채널(Height 외 Amplitude·
  Phase 등)이나 스캔 방향별로 여러 장이 있을 수 있습니까.
- 질문 (나): align·tip·capture 이미지는 측정마다 한 장입니까, point마다 있습니까.
- 질문 (다): 측정 한 건의 이미지 수는 실측으로 최대 몇 장입니까.
- 가정: (가) point마다 Height 한 장입니다. (나) 측정마다 한 장이며 첫 point의 이름을
  씁니다. (다) 수십 장입니다.
- 쓰임: 분석 이미지 팝업은 포인트별로 묶어 격자로 보여 줍니다. 웹은 사용자 한 명이 5초에
  50번까지 서버에 요청할 수 있으므로, 수백 장을 한 화면에 띄우면 일부 이미지가
  거절될 수 있습니다.
- 답 형식: (가) `한 장` / `여러 장 — 이름 예`. (나) `측정마다` / `point마다`. (다) 숫자.

### 4.4 값

#### Q28. 측정값 칸이 숫자가 아닐 때

- 질문: Data의 측정값 칸(`... (nm)`)에 숫자 대신 빈칸·`NaN`·`-`·문자가 오는 경우를
  보셨습니까. 적재 후 측정값이 문자열(`"79.24"`)로 올 수 있습니까.
- 가정: 측정된 칸은 언제나 숫자이고, 측정하지 못한 block은 그 칸 자체가 없습니다.
- 쓰임: 숫자가 아닌 칸은 화면에서 `–`로 보이고 평균과의 차이를 계산하지 않습니다.
  0으로 적재되면 실제 0 nm와 구분할 수 없습니다.
- 답 형식: 본 표기 전부와 그때의 State, 또는 `미실측`.

## 5. 앞선 질문서의 남은 미정

2차 질문서 4절의 두 가지가 아직 답을 기다리고 있습니다. 이번 화면이 둘 다에 기대므로
다시 적습니다.

| 번호 | 내용 | 이번 화면에서의 쓰임 |
| --- | --- | --- |
| P1 | `Valid`가 FALSE인 실물의 표기(`FALSE` / `False` / `0` / 빈 값)와, `<측정명>_Valid` 컬럼이 있는지 | 측정 상세의 Valid 표시와 측정 포인트 표의 Valid 필터. 웹은 명시적인 거짓만 FALSE로 보이고, 빈 값은 `–`로 둡니다. |
| P2 | 파일명과 Info의 시각이 어느 시간대인지 | 기간 '오늘'은 KST 날짜로 셉니다. 시각이 UTC라면 KST 00:00~09:00 측정이 전날로 분류됩니다. 사내 다른 원천에서 KST 값에 UTC 표기가 붙은 사례가 있었습니다. |

## 6. 회신 방법

- 회신은 [`office-data-findings.md`](office-data-findings.md)에 이어 붙입니다. 이
  저장소에 쓸 수 없으면 2절의 형식으로 전달해 주시면 Home이 옮겨 적습니다.
- 답이 앞선 회신과 달라지면 달라졌다고 적어 주십시오. 바뀐 부분만 다시 보내면 됩니다.
- 비밀번호·토큰 등 자격 증명 값은 적지 않습니다.
- 요청(Q23, Q26 (나))은 적재 형태를 정할 때 함께 고려해 주시면 됩니다. 불가하면 그렇다고만
  알려 주십시오. 웹은 지금의 추측 규칙을 유지합니다.
- 여기에 없지만 화면을 잘못 해석하게 만드는 예외를 보셨다면 함께 적어 주십시오.
