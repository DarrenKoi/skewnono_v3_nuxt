# AFM 미답 질문 — Home → Office

- 정리일: 2026-10-07입니다(7차 회신 반영).
- 수신자: 각 AFM 장비에서 파일을 추출·정제하여 적재하는 Office agent입니다.
- 목적: **아직 답을 받지 못한 질문만** 모은 문서입니다. 이 문서 하나만 보시면 됩니다.
- 답을 받은 질문: 회신 원문과 그 반영 현황은
  [`office-data-findings.md`](office-data-findings.md)에 있습니다. 정리된 사실은
  `docs/datatables/afm/afm_raw_files.txt`(raw 파일)와 `docs/datatables/afm/afm_redis.txt`
  (Redis·MinIO 적재 형태)에 있습니다. 잘못 옮긴 곳이 있으면 함께 알려 주십시오.
- 번호: 앞선 질문서의 번호를 **그대로** 두었습니다. 그래서 번호가 이어지지 않습니다.
  6차 회신에서 새로 생긴 질문은 Q43부터 붙였습니다. 2026-10-07에 추가한 화면(가동 현황·
  Recipe 현황)에서 생긴 질문은 Q46부터, 7차 회신에서 새로 생긴 질문은 Q54부터입니다.
- 회신 기한: 날짜 기한은 없습니다. 아는 것부터 부분 회신해 주시면 됩니다.

## 1. 6차 회신으로 웹이 바꾼 것

보내 주신 답대로 고쳤습니다. 잘못 이해한 곳이 있으면 알려 주십시오.

- **block** — points의 `Site` 열로만 나눕니다. "같은 point가 다시 나오면 다음 block"
  규칙은 지웠습니다. repeat recipe에서 한 point의 반복 측정은 같은 block 안에 **여러 값으로
  나란히** 보여 줍니다.
- **값** — 상세의 문자열을 웹이 바꿉니다. 단위가 붙은 열(`... (nm)`, `X (um)`)과 `Point No`·
  `Site X`·`Site Y`는 숫자로, `Valid`·`<측정명>_Valid`는 참/거짓으로 읽습니다. 공백 한 칸과
  빈 문자열은 "값 없음"으로 보이고 0이나 FALSE로 보이지 않습니다.
- **이미지의 포인트** — 이름의 **끝**(`_<위치 키>_<종류>.webp`)에서만 읽습니다. `filename`으로
  시작하는지는 보지 않습니다.
- **Profile 단위** — MinIO 객체의 user metadata에서 읽습니다.
- **원본 TIFF** — `tiff_dir_list`에서 찾습니다(Q35).
- **Slot** — 목록은 `slot_number` 열을, 링크로 바로 연 측정 상세는 Info의 `Sample Location`을
  읽습니다. 파일명에서는 읽지 않습니다.
- **"측정 데이터 있음" 표시** — `data_dir_list`에 `detail_points.parquet`이 있을 때만 켭니다.
- **장비의 fab** — `fab`이 비어 있으면 `alias`를 fab으로 씁니다(Q40).

## 1-1. 2026-10-07에 추가된 화면

장비마다 상단 탭이 둘 늘었습니다. 둘 다 **측정 목록(`afm_d2_measurements`) 열만** 읽고
상세나 파일은 열지 않습니다.

- **가동 현황** — 기간(7일·30일·전체) 안의 측정 건수, 측정이 있던 날 수, recipe·lot 수,
  `point_count` 합, 일별·시간대별 측정 수, 일별 미완료·무효 측정 수를 보여 줍니다.
  시간대는 `time`의 앞 두 자리로 셉니다.
- **Recipe 현황** — `recipe_name`으로 묶어 recipe마다 측정 수, 처음·마지막 측정일, lot 수,
  point 수, 남기는 파일 종류(`has_*`), 미완료 비율을 보여 줍니다.
- 두 화면 모두 null은 "모름"으로 두고 세지 않으며, 뺀 건수를 화면에 적습니다.

## 1-2. 7차 회신으로 웹이 바꾼 것

보내 주신 답대로 고쳤습니다. 잘못 이해한 곳이 있으면 알려 주십시오.

- **측정 시각** — 목록·가동 현황·팁 모니터링이 `measured_time`을 읽고, 값이 null이면
  `time`을 씁니다(Q55).
- **팁이 바뀐 지점** — 시계열 비교의 세로선을 `Tip ID`·`Tip Cassette ID`·`Tip Port No`·
  `Tip Slot No` 가운데 하나가 달라졌거나 **Mileage가 앞 측정보다 작아진** 자리에 긋습니다.
- **팁 폭의 관리선** — `Tip ID`에 `MCNT`가 들어 있는 종류는 팁(카세트·포트·슬롯)마다 따로
  긋고, 그 밖의 종류는 종류 단위로 긋습니다. 한 팁의 측정이 5건 미만이면 그 팁의 폭은
  판정하지 않습니다.
- **Mileage** — 팁 단위 누적값이므로 관리선을 긋지 않고 판정에서 뺐습니다. 값은 그대로
  보여 줍니다.
- **`point_count`** — 실제로 스캔한 위치 수로 읽습니다. 가동 현황의 point 합과 Recipe
  현황의 Point 칸은 그대로이고, 중단된 측정은 작은 값으로 셉니다.
- **팁 열 9개** — 적재된 이름 그대로 읽습니다. `tip_width`의 NaN은 "측정 없음"입니다.
- **팁 이미지의 포인트** — `_<위치 키>_C_PR.webp`처럼 종류가 두 토막인 이름에서도 위치 키를
  읽습니다. `C_Result`는 포인트가 없는 이미지로 둡니다(Q53).
- **원본 TIFF** — align·tip·capture 목록에 원본이 섞여 있어도 화면의 이미지 목록에는
  webp만 올립니다(Q35).

## 2. 답하는 방법

질문마다 **Home의 현재 가정**을 적어 두었습니다. 가정이 맞으면 `맞음` 한 단어면
충분합니다. 다르면 실제 값을 적어 주십시오.

```text
Q35 (나): 맞음
Q55 (가): HHMMSS
P2: 미정
```

- 아직 모르는 것은 `미정`, 해당 사례를 보지 못한 것은 `미실측`으로 구분해 주십시오.
- 추정은 추정이라고 표시해 주십시오.
- **이름과 값은 한 글자씩 그대로** 옮겨 주십시오. 대소문자·공백·밑줄·괄호·단위 표기가
  그대로 웹의 키가 됩니다.

## 4. 질문

### 4.1 측정 상세

#### Q31. Summary의 값

- 질문: `detail_summary.parquet`의 값도 points처럼 **문자열**입니까.
- 가정: 문자열입니다. 숫자여도 웹은 그대로 읽습니다.
- 답 형식: `문자열` / `숫자`.

#### Q54. `Sample Count`의 뜻 (새 질문)

- 질문: repeat recipe의 반복은 `Sample Count`가 4에서 5로 바뀌는 것으로 구분할 수 있다고
  하셨습니다. (가) `Sample Count`는 무엇을 세는 값입니까. (나) 반복이 없는 recipe에서도
  한 측정 안에서 값이 바뀝니까. (다) 첫 바퀴의 값이 늘 같습니까(4), 측정마다 다릅니까.
- 가정: (가) 모릅니다. (나) 바뀌지 않습니다. (다) 측정마다 다르고, 한 측정 안에서 값이 한
  번 커진 자리가 다음 바퀴의 시작입니다.
- 쓰임: 지금은 반복 측정을 같은 block 안에 나란히 보여 주기만 합니다. 가정이 맞으면
  "1회차 / 2회차"로 나누어 보여 줍니다.
- 답 형식: (가) 한 줄. (나) `안 바뀜` / `바뀜 — 예`. (다) `같음` / `다름`.

#### Q22. 한 측정 안의 같은 method 명

- 질문: 한 측정 안에서 두 block이 **같은 method 명**을 가질 수 있습니까.
- 가정: 없습니다.
- 쓰임: block을 `Site`의 이름으로 나누므로, 이름이 겹치면 두 block이 하나로 합쳐 보입니다.
- 답 형식: `없음` / 실제 예 한 건 / `미실측`.

#### S2. Summary의 계산 규칙

- 질문: Summary의 통계는 장비가 쓴 값 그대로입니까, 적재할 때 계산한 값입니까. 계산한다면
  `Valid`가 FALSE인 point를 빼는지, STDEV의 ddof가 0인지 1인지 알려 주십시오.
- 가정: 장비 값 그대로이고 FAILED·FALSE도 포함합니다.
- 쓰임: 시계열 비교는 Summary가 없는 측정의 평균을 points에서 직접 계산합니다. 규칙이
  다르면 Summary가 있는 측정과 없는 측정의 값이 어긋납니다.
- 답 형식: `장비 값 그대로` / `계산 — <규칙>` / `미정`.

#### S8. 이름이 같은 측정 컬럼

- 질문: 서로 다른 recipe에 있는 **같은 이름의 컬럼**(`Left_H (nm)` 등)은 같은 측정량입니까.
- 가정: 같은 recipe 안에서만 비교할 수 있다고 보고, 시계열 비교를 recipe별로 묶습니다.
- 답 형식: `같음` / `recipe마다 다름` / `미정`.

### 4.2 Profile과 이미지

- 받은 답(7차): 확장자는 `.tiff`입니다. 5EAP1501의 원본은 다시 적재될 예정이고, align·tip·
  capture의 원본도 이미 적재되어 있습니다.
- 질문:
  - (나) 어느 webp의 원본인지는 무엇으로 압니까 — **이름이 같고 확장자만 다릅니까.**
  - (마) align·tip·capture의 원본은 **어느 목록**에 들어 있습니까 — 각자의 목록

- 가정: (나) 이름이 같고 확장자만 다릅니다. (마) 각자의 목록입니다. 웹은 어느 목록이든

#### Q33. 이미지 이름의 나머지 규칙

#### Q27. 이미지의 수

- 질문: (가) Result(Height) 이미지는 point마다 한 장입니까. 채널(Amplitude·Phase 등)이나

- 쓰임: 웹은 사용자 한 명이 5초에 50번까지만 서버에 요청할 수 있어, 수백 장이면 일부

- 답 형식: (가) `한 장` / `여러 장 — 이름 예`. (나) `측정마다` / `point마다`. (다) 숫자.

#### Q24. Site 배치

- 질문: (가) Site ID를 기록하는 recipe에서 `Site X`·`Site Y`의 범위는 실측으로 어디까지입니까.

- 가정: (가) X·Y 모두 -3 ~ 2입니다. (나) 위쪽입니다. (다) 모릅니다.
- 쓰임: 측정 상세 왼쪽의 Site 지도입니다. 위아래가 웨이퍼와 반대면 사용자가 포인트를

- 답 형식: (가) X·Y 각각의 최소~최대. (나) `위쪽` / `아래쪽` / `미정`. (다) 숫자.

### 4.3 측정 목록

#### Q36. null이 되는 칸

- 질문: `formatted_date`·`time`·`point_count`가 null이 되는 것은 각각 어떤 경우입니까.
  Recipe·Lot·Slot 칸도 null이 될 수 있습니까. `NA`라는 글자가 그대로 들어가는 칸이
  있습니까.
- 받은 답(7차): `point_count`는 실제로 스캔한 위치 수(profile·tiff 파일 수)이고, 첫
  point에서 중단되어 파일이 하나도 없는 측정은 null입니다.
- 가정: `time`은 파일명의 그 자리가 `NA`일 때, `formatted_date`는 날짜를 읽지 못했을 때,
  `point_count`는 스캔 파일이 없을 때입니다(profile도 Result 이미지도 남기지 않는 recipe는
  측정이 끝났어도 null). 나머지 칸은 항상 채워져 있습니다.
- 쓰임: 날짜가 null인 행은 "오늘 / 3일 / 7일"에서 빠지고 "전체"에만 보입니다. `NA`가
  글자로 오면 Lot 검색에 걸립니다. 가동 현황은 날짜 없는 행을 모든 집계에서 빼고 건수만
  적으며, 시각 없는 행은 시간대 히트맵에서만 뺍니다. Recipe 현황은 `recipe_name`이 비어
  있는 행을 어느 recipe에도 넣지 않습니다.
- 답 형식: 칸별 한 줄.

#### Q29. Slot 값의 모양

- 질문: (가) Info의 `Sample Location` 값은 전체가 어떻게 생겼습니까. (나) `slot_number`
  열의 값은 `5`입니까, `05`입니까. ((다)는 5차에서 답을 받아 뺐습니다.)
- 가정: (가) 값 안에 `Slot 5`처럼 `Slot` 뒤에 숫자가 옵니다. 웹은 그 숫자만 읽습니다.
  (나) 모릅니다. 받은 그대로 보여 줍니다.
- 쓰임: 링크로 바로 연 측정 상세가 `Sample Location`에서 Slot을 읽습니다. 값의 모양이
  다르면 Slot 칸이 비어 보입니다(틀린 값을 보여 주지는 않습니다).
- 답 형식: (가) 장비별 실제 값 한 건. (나) 실제 값.

#### Q55. `measured_time` 열의 값 (새 질문)

- 받은 답(7차): `measured_time` 열이 추가되었습니다. MAP608의 6번째 필드는 오래된 파일만이
