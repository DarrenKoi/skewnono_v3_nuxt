# AFM 적재 데이터 명세 공유 — Home ↔ Office

- 작성일: 2026-10-02입니다.
- 수신자: 각 AFM 장비에서 파일을 추출·정제하여 적재하는 Office agent입니다.
- 목적: Office가 적재하는 데이터의 **위치(path)·형식(format)·타입(type)** 을 Home과 맞추는 것입니다.
- 회신 기한: 날짜 기한은 없습니다. 적재 설계가 정해지는 dataset부터 차례로 회신해 주시면 됩니다.

## 1. 진행 단계와 역할 분담

```text
AFM 장비 파일 추출 → 정제 → 적재(Redis 색인 + MinIO 파일) → 웹 화면이 조회
└─────────────────── Office ───────────────────┘   └──── Home ────┘
```

저장 구조는 아래와 같이 정했습니다(user-confirmed 2026-10-02).

- **Redis**에는 측정 이력(목록)과, 그 측정의 파일이 놓인 MinIO 경로만 담습니다.
- **MinIO**에는 측정 본문인 상세·Profile·이미지 파일을 둡니다.
- SQLite는 쓰지 않습니다.
- 보존 기간은 **최근 3개월**입니다. 그보다 오래된 측정은 Redis와 MinIO 양쪽에서 지웁니다.

역할은 이렇게 나눕니다.

- Office는 추출·정제·적재를 맡고, 적재 결과의 명세를 5절 양식으로 공유합니다.
- Home은 그 명세를 근거로 웹 쪽 읽기 코드와, 사내망 밖에서 같은 형태를 재현하는
  mock 데이터를 작성합니다. 웹 쪽 코드는 Office가 작성하지 않아도 됩니다.
- Home은 사내 저장소에 접근할 수 없습니다. 회신 문서가 Home이 실데이터에 대해 아는
  것의 전부이므로, 값의 범위·결측 표현·선행 0처럼 사소해 보이는 사실도 적어 주십시오.
- 아직 정하지 않은 항목은 `미정`으로 남겨 주십시오. 추정은 추정이라고 표시합니다.

## 2. 웹 화면이 읽는 dataset

| ID | Dataset | 저장소 | 화면에서의 쓰임 | 한 번에 읽는 단위 |
| --- | --- | --- | --- | --- |
| D1 | 장비 목록 | Redis | 장비 선택 | 전체 |
| D2 | 측정 목록 | Redis | 장비별 검색·최근 측정, 파일 보유 표시 | 장비 하나의 전체 목록 |
| D3 | 측정 상세 | MinIO | Information, Site별 요약 표·산점도, Measurement points 표, 측정 간 시계열 비교, Excel 내보내기 | 측정 한 건 |
| D4 | Profile | MinIO | Heatmap·Histogram | 측정 한 건의 위치 하나 |
| D5 | 이미지 | MinIO | Profile 이미지, Align·Tip·Capture·TIFF 갤러리 | 이미지 한 장 |

D1은 D2의 장비별 key에서 알 수 있다면 따로 적재하지 않아도 됩니다. 그 경우 장비와
fab의 대응만 알려 주십시오.

조회 이력·그룹·최근 검색은 브라우저에 저장하므로 적재 대상이 아닙니다.

## 3. Home이 현재 가정하는 형태

아래는 2025-08 요구사항과 현재 mock에서 온 **가정**이며, 실데이터로 확인된 것이
아닙니다. 이 형태에 맞춰 적재할 필요는 없습니다. 실제 적재 형태가 다르면 다른 그대로
알려 주십시오. 웹 쪽을 Home이 맞춥니다.

### 3.1 D1 장비 목록

행 하나는 `id`, `name`, `fab`입니다. 장비와 fab의 대응은 자료마다 다릅니다.

| 출처 | 대응 |
| --- | --- |
| 현재 화면과 mock | `R3 → MAP608`, `M12 → MAPC01`, `M15 → 5MAPT01` |
| 과거 `tool_info.txt` | `PKG → MAP608`, `R3 → MAPC01`, `M15 → 5EAP1501` |

### 3.2 D2 측정 목록 — 행 하나가 측정 한 건

| 필드 | 타입 | 가정한 예 | 비고 |
| --- | --- | --- | --- |
| `unique_key` | str | `260424#093000#FSOXCMP_DISHING_9PT#01_1#T7HQR16#1` | `date#time#recipe_name#slot_info#lot_id#measured_info` |
| `filename` | str | `#260424#FSOXCMP_DISHING_9PT#T7HQR16_093000#01_1#.csv` | 현재 웹이 같은 장비 안에서 측정을 가리키는 키 |
| `date` | str | `260424` | YYMMDD |
| `formatted_date` | str | `2026-04-24` | |
| `recipe_name` | str | `FSOXCMP_DISHING_9PT` | |
| `lot_id` | str | `T7HQR16` | |
| `slot_number` | str | `01` | 선행 0을 가진 문자열 |
| `time` | str | `093000` | hhmmss. 과거 요구사항은 `None` 허용 |
| `measured_info` | str | `1`, `repeat2` | 반복 횟수 등. 과거 요구사항은 `None` 허용 |
| `tool_name`, `fab` | str | `MAP608`, `R3` | |
| `data_dir_list` | list[str] | 상세 파일의 MinIO 경로 | 과거 요구사항은 파일명만 담고, 없으면 `["no files"]` |
| `profile_dir_list` | list[str] | 위치별 profile 파일의 MinIO 경로 | 위와 같음 |
| `tiff_dir_list`, `align_dir_list`, `tip_dir_list`, `capture_dir_list` | list[str] | 이미지 파일의 MinIO 경로 | 위와 같음 |
| `point_count` | int | `5` | 측정 위치(Site) 수. 목록에 있으면 상세를 열지 않고 표시 가능 |

### 3.3 D3 측정 상세 — 세 부분

| 부분 | 형태 | 화면이 이름으로 찾는 필드 |
| --- | --- | --- |
| `information` | `{이름: 값}` | `Recipe ID`, `Lot ID`, `Start Time`. 나머지는 받은 그대로 표시 |
| `summary` | 행 목록 | `Site`, `ITEM`(`MEAN`·`STDEV`·`MIN`·`MAX`·`RANGE`), 측정 컬럼 |
| `data` | 행 목록, 행 하나가 측정 point 하나 | `Site ID`, `Site X`, `Site Y`, `Point No`, `State`, `Valid`, 측정 컬럼, `<측정명>_Valid` |

측정 컬럼은 `Left_H (nm)`, `Right_H (nm)`, `Ref_H (nm)`을 가정합니다. 웹은 컬럼
이름을 고정하지 않고 받은 대로 표시하지만, 시계열 선택지는 이름에 `nm`가 들어간
컬럼만 고릅니다.

### 3.4 D4 Profile

`[{x, y, z}]` 형태의 실수 목록을 가정합니다. mock은 20×20 격자 400점을 만들지만
근거가 없습니다. 실제가 1D 선형 profile이면 그 형태 그대로 알려 주십시오.

### 3.5 D5 이미지

과거 요구사항은 WebP를 언급합니다. 현재 웹은 자리 표시용 SVG를 그립니다. 종류는
Height(위치별 profile 이미지), align, tip, capture, tiff 다섯 가지를 가정합니다.

## 4. 적재 설계에 참고할 웹 쪽 조건

- **Redis 형식** — 웹의 기존 리더는 DataFrame을 parquet(`df.to_parquet()`)로 읽습니다.
  pickle은 numpy·pandas 버전이 다른 호스트에서 역직렬화가 깨진 전례가 있어 권하지
  않습니다.
- **Redis에 담는 경로** — 웹은 prefix listing 없이, 목록 행에 적힌 경로로 MinIO 객체를
  바로 읽습니다. 따라서 경로는 bucket을 뺀 객체 key 전체여야 하고, 측정 한 건에
  딸린 파일을 빠짐없이 담아야 합니다.
- **MinIO 위치** — 웹의 자격 증명은 bucket `user`의 `2067928/` prefix 아래 객체만 읽을
  수 있고 bucket 단위 권한은 없습니다(office 확인 2026-07-24). 다른 위치에 적재한다면
  웹이 읽을 방법을 함께 알려 주십시오.
- **3개월 보존** — bucket 단위 권한이 없어 MinIO의 lifecycle 만료를 쓸 수 없으므로,
  삭제는 적재 쪽 작업이 직접 해야 합니다. Redis 목록의 행을 먼저 지우고 MinIO 파일을
  나중에 지워 주십시오. 순서가 반대면 목록에는 있는데 파일이 없는 측정이 화면에
  나타납니다. 3개월을 세는 기준 시각(측정 시각인지 적재 시각인지)도 알려 주십시오.
- **Redis 유실 대비** — Redis의 목록이 사라져도 MinIO의 파일에서 다시 만들 수 있으면
  좋습니다. 재생성이 가능한지 알려 주십시오.
- **이미지 형식** — WebP·PNG는 웹이 변환 없이 전달합니다. TIFF는 대부분의 브라우저가
  표시하지 못하므로, TIFF만 적재한다면 알려 주십시오.
- **key의 특수 문자** — 현재 웹은 `filename`을 URL 경로에 넣습니다. key에 `#`·공백·
  한글이 들어가면 샘플에서 그대로 보존해 주십시오.
- **시각** — 시간대를 명시해 주십시오. 사내 다른 원천에서 KST 값에 UTC 표기가 붙은
  사례가 있었습니다.
- **결측** — `None`, `NaN`, 빈 문자열, `[]`, `["no files"]`, 키 누락을 구분해 주십시오.

## 5. Office가 회신할 적재 명세

dataset마다 아래 양식을 한 벌씩 채워 주십시오.

```text
dataset : D2 측정 목록
상태    : 적재 완료 | 설계 확정 | 설계 중 | 미정
저장소  : Redis | MinIO
위치    : Redis key와 자료형 | bucket과 객체 key 패턴
형식    : parquet | json | csv | webp 등 (인코딩·압축 포함)
구조    : 행 하나의 의미, 전체 shape, index
스키마  : 필드 → 타입(dtype) → null 가능 여부 → 단위 → 대표값
연결 키 : MinIO 경로를 담은 필드, 또는 다른 dataset을 찾는 key 조립 규칙
갱신    : 적재 주기, 덮어쓰기 또는 추가, 3개월 삭제 작업의 주기와 기준 시각
규모    : 3개월치 건수, 값·파일 크기의 대표값과 큰 사례
샘플    : 실제 값 2건 이상 (발췌 여부 표시)
확인    : 확인 날짜와 조회 방법
```

dataset별로 함께 적어 주실 내용입니다.

| ID | 추가로 필요한 내용 |
| --- | --- |
| D1 | 실제 장비 ID·이름·fab·별칭. 3.1의 두 대응 중 맞는 쪽 |
| D2 | 장비별 key인지 전체가 한 key인지. 측정 한 건의 식별자 규칙과 재측정·동명 파일의 중복 가능성 |
| D3 | `information`·`summary`·`data`가 한 객체인지 따로 적재되는지. recipe·장비별 측정 컬럼과 단위 |
| D4 | 위치 하나를 가리키는 key 규칙. 1D인지 2D인지, 축과 단위, 격자 크기·간격·원점 |
| D5 | 종류별 형식·크기·key 규칙. 장비 원본 형식과 변환 여부 |

## 7. 회신 방법

- 회신 파일은 `docs/afm/office-data-findings.md`입니다. 이 저장소에 쓸 수 없으면 같은
  내용을 다른 형태로 전달해도 됩니다.
- 확정된 dataset부터 부분 회신합니다. 적재 후 구조가 바뀌면 바뀐 부분만 다시 보냅니다.
- 식별자를 치환할 때는 같은 원본을 모든 샘플에서 같은 값으로 바꾸고, 키·타입·null·
  선행 0·구분자·단위·dataset 간 연결 관계는 유지합니다.
- 비밀번호·토큰 등 자격 증명 값은 적지 않습니다. 환경 변수나 설정의 이름만 적습니다.
- 여기에 없지만 화면을 잘못 해석하게 만드는 장비별 예외가 있으면 함께 적어 주십시오.

## 8. 회신 후 Home의 작업

1. 확인된 사실을 `docs/datatables/`의 스키마 문서와 AFM mock에 함께 반영합니다.
2. mock이 확인된 key·타입·결측·단위·dataset 간 연결 관계를 재현하도록 고칩니다.
   확인되지 않은 부분은 `OFFICE-VERIFY`로 표시합니다.
3. 적재 명세에 맞춰 웹 쪽 읽기 코드를 작성하고, 화면이 가정과 다른 부분을 고칩니다.
4. 브라우저에 저장된 조회 이력·그룹이 3개월이 지나 삭제된 측정을 가리킬 때, 오류가
   아니라 "보존 기간이 지난 측정"으로 보이도록 처리합니다.
5. 실제 저장소 연결 확인은 사무실에서 마무리합니다.
