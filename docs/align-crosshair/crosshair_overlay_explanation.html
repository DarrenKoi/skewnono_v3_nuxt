1. 전체 그림

align 이미지(OM/SEM) 옆에는 같은 폴더의 숨김 폴더 안에 cond.txt 가 함께 있습니다. 이 파일의 !Cursor_info 행에는 도구가 마지막으로 가리킨 crosshair(측정/align point) 좌표가 들어 있습니다. 오버레이 방법은 좌표계 변환 하나가 전부이고, 나머지는 십자선 두 줄입니다:

  1. !Cursor_info 에서 crosshair 숫자 2개 (cx, cy) 를 뽑는다.
  2. 현재 구현의 Pixel × 10 oversample 가정에 따라 이미지 크기를 보정한 뒤 /10 으로 변환합니다 (1024px 샘플은 OFFICE-VERIFY).
  3. 변환된 점에서 프레임 전체를 가로지르는 초록 십자선 + 원 마커를 그린다.
  4. 프레임 중심 마커(빨강)를 함께 찍어, 단일 프레임에서 crosshair 가 중심으로부터 얼마나 벗어났는지를 표시합니다.

2. cond.txt 위치와 !Cursor_info

2.1 파일 위치 규약

이미지 파일마다 같은 폴더 안에 점(.) 접두 숨김 폴더가 하나씩 있고, 그 안에 cond.txt 가 있습니다. 파일명은 확장자까지 그대로 씁니다.

<image>.jpeg   →   .<image>.jpeg/cond.txt

align_images/<eqp_id>/<class>/<recipe>/
├─ align_img_from_rcp/   # recipe 등록 align key (Scope 있음): IMAP0001.jpeg …
└─ align_img_from_msr/   # 측정 궤적 (S=성공, E=실패. Scope 없음): S0001.jpeg …

경로 계산과 파싱은 손으로 하지 말고 align/cond_file.py 의 cond_path_for() / load_cond() 를 씁니다.

2.2 필요한 키 세 개

키뽑는 것용도
Pixel(width, height) — 예 512,512좌표 스케일 기준
ScopeOM / OMDF / SEM 토큰modality 구분 (rcp 만 존재)
!Cursor_info콤마 구분 숫자열crosshair + white box 좌표

2.3 !Cursor_info 인덱스 (0-base)

인덱스의미
[4], [5]crosshair (cx, cy) — 이 둘이 -1 이 아니면 crosshair 존재. 중심에서 align point 를 얻는 바로 그 값
[6]~[9]white box (left, top, right, bottom) — [6],[7],[8],[9] 가 모두 존재하고, 정수로 파싱되며, 모두 -1 이 아니어야 존재합니다.
-1 은 "없음"입니다. 그리기 전에 반드시 확인합니다. E(실패) 이미지에는 crosshair 가 아예 없는 경우가 흔하고, 그 부재 자체가 신호입니다.

키 이름은 실데이터에서 !Cursor_inf / !Cursor_info 로 흔들리므로 파서는 cursor_inf 접두 매칭을 합니다. 직접 파싱하지 말고 parse_cond() 를 씁니다. msr cond 에는 Scope 가 없으므로 modality 는 Accelerating_voltage(→SEM) · !OM_Brightness(→OM) 키로 확정하고, 둘 다 없으면 Magnification(<200 → OM, >500 → SEM)으로 추론합니다.

3. 좌표 변환 — Pixel × 10 프레임 가정

현재 구현은 !Cursor_info 의 좌표를 이미지 px 가 아닌 Pixel 의 10배 oversample 프레임 (clean_align_image.OVERSAMPLE = 10) 기준으로 처리합니다. 이 가정에 따른 변환입니다: 

이미지 px = cursor 좌표 / 10
OFFICE-VERIFY: clean_align_image.py 는 1024px 이미지 샘플이 없어 이 비율을 오피스 실데이터로 검증해야 한다고 명시합니다. OVERSAMPLE = 10 은 현재 구현값이며, 모든 해상도에서 검증된 규칙은 아닙니다.

예: Pixel 512,512 이면 cursor 프레임은 5120×5120 (= draw_crosshair_from_numbers.py 의 NATIVE_SIZE = 5120)이고, (2097, 2561) 의 변환 중간값은 (209.7, 256.1) 이고, 실제 그리기와 이미지 캡션에는 반올림한 (210, 256) 을 사용합니다.

이미지 실제 크기가 Pixel 과 다르면 고정 /10 은 계통 오차가 됩니다 (리사이즈 저장 등). 이때는 나누기 전에 cond_for_image() 로 축별 보정한 사본을 먼저 얻습니다. 멱등이라 여러 번 불러도 이중 보정되지 않습니다: 
img  = cv2.imread(path)
cond = cond_for_image(load_cond(path), img.shape[:2])

4. 오버레이 그리기

crosshair 는 점 하나입니다. 십자 두 선은 FOV 전체를 가로지르므로 교차점 (cx, cy) 하나만 있으면 선 길이는 화면 전체로 암시됩니다 — white box 처럼 숫자 4개가 필요하지 않습니다 (영역 = 숫자 4개, 점 = 숫자 2개). 

img  = cv2.imread(image_path)
h, w = img.shape[:2]
cond = cond_for_image(load_cond(image_path), (h, w))

if cond and cond.crosshair_xy:
    cx, cy = cursor_to_image(cond.crosshair_xy)      # /10
    cxi, cyi = round(cx), round(cy)
    t = max(1, w // 400)
    cv2.line(img, (cxi, 0), (cxi, h - 1), (0, 255, 0), t, cv2.LINE_AA)  # 세로
    cv2.line(img, (0, cyi), (w - 1, cyi), (0, 255, 0), t, cv2.LINE_AA)  # 가로
    cv2.circle(img, (cxi, cyi), max(3, w // 80), (0, 255, 0), t, cv2.LINE_AA)

if cond and cond.box_ltrb:                            # 겸사 white box
    l, top = cursor_to_image(cond.box_ltrb[:2])
    r, b   = cursor_to_image(cond.box_ltrb[2:])
    cv2.rectangle(img, (round(l), round(top)), (round(r), round(b)), (255, 255, 0), 1)
  • 선 두께 t = max(1, w // 400), 반지름 max(3, w // 80) — 화면 크기에 비례.
  • 이미지 밖 좌표면 초록 대신 빨강으로 그리고 캡션에 OUT! 을 표시 (draw_crosshair_from_numbers.py).
  • draw_crosshair_from_numbers.py 는 이 최소 예제로, 배경을 실제 msr 이미지로 쓰면 그린 십자가 도구가 그린 실제 십자 위에 정확히 겹치는 것으로 좌표계(NATIVE_SIZE)를 확정할 수 있습니다. 이것이 좌표계 검증 방법입니다 (S 이미지만 가능 — E 에는 십자가 없음).

5. 중심 vs align point — 정적 중심 오프셋 계산과 표시

5.1 정의

이름값의미
중심점 (center)(W // 2, H // 2)코드가 사용하는 정수 중심입니다. 홀수 크기에서는 W / 2, H / 2 보다 해당 축에서 0.5px 작습니다.
align point(cx, cy) = (cx0 × W / NATIVE_SIZE, cy0 × H / NATIVE_SIZE)스케일 변환한 crosshair 교차점입니다. 그릴 때는 각 축을 반올림합니다.

5.2 단일 프레임의 중심 오프셋 계산

한 이미지 안에서 crosshair 좌표와 정수 중심의 차를 축별로 계산합니다. 시간에 따른 이동(drift), 회전 기울기(skew), 오프셋 벡터의 크기는 계산하지 않습니다: 

fcx, fcy = W // 2, H // 2
off_x = cx - fcx          # +이면 중심보다 오른쪽입니다.
off_y = cy - fcy          # +이면 중심보다 아래입니다.

draw_crosshair_from_numbers.py 는 이 값을 계산해 캡션에 숫자로 찍습니다 (off-center=(-46,+0)px). 기본 예제 (2097,2561)@5120 을 512×512 이미지로 변환하면 좌표는 (209.7,256.1), 오프셋은 (-46.3,+0.1) 입니다. 이미지 캡션은 .0f 형식으로 좌표 (210,256) 과 오프셋 (-46,+0) 을 표시합니다.

5.3 다이어그램 — 중심 vs align point 와 정적 중심 오프셋

5.4 OM / SEM 을 함께 볼 때의 주의

  • 같은 recipe 의 OM(IMAP0001)과 SEM(IMAP0002)은 배율·FOV 가 달라 좌표를 서로 옮길 수 없습니다. 나란히(side-by-side) 배치해 각각 자기 cond 로 그리는 것이 유일하게 맞는 조합 방식입니다. 패널 캡션에 Scope / Pixel / Magnification 을 찍어 혼동을 막습니다.
  • OM key 는 프레임의 10~20% 를 차지하지만 SEM 은 zoom-in 되어 key 가 80~100% 를 채웁니다. 그래서 SEM 패널에서는 crosshair 가 거의 중앙에 찍혀 눈으로 오프셋을 읽기 어렵습니다 — 중심 오프셋을 캡션 숫자로도 확인할 수 있습니다.

6. cond 없이 crosshair 찾기 — 기하 기반 검출기

crosshair_detect.py 는 cond.txt 없이 이미지에서 도구가 그린 crosshair 를 역으로 찾는 쪽입니다 (검증·보정용). 기존 top-hat(국소 대비) 검출기는 배경이 밝으면 "주변보다 밝지 않다" → 응답 0 로 선이 사라져, 실데이터에서 crosshair 가 있는데도 "없음" 판정(no_crosshair_drawn 229/339)이 나오던 구조적 문제가 있었습니다.

v2 는 밝기 대비가 아니라 모양으로 찾습니다:

  1. 절대 고임계 mask: bright = (gray ≥ SAT_THRESH) (기본 235, ladder 235→215→195). crosshair 는 순백(255)에 가깝습니다. 스케일바(하단 10%)/축라벨(좌측 5%) 영역은 미리 제외.
  2. 방향성 형태학 opening: 가로선은 커널 (0.30·W, 1) 로 open — 긴 얇은 가로 런만 생존(2D blob 사망). 세로선은 전치. open 전에 선 방향 close (0.08 비율 커널)로 center gap 끊김을 메웁니다.
  3. projection → argmax: opened mask 의 row/col coverage 합의 argmax = 선 위치, argmax 주변 가중 평균으로 sub-pixel 교점 (cx, cy) 를 계산합니다. 반환되는 xy 는 반올림한 정수이며, 소수 좌표는 검출 성공 시 debug["sub_pixel"] 에만 남습니다.
  4. 가드: peak coverage 가 span 미달이면 선 없음. 고-coverage band 가 MAX_THICKNESS_PX * 3 = 18px 를 초과하면 blob 의심으로 해당 축마다 신뢰도에 0.5를 곱합니다 (두 축 모두 초과하면 0.25배). 배경 전체가 saturate(bright 비율 > 0.45)면 "모호" 처리 — 진짜 없음(E)과 구분.
confidence = min(1.0, 0.5·(h_cov + v_cov)) × thin_penalty
result = detect_crosshair(gray)       # CrosshairResult 객체를 반환합니다.
xy, confidence, debug = result.as_tuple()  # 튜플이 필요하면 별도로 변환합니다.
# xy: tuple[int, int] | None (검출 시 반올림한 정수 좌표)
# debug["sub_pixel"]: 검출 성공 시의 소수 좌표

검증은 오피스에서 실 msr 이미지에 대해 old vs v2 + 중간 mask(bright / h_mask / v_mask)를 montage 로 덤프하는 probe 하니스로 합니다. 기대 지표: S(성공) 의 검출률은 높고, E(실패 — ground truth 상 crosshair 없음) 의 false positive 는 0 에 가까워야 합니다.

7. 그리기 vs 지우기 — 같은 좌표, 반대 목적

같은 좌표를 지우는 구현이 align/clean_align_image.py 에 있습니다. crosshair 는 CV matcher 의 distractor 라 매칭 전에 cv2.inpaint(TELEA) 로 지우고, white box 는 rcp 에 그려 넣은 주석이라 테두리만 지웁니다(안쪽은 실제 내용이므로 절대 채우지 않음).

목적동작코드
시각화 (사람용)그린다 — 십자선 + 중심 마커 + 오프셋 캡션draw_crosshair_from_numbers.py, 본 문서의 오버레이
매칭 입력 (CV용)지운다 — inpaint 로 crosshair·box 제거clean_align_image.py

같은 파서·같은 좌표 변환을 쓰되 목적이 반대입니다. 시각화 코드를 매칭 경로에 끼워 넣지 않습니다.
