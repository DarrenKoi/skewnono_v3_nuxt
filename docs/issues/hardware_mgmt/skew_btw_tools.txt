스큐노노는 측정 장비간 스큐를 최대한 줄이고자 하는 목적으로 만들어진 웹 어플리케이션
반도체 CD를 측정하기 때문에 측정 수치가 매우 민감하게 작동하고 어느 장비로 측정하던지 
같은 수치로 나오는게 최대 목표. 하지만 장비간 약간의 설정 차이로 인해 동일한 Wafer를 
측정해도 약간씩 오차가 발생. 

CD_MONITORING이라는 Recipe로 동일한 WAFER를 주기적으로 측정하여 어느정도 장비간의 스큐를 모니터링하고
측정 값으로 장비의 상태를 확인. 
CD-SEM의 경우 X, Y 스캔 방향에 대해 전자 코일이 조정되기 때문에 각각 Calibration 되어 있음. 
 X, Y의 코일이 복합적으로 작용하는 특수각 (예, 32도, 64도, 218도 등등)도 측정하며, 
X, Y의 Calibration이 어떤 식으로 영향을 끼치는 지는 확인 못함.
       ? 
Calibration 수치는 장비마다 고유의 수치 (초기 H/W Setting 시 결정)를 가지며 예를 들어 A 장비에서 1.0001과 B 장비에서 1.0001은
다르다. S/W적으로 MDC (Measure Data Correction)를 조정해 최종적으로 원하는 값을 뱉어낼 수 있게 함. 
그 기준은 CD_MONITORING이고 모든 장비가 매일 측정하기 때문에 신규 장비 또는 BM/PM했을 때 H/W Setting을 마치고 
MDC를 조정해 원하는 값을 뽑을 수 있게 함. A = (MDC)*B + C 개념이기 때문에 CD_MONITORING 영역에서만 잘 맞을 수 있음. 

Run Lot Recipe들은 여러 공정의 CD를 측정하기 위해 운영되는 Recipe들. 

CD_MONITORING은 16nm대에 측정하기 때문에 Run Lot Recipe처럼 여러가지 CD 대역을 측정하는 경우를 완벽하게
대변하지 못함. 

양산의 경우 동일한 공정의 샘플을 여러번 측정하기 때문에 CD MONITORING과 동일한 공정 샘플을 같이 비교해 
어느 nm 영역대에선 어떤 Tool끼리 SKEW가 적다라고 추측할 수 있을거라 추정 --> 검증해본 적 없음.

R&D의 경우 동일 공정의 여러 장비에서 측정하는 경우가 거의 없기 때문에 참고 데이터를 얻기 어려움. 
MI팀에서 CD_MONITORING 외에도 3~4개의 샘플 Data를 모아서 주기적으로 돌려보는 수 밖에 없음. 

장비간 SKEW를 모니터링하고 관리하고 개선하는게 MI 팀에서 제일 중요함. 

관리 방법론을 정립하고, 모니터링할 수 있는 대시보드를 만들고 싶다.
