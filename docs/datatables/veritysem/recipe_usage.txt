Key 1 — recipe 목록 (존재하는 recipe)

Key 2 의 "사용량" 과는 별개입니다. 이쪽은 장비가 한 번이라도 작업을 시작한 recipe 의
전체 기간 목록입니다.

규모: VeritySEM 24,352 행 / 55 대 / recipe 9,451 개, Provision 27,386 행 / 54 대 /
recipe 11,040 개입니다. 고정값으로 가정하지 않습니다.

grain: 1행 = (eqp_id, recipe_id, fab_id) 입니다. **(eqp_id, recipe_id) 로는 유일하지
않습니다.** 같은 장비 · 같은 recipe 가 fab_id 별로 여러 행에 나뉘어 있으므로, 장비별 값이
필요하면 n_uses 는 더하고 first_used 는 최솟값, last_used 는 최댓값을 씁니다.

| 컬럼 | 뜻 |
| --- | --- |
| eqp_id | v3_df_sem_list 의 eqp_id |
| fac_id | 장비의 fac_id |
| fab_name | 장비의 fab_name. 조회는 이 값으로 합니다 |
| fab_id | MES 이력의 fab. fab_name 에 없는 값(C2, X1)이 있습니다 |
| recipe_id | recipe full name. 계열마다 형식이 다릅니다 (아래) |
| n_uses | int. (eqp_id, recipe_id, fab_id) 조합의 JobStart 수 |
| first_used / last_used | str. KST, offset 없음 |
| product_id / layer_id / recipe_name | str. **Provision 전용** split 컬럼 |

Provision 은 11개, VeritySEM 은 split 컬럼 3개가 빠진 8개입니다.

first_used / last_used 의 형식은 전달받은 표기가 "YYYY-MM-DD HH:MMSS" 였습니다. 초 앞의
":" 이 빠진 오기로 보고 mock 은 "YYYY-MM-DD HH:MM:SS" 로 만듭니다 (OFFICE-VERIFY).
어댑터는 문자열을 그대로 넘기고 datetime 컬럼이면 이 형식으로 바꿉니다.

fab_id 가 평소 어떤 값인지는 받지 못했습니다. mock 은 대부분 장비의 fab_name 과 같다고
가정합니다 (OFFICE-VERIFY). 확인된 것은 "C2, X1 이 있고 fab_name 이 아니다" 까지입니다.

recipe_id 형식

    Provision : <ProductID>/<LayerID>/<RecipeName>     예) 4S8/4S8_CBL_C0A_UPH_4P/AVIS   ("/" 2개)
    VeritySEM : <TYPE>/<DEVICE>/<LAYER>/<JOB>          예) FI/S2/POM/S2_POM              ("/" 3개)

VeritySEM 의 recipe_id 는 4조각을 통짜로 저장합니다. **무조건 4조각으로 파싱하지
않습니다** — 4조각으로 자르면 10 행이 깨집니다. 적재기는 "/" 가 2개 미만인 행만 버리므로,
"/" 가 2개이거나 4개 이상인 VeritySEM id 가 key 에 남아 있습니다. SKEWNONO 는 recipe_id 를
어디서도 자르지 않고, Provision 의 세 조각은 key 가 준 split 컬럼만 씁니다.

이 key 는 MES 실측 목록이라 JobStart 가 있는 recipe 만 있습니다. 장비 내부용 · 모니터용
recipe 는 없습니다(Key 3 에 있습니다).

fac_id 와 fab_name: **fac_id = R3, fab_name = R4 조합이 실재합니다.** fab_name 이 fac_id 로
시작한다고 가정하지 않습니다. fab_name 값은 계열마다 있는 것과 없는 것이 다릅니다.

Key 2 — recipe 사용량 (일별)

규모: VeritySEM 76,995 행 / 54 대 / recipe 2,220 개, Provision 27,358 행 / 53 대 /
recipe 1,708 개입니다.

grain: 1행 = (dt, eqp_id, recipe_id) 이며 이 셋이 유일합니다. fab_name 은 grain 이
아닙니다.

두 계열의 컬럼은 같은 11개입니다. **null 이 없습니다.** meas_min 만 float 이고 나머지
수치는 int 입니다.

| 컬럼 | 뜻 |
| --- | --- |
| dt | 측정일 YYYY-MM-DD (MES event_tm 기준) |
| eqp_id | v3_df_sem_list 의 eqp_id |
| fac_id | 장비의 fac_id |
| fab_name | 장비의 **현재** 소속 fab. 그 장비가 과거 다른 fab 에서 돌린 실적은 들어 있지 않습니다 |
| recipe_id | Key 1 과 같은 형식 |
| runs | 그날 시작한 측정 작업 수 (재측정 포함) |
| wafers | 측정 wafer 합계 |
| meas_min | 측정 소요 분 합계 (JobEnd.proc_time) |
| fail_runs | 정상 종료되지 않은 작업 수 (아래) |
| first_start / last_start | 그날 그 recipe 의 첫 / 마지막 작업 시작 시각 (KST) |

기간에 대한 주의

- 최신 dt 는 **전날**입니다. 오늘 날짜의 dt 를 찾지 않습니다.
- 창은 "dt 90일" 이 아니라 **적재 파티션 90일**입니다. 실제 행의 dt 범위와 다르므로, 기간
  합계를 낼 때 90일을 가정하지 않고 dt 를 직접 셉니다.
- 초반부는 하루 1~2 행 수준으로 희박합니다.

fail_runs 에 대한 주의

- 끝나지 않았거나 MES 가 최종 데이터로 채택하지 않은 작업 수입니다. 이유는 저장하지
  않습니다. 여러 이유가 겹칠 수 있어 OR 로 센 값입니다.
- **fail_runs == runs 인 행이 흔합니다.**
- JobEnd 가 없는(no_jobend) 작업은 meas_min 이 0 으로 잡힙니다. 평균 측정 시간은
  meas_min / runs 로 계산하되, fail_runs 가 많은 행에서는 낮게 나옵니다.

두 key 의 관계: Key 2 의 (eqp_id, recipe_id) 조합은 Key 1 에도 있어야 정상입니다.

Key 3 — 장비 상주 recipe

hash 이며 field = eqp_id, value = JSON 배열(recipe full name)입니다. 장비의
Veridity/Reports/*.KLA 파일명에서 파싱한 이름입니다. **갱신이 보장되지 않습니다.**

Key 1 과 상보적입니다. VeritySEM 기준으로 Key 3 에만 있는 recipe 가 630 개(내부 · 모니터용),
Key 1 에만 있는 recipe 가 8,421 개입니다. 두 key 의 **합집합**이 "이 장비가 쓸 수 있는
recipe" 입니다.

Veridity 가 없는 장비(../veritysem/verity_hosts.txt 의 veridity "-")가 이 hash 에 없는지는
받지 못했습니다. mock 은 그렇다고 가정합니다 (OFFICE-VERIFY).

Key 4 — recipe 가 있는 장비

hash 이며 field = recipe, value = JSON 배열(eqp_id)입니다. key 이름의 {fab} 은 fab_name 을
소문자로 쓴 값입니다.

어댑터 소비 규약 (backend/ebeam/recipe_usage)

- **Key 4 는 읽지 않습니다.** Key 3 을 뒤집으면 같은 관계가 나오므로, 읽으면 fab 마다 key
  하나씩 왕복만 늘어납니다. 이름과 모양은 기록으로만 남깁니다.
- 장비 명부는 sem_list 뿐입니다. `model_to_tool_type(eqp_model_cd)` 가 그 계열인 행만 쓰고
  eqp_id 는 파싱하지 않습니다. key 에는 있으나 명부에 없는 장비의 행은 버립니다.
- 명부에는 있으나 실적이 없는 장비는 **0 으로 표시합니다** (user-confirmed 2026-11-12).
  목록에서 빼지 않습니다.
- fab 범위는 **명부의 fab_name** 으로 정합니다. key 의 fab_name / fac_id 컬럼은 읽지
  않습니다. fab_id 는 응답에 나가지 않습니다.
- Key 1 은 fab_id 를 가로질러 접습니다(n_uses 합, first_used 최솟값, last_used 최댓값).
- recipe 목록은 Key 1 과 Key 3 의 합집합이며 출처를 source 로 표시합니다 — mes(Key 1 만),
  tool(Key 3 만), both.
- 날짜 선택기의 한계(anchor_date, data_start)는 Key 2 의 행에서 구합니다. 기본 조회 기간은
  최신 dt 로 끝나는 14일입니다.
- Key 3 이 없거나 비어 있으면 오류가 아니라 빈 값으로 처리합니다(목록이 MES recipe 만
  보입니다). Key 1 · Key 2 가 없으면 502 입니다.
- null 이 없다는 사실에 기대지 않습니다. NaN / None 은 "" 또는 0 으로 바꾸고, eqp_id 나
  recipe_id 가 빈 행은 버립니다.
