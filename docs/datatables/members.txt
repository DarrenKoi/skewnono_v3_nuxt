사무실(Office) Redis hash — 사번 → 사원 정보

인증된 사용자의 이름과 소속을 채우는 유일한 소스입니다. 답하려는 질문은 하나입니다 —
**이 사번은 누구이고 어느 조직인가.**

이 문서가 기록하는 것은 *조회 방식*이지 접근 제어가 아닙니다. 접근 권한은
`access_control` 과 `_auth/admin.py` 의 allowlist 가 결정하며, 이 hash 는
아무도 승격시키지 못합니다.

Key
  members -> Redis hash. field = 사번(empno), value = 사원 1명의 JSON document

조회
  HGET members <LASTUSER 쿠키 값>

  `LASTUSER` 쿠키가 곧 사번입니다. 쿠키 값을 그대로 field 로 사용합니다.

  사무실 원본 코드 (user-confirmed 2026-07-31):

    data = redis.hget("members", str(LASTUSER))
    member = json.loads(data.decode("utf-8"))

  value 는 **UTF-8 로 인코딩된 JSON object** 입니다. field 이름은 str 로 넘깁니다.

사용 field

  empno -> str: 사번. 쿠키 값과 동일한 것으로 기대합니다.
                ※ 만약 document 의 empno 가 쿠키와 다르면 **쿠키가 우선**입니다.
                  access control, admin allowlist, activity log 가 이미 쿠키 값을
                  key 로 쓰고 있어서, document 가 요청 도중에 사용자를 개명시키면
                  한 사람이 두 identity 로 갈라집니다.
  emp_nm -> str: 이름.
  dept_nm -> str: 부서명.
  organ_cd -> str: 조직 코드. 숫자로 저장되어 있을 가능성이 있어 어댑터는 str 로
                   강제 변환합니다.
  upper_organ_nm -> str: 상위 조직명.

없을 수 있는 값

  empno 를 제외한 모든 field 는 없거나 빈 문자열일 수 있습니다. 빈 문자열은
  "미설정"으로 보고 None 으로 정규화합니다 — UI 에 빈 이름이 노출되지 않게 합니다.

  **조회 실패는 오류가 아닙니다.** 협력사·서비스 계정은 `LASTUSER` 쿠키만 있고
  members row 가 없을 수 있습니다. 이름은 이미 완결된 identity 에 붙는 장식이므로,
  아래 경우 모두 사번만 담은 record 로 degrade 하고 요청은 그대로 진행합니다.

    - Redis 미설정 / 접속 불가
    - members hash 없음
    - 해당 사번의 field 없음
    - value 를 JSON 으로 해석할 수 없음

  office adapter 들이 LookupError/RuntimeError 로 502/503 을 올리는 것과 **반대**
  방향입니다. directory 장애로 사용자가 볼 권한이 있는 페이지를 못 보게 되는 쪽이
  이름을 못 보여주는 것보다 나쁜 장애이기 때문입니다.

확인 근거

  hash 이름, 조회 방식, field 철자 5종 -> user-confirmed 2026-07-31
  value 가 UTF-8 JSON object 라는 것  -> user-confirmed 2026-07-31
                                        (사무실 원본 코드로 확인, 위 "조회" 절)

  가정으로 남은 항목은 없습니다. 다만 decode 실패는 여전히 degrade 로 처리합니다 —
  인코딩이 의심스러워서가 아니라, row 1건이 깨졌다고 그 사용자를 접속 불가로
  만들면 안 되기 때문입니다. 그런 경우 warning 로그
  "member document for <사번> is not the expected JSON object" 가 남고, 해당
  사용자는 사번만으로 계속 접속합니다.

소비 코드

  back_dev_home/_auth/directory.py  — 조회·정규화·캐시(TTL 600초)
  back_dev_home/_auth/routes.py     — GET /api/me 로 노출

  집/사무실 판정은 `get_mode()`(데이터 provider 와 동일한 knob)를 사용합니다.
  `is_cloud()` 가 아닙니다 — `is_cloud()` 는 집과 사무실 localhost 를 구분하지
  못하고, 집의 `.env` 에도 REDIS_HOST 가 (도달 불가한 사무실 host 를 가리킨 채)
  설정되어 있기 때문입니다.

  집에서는 Redis 를 아예 호출하지 않습니다. 연결을 시도하면 cold lookup 당
  socket timeout 전부(10초 = connect 5초 + 재시도 1회)를 소모하고 결과도 얻지
  못합니다. 대신 `_home_member()` 가 명백한 placeholder("홍길동(<사번>)",
  "MOCK-ORG")를 만들어 shape 만 재현합니다. 사무실 실제 값을 흉내내지 않습니다.
