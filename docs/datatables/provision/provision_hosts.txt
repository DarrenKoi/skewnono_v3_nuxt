사무실(Office) Redis — PROVISION 장비 data host 명부 + tool version (user-confirmed 2026-10-23)

Provision 은 다른 계열과 달리 측정 데이터를 **장비 IP 가 아닌 별도의 data host IP**
에서 꺼냅니다. v3_df_sem_list 의 eqp_ip 는 장비(tool) 자체의 IP 이므로 Provision
의 데이터 추출에는 쓸 수 없습니다. 이 key 가 Provision 장비마다 data host IP 와
측정 CSV export 위치를 짝지어 둔 명부입니다.

저장 형태: Redis, pandas DataFrame 을 parquet 직렬화(sem_list 와 같은 방식).

Key 1 -> "v3_df_provision_hosts"   : data host 명부 (아래 대부분이 이 key 의 설명)
Key 2 -> "v3_df_provision_version" : 장비(tool) 쪽 version 과 tool IP 접속 여부 (맨 아래 절)

용도: **읽기 전용** 입니다. 우리 쪽에서 쓰지 않습니다. 사무실의 정기 작업이 한 시간에
두 번 갱신합니다 (예약 작업에 문제가 없을 때 기준, user-confirmed 2026-10-23).

규모: 2026-10-23 기준 53 행 x 7 열입니다. 행 수는 장비 반입에 따라 바뀌므로 고정값으로
가정하지 않습니다.

컬럼 정보 (7개, 전부 문자열 타입)

| 컬럼 | 뜻 |
| --- | --- |
| eqp_id | v3_df_sem_list 의 eqp_id. 명부와 join 하는 key 이며 이 key 안에서 유일합니다 (user-confirmed 2026-10-23) |
| fab_name | v3_df_sem_list 의 fab_name |
| data_ip | data host IP (장비 IP 아님). 단, 아래 "tool-ip fallback" 행에서는 probe 대상으로 장비 IP 를 대신 넣어 둔 값입니다 |
| spreadsheet_path | 장비별 측정 CSV(wafer 단위) export 디렉터리의 FTP 절대 경로 |
| ip_note | data_ip 의 출처 (아래 값 목록) |
| available | "On" / "Off" |
| checked_at | 마지막 점검 실행의 UTC ISO timestamp |

ip_note 값 — 아래 네 문자열이 전부이며, 괄호까지 포함해 정확한 표기입니다
(user-confirmed 2026-10-23). 행 수는 2026-10-23 기준 분포입니다.

| 값 | 뜻 |
| --- | --- |
| data-ip confirmed | data IP 가 확인됨. 46 행 |
| data-ip candidate (authfail) | 후보 IP 이나 로그인 실패 |
| data-ip candidate (unreach) | 후보 IP 이나 접속 불가 |
| tool-ip fallback (no data share) | data share 가 없어 장비 IP 로 대체. "pending" 5 행 |

판정 규칙: ip_note != "data-ip confirmed" 인 행은 data_ip 를 추출용으로 아직 믿을 수
없습니다. 추출 경로는 반드시 이 비교 하나로 거릅니다 — available 만으로 거르지
않습니다. 네 값의 표기는 확정되었지만, 코드는 여전히 "data-ip confirmed" 와의 일치
여부만 봅니다 — 다섯 번째 값이 생겨도 그 행은 자동으로 미연결 쪽에 남습니다.

available 의 뜻: On 은 P-drive 목록 조회가 항목을 돌려준 경우입니다. 즉 로그인이 되었고
**그리고** data share 가 존재합니다. FTP 는 응답하지만 data share 가 없는 장비는
올바르게 Off 입니다. 따라서 Off 가 곧 "장비 고장" 을 뜻하지 않습니다.

spreadsheet_path 예시 — 장비마다 대소문자와 깊이가 다릅니다:

    /P_Drive/QA/EXPORT/Spreadsheet
    /p_drive
    /P_Drive/Export/Spreadsheet

경로를 정규화하거나 하나의 기본값으로 가정하지 않고, 행의 값을 그대로 씁니다.
(README.md 의 /I_Drive · /D_drive/ 결과 위치와 이 P-drive export 의 관계는
OFFICE-VERIFY 입니다.)

checked_at: 모든 행이 같은 stamp 하나를 공유합니다(한 번의 점검 실행). 화면에 보일 때는
KST 로 변환합니다. 이 값으로 갱신이 멈췄는지 판단할 수 있습니다 — 정상이면 30분
남짓보다 오래되지 않습니다.

Key 2 -> "v3_df_provision_version" (user-confirmed 2026-10-23)

장비 쪽 version 을 알려 주는 key 입니다. 하루 한 번 갱신합니다. 저장 형태는 Key 1 과
같습니다(parquet DataFrame).

| 컬럼 | 뜻 |
| --- | --- |
| eqp_ip | 장비(tool) IP — v3_df_sem_list.eqp_ip 와 같은 값. eqp_id 컬럼은 없습니다 |
| version | 장비의 /D_drive/Qrelease/current_version.ini 에서 읽은 **원문 그대로의** 문자열. "" = probe 실패 |
| available | "On" = 그 ini 파일 다운로드에 성공. 즉 tool IP 로 FTP 접속이 됩니다 |

eqp_id 가 없으므로 Key 1 과는 직접 join 되지 않습니다. v3_df_sem_list 의
eqp_id -> eqp_ip 를 다리로 씁니다. data_ip 로 join 하면 안 됩니다 — "tool-ip fallback"
행에서만 우연히 맞습니다. eqp_ip 는 이 key 안에서 유일하므로 안전한 join key 입니다
(user-confirmed 2026-10-23).

version 형식 (user-confirmed 2026-10-23) — 장비 vendor 별로 다르며, 계열 간 정규화를
하지 않습니다. key 는 ini 의 원문 문자열을 그대로 저장합니다.

    PROVISION : 점으로 구분한 숫자 <major>.<minor>.<patch>.<build>   예) 16.10.33.40755
    VeritySEM : (같은 version key 계열) Ver_<maj>_<min>_<pat>_<build>_Win7

따라서 version 을 숫자로 정렬하거나 계열을 섞어 비교하지 않습니다. 화면에는 받은 문자열을
그대로 보여 줍니다. VeritySEM 쪽 key 는 v3_df_verity_version 이며 이 key 와 같이 eqp_ip 로 join 합니다
(../veritysem/verity_hosts.txt).

두 key 의 available 은 이름이 같지만 다른 것을 잽니다(Key 1 = data host, Key 2 = tool).
SKEWNONO 백엔드는 읽자마자 data_available / tool_available 로 이름을 바꿉니다.

SKEWNONO 소비처 (sem_list, 2026-10-23 구현, 사무실 검증 대기)

Provision 은 v3_df_sem_avail 이 아니라 이 두 key 로 판정합니다. v3_df_sem_avail 에도
Provision 행이 있지만 쓰지 않습니다.

1. GET /api/sem-list (장비 리스트) — v3_df_sem_list 의 PROVISION* 행 중
   ip_note == "data-ip confirmed" 인 행. available 은 data host 의 것입니다.
2. GET /api/sem-list/pending (미연결 장비) — 나머지 PROVISION* 행 전부. Key 1 에 아예
   없는 장비도 미연결입니다.

두 화면 모두 Tool IP(eqp_ip) 와 Data IP(data_ip), tool / data 접속 여부를 함께 보여
주며 checked_at 은 KST 로 표시합니다. Provision 에는 스토리지 탭이 없습니다
(user-confirmed 2026-10-23). 구현과 컬럼 매핑은 backend/sem_list/MIGRATION.md 의
PROVISION 절을 참고합니다.

OFFICE-VERIFY

- v3_df_sem_list 의 PROVISION* 행이 전부 Key 1 에 있는지(빠진 장비가 있는지).

FTP 접속 (tool_files, 2026-10-23 구현)

계정은 wf 이며 tool IP(eqp_ip) 와 data IP(data_ip) 모두 같은 계정으로 접속합니다
(user-confirmed 2026-10-23, 비밀번호는 사무실 .env 에만 둡니다). FTP 접속 화면에서 Tool / Data
호스트를 골라 둘러봅니다. 각 호스트의 로그인 폴더는 OFFICE-VERIFY 입니다.

spreadsheet_path 는 sem_list 응답에 그대로 실려(정규화 없음) FTP 접속 화면의 "측정 CSV 폴더"
바로가기가 됩니다. 누르면 Data 호스트로 바꾸고 그 경로를 엽니다. 이 경로가 data host 에서
FTP 로 열리는지는 OFFICE-VERIFY 입니다.
