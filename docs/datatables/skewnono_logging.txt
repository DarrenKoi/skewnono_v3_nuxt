skewnono_logging / skewnono_logging_local — 제품 활동·운영 로그 (OpenSearch)

출처: SKEWNONO 자체 생성 인덱스입니다. 외부 팀 소스가 아니라 우리 Flask
middleware(OpenSearchBulkHandler)가 쓰는 canonical log document이며, 스키마의
진실 원천은 ops_index_mgmt/skewnono_logging.py 의 LOG_MAPPING_PROPERTIES 와
docs/api-contracts/usage-events.yaml 입니다. 이 문서는 datatables 규약에 따라
reader/writer가 함께 보는 요약본입니다. (mapping 은 user-confirmed 2026-07-27,
cluster 반영은 office 확인 2026-07-28 — 회사에서 두 alias 를 실제로 생성했습니다)

환경과 alias
- office PC localhost -> alias skewnono_logging_local, 보존 rollover 후 30일
- production cloud    -> alias skewnono_logging,       보존 rollover 후 365일
- 두 family 는 같은 mapping/shard/rollover(20GB 또는 7일)이며 보존 기간만 다릅니다.
- 쓰기/읽기 alias 는 모두 SKEWNONO_LOG_ENV 를 back_dev_home/_logging/target.py 가
  해석해 결정합니다. 코드에 alias 문자열을 직접 쓰지 않습니다.

mapping (dynamic: false — 아래 필드만 색인됩니다)
event_id -> keyword: 문서 _id 로도 사용합니다. bulk retry 가 중복 문서를 만들지 않습니다.
@timestamp -> date: UTC ISO-8601 (offset 포함). 사무실 다른 인덱스의 KST wall-clock
  관행과 다르므로 주의 — calendar 집계는 time_zone Asia/Seoul 을 명시해 계산합니다.
event -> keyword: request | request_exception | 일반 application event
level -> keyword: Python logging level (INFO/WARNING/ERROR/...)
logger -> keyword: logger 이름 (요청 로그는 skewnono.activity)
message -> text: bounded 사람용 메시지 (최대 4,096자)
service -> keyword: 고정값 skewnono
deployment -> keyword: local | production
host -> keyword: 실행 host 이름
request_id -> keyword: 요청 correlation ID (request 와 request_exception 을 잇습니다)
user_id -> keyword: 인증 사용자 ID. 없으면 필드 자체를 생략합니다 (null 컬럼 없음).
api_token_id -> keyword: token 자동화 요청 식별자. 없으면 생략합니다.
method -> keyword: HTTP method
path -> keyword: query 제외 request path
query_string -> keyword(ignore_above 2048): 민감 key 는 [REDACTED] 치환, 2,048자 제한
status -> integer: HTTP status
latency_ms -> integer: 요청 처리 시간
remote_addr -> keyword: 내부 client/proxy 주소
feature -> keyword: page-level feature slug (_logging/feature_map.py 가 결정)
activity_kind -> keyword: entry | feature | background | operation
activity_weight -> integer: 활동 집계 대상이면 1, 아니면 0
fab_name_list -> keyword: 정규화된 FAB 이름 JSON list. 단일 FAB 도 ["M14"] 형태이며
  context 가 없으면 빈 list 입니다. scalar fab_name 과 혼동하지 않습니다.
error_code -> keyword: HTTP status 또는 예외 타입 이름
error_name -> keyword(최대 1,024자): bounded 오류 이름
exception.type -> keyword / exception.message -> text / exception.stack -> text(32,768자)

alias 판정 시 주의 (office 확인 2026-07-28)
- OpenSearch 의 HEAD /<target> (indices.exists) 는 concrete index 뿐 아니라
  alias 도 resolve 해서 200 을 돌려줍니다. ops_store.OSIndex.describe() 는
  exists() 가 False 일 때만 exists_alias() 를 호출하므로, 정상적인 rollover
  alias 에 대해 is_alias=False 와 빈 rollover 요약을 반환합니다.
- 따라서 alias 건강성은 describe()["is_alias"] 나 describe()["rollover"] 로
  판정하면 안 됩니다. exists_alias() 를 직접 부르고
  describe()["aliases"][alias]["write_index"] 를 읽어야 정확합니다.
  (_summarize_aliases 가 실제 cluster metadata 로 만든 값이라 정확합니다.)
- 이 함정 때문에 2026-07-28 회사에서 alias 생성 직후 python index.py 가
  "skewnono_logging_local is not a ready numbered rollover alias" 로 실패했고,
  같은 원인으로 provisioning script 재실행도 거부되었습니다. 두 호출부
  (_logging/opensearch_handler.py, ops_index_mgmt/skewnono_logging.py) 는
  수정했지만 vendored ops_store.OSIndex.describe() 자체는 그대로이므로,
  alias 를 다루는 새 코드는 같은 방식으로 우회해야 합니다.

레거시 필드 (mapping 에 없음)
- request_path 는 c11fbc2 이전 스키마가 쓰던 필드로 mapping 에 없습니다
  (dynamic:false 이므로 색인되지 않고 _source 에만 남습니다). admin_logs 의
  item_from_hit 은 path or request_path 순서로 fallback 하므로 과거 문서도
  화면에는 정상 표시됩니다. 새 문서에는 절대 쓰지 않습니다.

어댑터 소비 규약
- 활동 지표(activity reader)는 event=request AND activity_weight=1 AND
  activity_kind IN (entry, feature) 만 셉니다. top feature / FAB page 순위는
  activity_kind=feature 만 씁니다. entry(sem_list 진입)는 DAU/WAU/MAU 에는
  포함하고 순위에는 넣지 않습니다.
- OPTIONS/HEAD 요청은 분류 단계에서 operation/0 이므로 활동 지표에 나타나지
  않습니다 (CORS preflight 오염 방지, 2026-07-27 수정).
- 날짜 경계는 반드시 time_zone: Asia/Seoul 로 집계합니다. @timestamp 를 UTC 로
  저장하므로 KST 자정 전후 9시간 구간에서 수동 date() 절단은 하루가 어긋납니다.
- pagination 은 from+size <= 10,000 (index.max_result_window) 안에서만 동작합니다.
  admin_logs 는 이 한도를 넘는 page 를 400 invalid_log_query 로 거부합니다.
- error_name 은 keyword 이므로 부분 일치 검색은 wildcard 를 씁니다. match_phrase
  는 전체 값 정확 일치로 조용히 축소되므로 금지합니다.
- 요청·응답 body, Authorization header, cookie 는 저장하지 않습니다. 새 query
  field 가 필요하면 이 파일과 ops_index_mgmt mapping 에 함께 추가한 뒤
  회사에서 additive mapping update 를 실행합니다.
