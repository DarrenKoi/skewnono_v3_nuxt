R3, R4와 같은 R로 시작하는 팹을 눌렀을 때 불러와지는 Datatable

Column -> Type: Value 설명

(컬럼명은 아래 Office/Redis 섹션과 동일 — plan_catg_typ, den_typ 표기가 정식)
주의: 결측이 섞여 있습니다 — 실제 None/NaN 뿐 아니라 문자열 "None" 이
그대로 들어 있는 cell 도 있습니다. 어댑터는 둘 다 빈 값("")으로

fac_id -> R3 (단일 value)
plan_catg_typ -> FULL, ADTPJT, MODULE, "" (플랜 카테고리 타입)
prod_catg_cd -> DRAM, Tech, Advanced, FLASH, NAND ()
tech_cd -> T1Z, S128, T1Y, C20, F12m, ""
den_typ -> 16G, 1T, 512G 등
prod_grp_typ -> DDR4, Memory Tech, Advanced, NAND, Raw NAND, HZBM2E, GDDR6, ""
gen_typ -> 2ND, 4TH, 1ST,

========================================================================
사무실(Office) 실데이터 소스 — Redis
========================================================================

사무실에서는 이 R3/R&D 카탈로그가 Redis 에 pandas DataFrame 으로 저장됩니다.
device_desc 와 형태가 비슷하며 fac_id 는 항상 "R3" 입니다.

Key    -> "device_info_rnd" (DataFrame, parquet 직렬화)
          R3 연구개발(R&D) 카탈로그입니다. (user-confirmed 2026-07-30)
Column -> fac_id, plan_catg_typ, prod_catg_cd, tech_cd, den_typ,
          prod_grp_typ, gen_typ, lot_cd, plan_grade_cd, lake_load_tm, ctn_desc

정정 사항 (user-confirmed 2026-07-30)

- Key 이름: 이전에 "r3_device_grp" 로 기록했으나, 사무실이 실제로 서빙하는
  key 는 device_info_rnd 입니다. M 계열 양산 쪽은 별도 key device_info_hvm
  입니다 (docs/datatables/device_desc.txt 참고).
- 두 key(device_info_hvm, device_info_rnd)는 device-statistics 의 initial
  setup 카탈로그입니다. 화면 요청에 따라 이 카탈로그에서 device code 를
  추출해 사용합니다.
- tech_cd 와 device_desc 의 tech_nm 은 서로 다른 컬럼입니다. 이름이 비슷해
  혼용하기 쉬우나, 어댑터에서 alias 로 묶지 않습니다.

실제 컬럼/행 수/결측 분포는 사무실에서 아래로 확인합니다 (OFFICE-VERIFY):

    .venv/bin/python -m scripts.inspect_device_info_keys

사용 방법

- recipe_tat 디바이스별 화면: lot_cd -> prod_catg_cd 로 R3/R&D device 의
  제품 카테고리를 채웁니다. (M fab device 는 device_info_hvm.tech_nm,
  R3/R&D device 는 device_info_rnd.prod_catg_cd — device 당 둘 중 하나만
  채워짐.)
- device-statistics 기능에서도 이 DB 를 그대로 활용할 수 있습니다.
