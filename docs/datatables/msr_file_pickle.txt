========================================================================
어댑터 소비 규약 (msr_file office adapter)
========================================================================

이 pickle 을 화면 계약(MsrFileResponse)으로 옮길 때 지켜지는 규칙입니다. 위 스키마가
바뀌면 여기부터 확인합니다.

컬럼 이름 정규화

  df_result_data 의 컬럼명에는 **공백**이 들어 있습니다("mp_image_name 01",
  "meas_condition mag", "meas_condition vac", "meas_condition pixel"). 어댑터는 읽는
  즉시 소문자 + 공백->underscore 로 정규화하므로, 아래 계층은 한 가지 철자만
  다룹니다(mp_image_name_01, meas_condition_mag, ...).

  "object" 컬럼은 Python 내장 이름과 겹치므로 계약에서는 object_type 으로 옮깁니다.
  "class"(exe_detail_info) 도 예약어라 class_name 이 됩니다.

  mp_image_name 은 01 하나가 아니라 NN 번호가 붙어 여러 개 존재할 수 있습니다
  (no_of_mp_image 만큼). 화면 계약은 대표 1장(mp_image_name_01)만 쓰지만, 장비 FTP
  이미지 목록 대조(docs/datatables/msr_image_ftp.txt)는 mp_image_name 으로 시작하는
  컬럼 **전부**를 훑습니다.

없는 field

  chip_coordinate -> 이 pickle 에 **없습니다.** 계약에는 있으므로 빈 문자열("")로
                     채웁니다. meas_hist 의 lot_cd 와 같은 처리입니다(row 를 버리지
                     않고 미매핑을 빈 값으로 표기).
  per-sequence timestamp -> 없습니다. sequence 별 시각을 요구하는 계산(초당 변화율,
                     시간 지연)은 이 소스로 만들 수 없습니다. 스큐보아의 sequence
                     workbench 가 모든 기울기를 "sequence step 당" 으로만 내보내는
                     이유입니다.

부모 문서에서 오는 값

  pickle 은 자기 자신을 설명하지 못하는 값이 있어 meas_hist 문서에서 받습니다.
    total_images        <- 부모 doc
    sequence_timestamp  <- 부모 doc 의 start_time (없으면 timestamp)
    recipe_name / idp_name / idw_name / lot_id -> pickle 값이 비면 부모 doc 로 보완

파생되는 canonical metadata (office 모드에서 비어 있으면 계약 gate 실패)

  site_layout_hash -> layout 을 정의하는 값들의 sha1:
                      chip_array / chip_pitch / wafer_size / map_origin +
                      (chip_number, dnum_group, mp_number) site 집합(정렬).
                      **map_offset 은 일부러 제외**합니다 — run 마다 달라지는
                      align 보정이 섞여 있으면 같은 layout 이 여러 개로 쪼개집니다.
                      OFFICE-VERIFY: map_offset 이 실제로 run 별로 변하는지 확인.
  recipe_revision -> exe_detail_info 에 진짜 revision key 가 있으면 그 값을 씁니다.
                     찾는 이름 순서: recipe_revision, revision, recipe_rev, rev_no.
                     없으면 recipe identity + layout + parameter 집합으로 만든
                     "fp-" 지문입니다. 지문은 pickle 에 드러나는 변화만 구분하므로,
                     pickle 에 안 보이는 revision 변경은 하나로 합쳐집니다.
                     실제 field 를 찾으면 교체합니다.
  coordinate_transform_version -> pickle 에 있으면 그 값, 없으면 고정 tag
                     "minio-pkl-v1" (사무실 pickle 후처리 파이프라인의 이름).

FDC 처리

  fixed_fdc / dynamic_fdc 는 숫자로 해석되는 값을 **전부 그대로** 통과시킵니다.
  모델마다 key 가 달라지므로 화이트리스트로 자르지 않습니다 — 차트는 아무것도 잃지
  않습니다.

  다만 요약 행(nominal / drift_sigma / status 판정)은 baseline 이 있어야 의미가
  있으므로, 공유 카탈로그(DYNAMIC_FDC_SPECS)에 등재된 파라미터에 대해서만 만듭니다.
  카탈로그에 없는 파라미터는 raw 값은 나오되 판정은 나오지 않습니다 — nominal 을
  지어내지 않기 위해서입니다. 사무실 baseline 이 합의되는 대로 카탈로그를 늘립니다.

  health 값은 이 요약에서 파생됩니다: 최악 drift_sigma 를 3.5 sigma("bad" 임계)에서
  1.0 이 되도록 스케일한 [0, 1] 값입니다.

값 타입

  pickle 값은 str / float / None / 문자열 "None" 이 섞여 옵니다. 숫자 계약 field 는
  float 로 변환하고, 변환 실패나 비유한(NaN/inf) 값은 None 으로 둡니다. 문자열
  "None" 을 그대로 통과시키면 화면에 "None" 이 찍히므로 빈 값으로 취급합니다.
