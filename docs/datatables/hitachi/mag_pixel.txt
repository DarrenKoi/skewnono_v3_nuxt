1. 메커니즘 — SEM 배율은 렌즈 배율이 아닙니다
------------------------------------------------

SEM 은 빔을 시료 위의 사각 영역(FOV, field of view)에 raster 로 훑고, 그 신호를
**크기가 고정된 기준 화면**에 그립니다. 그래서

    Mag = 기준 화면 폭 / 시료 위 스캔 폭(FOV)

입니다. 배율을 올린다는 것은 빔이 훑는 영역을 좁힌다는 뜻이고, 화면 폭은 그대로
입니다. 이 정의에서 두 가지가 따라옵니다.

  - **픽셀 수는 FOV 를 바꾸지 않습니다.** 512 든 4096 이든 같은 배율이면 같은
    영역을 봅니다. 픽셀 수가 바꾸는 것은 그 영역을 몇 개의 샘플로 나누느냐
    (= 픽셀 하나가 덮는 nm)뿐입니다.
  - **경계 번짐은 nm 로 고정된 시료·빔 쪽 사실**(빔 직경 + 상호작용 부피 + 측벽
    기울기)이라 픽셀을 늘려도 물리적으로 얇아지지 않습니다. 늘어나는 것은 그
    고정된 폭 위에 얹히는 샘플 수입니다. `magPixel.ts` 의 경계 확대 뷰가 픽셀
    설정을 인자로 받지 않는 이유가 이것입니다(2026-07-26 에 `픽셀크기 × 1.5`
    로 그리던 거짓 그림을 걷어냈습니다).

기준 화면 — "13 cm SEM 모니터"
  Hitachi 배율의 기준 화면은 장비의 고정 크기 표시 화면(약 13 cm 폭의 SEM 모니터
  규격, user-described 2026-08-28)입니다. 계산에 쓰는 정확한 상수는
  **135 mm = 135,000 µm** 입니다(원본 mag-fov-pixel 표, 2026-07-25). 즉 1× 에서
  FOV 가 135 mm 이고, 배율 Mag 에서 FOV 는 135 mm / Mag 입니다.

  office 근거: recipe cond.txt 의 SEM 표본 1건이 Magnification `'30000'`,
  Field_Size `'4.499 um, 4.499 um'` 이었고 4.499 × 30000 = 134,970 입니다
  (office 확인 2026-07-30, `recipe_idp.txt` 참고). 135,000 과 0.02 % 차이이며
  소수 3자리 표기 절사로 보이지만, 상수가 정확히 135,000 인지 134,970 부근인지는
  **OFFICE-VERIFY** 입니다(표본 1건). 어느 쪽이든 nm/px 표기에는 차이가 없습니다.

  단위 주의: 원본 표는 135000 을 nm 로 적었으나 그러면 FOV 가 µm 로 나오지
  않습니다. **135,000 의 단위는 µm** 입니다(2026-07-25 정정).


2. 계산식
---------

    FOV_µm        = 135,000 / Mag
    FOV_nm        = FOV_µm × 1000
    PixelSize_nm  = FOV_nm / N_pixels          (N = 가로 픽셀 수)
    px/CD         = CD_nm / PixelSize_nm       (CD 하나에 얹히는 픽셀 수)
    ScanTime      ∝ N_x × N_y  → 512 기준 배수 = (N / 512)²

  - FOV 는 **폭**입니다. 비정사각 픽셀 설정이 오면 x(가로) 를 씁니다.
  - 512 → 1024 는 스캔 시간 4배, 2048 은 16배, 4096 은 64배입니다. 화면의
    "스캔 비용" 열이 이 제곱 규칙입니다.

  예 (CG, 512 px):
    | Mag     | FOV (µm) | 512 px (nm/px) | 1024 px | 2048 px | 4096 px |
    | ------- | -------- | -------------- | ------- | ------- | ------- |
    | 50,000  | 2.700    | 5.273          | 2.637   | 1.318   | 0.659   |
    | 100,000 | 1.350    | 2.637          | 1.318   | 0.659   | 0.330   |
    | 200,000 | 0.675    | 1.318          | 0.659   | 0.330   | 0.165   |
    | 500,000 | 0.270    | 0.527          | 0.264   | 0.132   | 0.066   |

  원본 datatable 의 컬럼: Mag, Fov, pixels (512, 1024, 2048, 4096).


3. 장비 상수 — 계열별 MAG 구간과 픽셀 설정
------------------------------------------

계열 판정은 모델코드 **접두사**(`CG…` / `GT…`)로 합니다 — `_tool_specs.py` 의
`model_to_tool_type()` 과 같은 방식입니다. `TOOL_SPECS.eqp_models` 목록으로
분류하면 목록에 없는 실장비가 조용히 사라집니다(2026-07-24 사고).

CG 계열 (대표 CG6300) — 23단, 전 구간 확인
  1000, 2000, 5000, 8000, 10000, 20000, 50000, 60000, 70000, 80000,
  100000, 120000, 150000, 180000, 200000, 220000, 250000, 300000,
  350000, 400000, 420000, 450000, 500000

GT 계열 (대표 GT2000) — CG 23단 + 500K 초과 5단 = 28단
  600000, 700000, 800000, 900000, 1000000 (100,000 단위, user-confirmed 2026-08-06)
  2026-08-06 이전 문서는 "확인 안되지만 100000 단위로 가정" 이었고 화면에 `가정`
  배지를 달았으나, 확정되어 배지와 assumed 플래그 인프라를 모두 걷어냈습니다.
  더 이상 CG 구간과 신뢰도가 다르지 않습니다.

픽셀 설정 — CG·GT 공통: 512, 1024, 2048, 4096
  실사용은 512 · 1024 가 대부분입니다. msr_file mock 의 `_PIXELS` 도 그 둘만
  냅니다. 관측된 값은 전부 정사각("512,512")이며 비정사각은 아직 본 적 없습니다
  (OFFICE-VERIFY).

배율 표기 규칙 — **항상 K 단위**, 1M 으로 접지 않습니다.
  GT 상단이 600K·700K·800K·900K 로 이어지므로 마지막만 1M 이 되면 같은 수열이
  두 이름으로 불립니다(user-confirmed 2026-08-16). 최저 배율이 1000 이라 K 미만
  구간은 없습니다. 화면 어디서든 `magLabel()` 하나만 씁니다 — 참조표 1000K 와
  캡션 1M 이 한 화면에서 어긋난 적이 있습니다(2026-08-16 수정).


4. 실데이터에서 배율·픽셀이 나타나는 자리
----------------------------------------

msr_file pickle (`msr_file_pickle.txt`)
  "meas_condition mag"   : 0, 250030, 250044 … — **정수, 그러나 표의 정격값이
                            아닙니다.** 250000 이 아니라 250030 처럼 실현된 값이
                            기록됩니다. 왜 정격에서 벗어나는지(보정 계수인지,
                            장비가 실제 달성한 값인지)는 OFFICE-VERIFY 입니다.
                            mock `_MAGNIFICATIONS = (200015, 250030, 250044)` 는
                            이 비정격 성질을 그대로 흉내 냅니다.
  "meas_condition pixel" : "0,0", "512,512" — 문자열, 공백 없는 `,` 구분.
  빈 row 센티널 : mag 0 / pixel "0,0". 135000/0 은 Infinity 이므로 코드는
                  **null 을 돌려주고 호출부가 게이팅**합니다(0 으로 강제 변환
                  금지 — `useMsrFileApi.ts` 의 cd_value 와 같은 규율).
  어댑터는 컬럼명을 소문자 + 공백→underscore 로 정규화합니다
  (`meas_condition_mag`, `meas_condition_pixel`).

recipe cond.txt (`recipe_idp.txt`, `read_meas_image_condition` /
`read_align_image_condition`)
  Magnification : `'30000'` — 단위 없는 **str** (SEM). OM 은 `'104'` 부근이며
                  recipe 마다 달라집니다(user-confirmed 2026-07-30).
  Field_Size    : `'4.499 um, 4.499 um'` — `', '` 구분 str. **OM 은 key 만 있고
                  값이 없습니다** — SEM 상수로 계산해 채우면 안 됩니다
                  (2026-07-30 이전 mock 이 `'1297.788 um'` 을 지어냈던 실수).
  Pixel         : `'512,512'` — 공백 없는 `,`. pickle 과 같은 표기.
  Magnification 과 Field_Size 는 **한 설정을 두 번 본 것**이므로 mock 은 곱
  (`_FOV_MAG_PRODUCT`)을 유지합니다. 이것은 mock 내부 일관성을 위한 선택이지
  사무실 규칙이 아니며, office adapter 는 이 상수를 쓰지 않습니다.

pickle FDC 컬럼 (`msr_file_pickle.txt` 의 df_ 컬럼 목록)
  MagnificationX / MagnificationY — 장비 FDC 텔레메트리의 배율 축별 값. 위의
  meas_condition mag 와는 다른 자리이며, 관계는 미확인(OFFICE-VERIFY).


5. 셋업 역산 규칙 (Mag/Pixel 가이드가 쓰는 도메인 규칙)
---------------------------------------------------

제약이 둘이고 반대 방향으로 당깁니다.
  ① FOV 제약  — 패턴 N개 + 여유 마진이 화면에 다 들어와야 함 → 배율 **상한**
  ② 픽셀 제약 — CD 하나에 픽셀이 충분히 얹혀야 측정됨      → 픽셀 **하한**
답은 한 점이 아니라 성립 구간이고, 추천은 그 구간의 한 점입니다.

  필요 FOV_nm = (패턴 수 × pitch_nm) / (1 − 2 × 마진비율)
    패턴이 가운데 놓이고 각 변에 마진이 필요하므로 패턴 몫은 (1 − 2r).
    마진 10 % 면 패턴은 FOV 의 80 %.
  추천 배율 = 필요 FOV 이상인 FOV 를 갖는 **가장 높은** 배율
    (높을수록 FOV 가 좁아 px/CD 가 커짐)
  추천 픽셀 = px/CD 기준을 넘는 **가장 작은** 설정
    (기준만 넘으면 더 키울 이유가 없고 스캔 시간만 제곱으로 늚)
  실제 마진 = (선택된 FOV − 패턴 span) / 2
    배율이 이산값이라 실제 마진은 요청 비율보다 대개 **넓습니다**. 그림·표·
    추천 패널은 요청값이 아니라 실제 span 에서 역산해 서로 어긋나지 않게 합니다.

상수와 근거
  - 여유 마진 프리셋 : 0 / 5 / 10 / 15 / 20 % (각 변 기준), 기본 10 %.
    배율이 이산값이라 자유 입력은 없는 정밀도를 시사하므로 프리셋만 둡니다.
  - 기본 패턴 수 : 8.
  - **최소 px/CD = 8 — 잠정값.** 사내 계측 기준이 아직 없습니다(user-confirmed
    2026-07-25). 화면에서 조정 가능하며, 기준이 정해지면
    `DEFAULT_MIN_PX_PER_CD` 상수 하나만 바꿉니다. 화면 문구는 "표준안"
    (2026-07-26 에 "사내 기준" 에서 정정 — 사내 기준이 아니기 때문).
  - pitch 미입력 시 CD × 2 (bar:space 1:1) 로 가정하고 화면에 밝힙니다.
  - **pitch > CD 는 엄격 부등식** (user-confirmed 2026-07-25): bar 가 자기가
    들어앉은 반복 단위보다 넓을 수 없고, pitch == CD 는 space 0 이라 line/space
    패턴으로 무의미합니다. 이 guard 는 완화하지 않습니다.
  - 경계 전이 폭 `SEM_EDGE_WIDTH_NM = 3` — **설명용 대표값**, 장비 실측 스펙이
    아닙니다. 화면에서도 대표값임을 밝힙니다.
