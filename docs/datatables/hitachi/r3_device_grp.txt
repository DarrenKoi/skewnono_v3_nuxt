R3, R4와 같은 R로 시작하는 팹을 눌렀을 때 불러와지는 Datatable

Column -> Type: Value 설명
모든 컬럼과 밸류는 string Type
(컬럼명은 아래 Office/Redis 섹션과 동일 — plan_catg_typ, den_typ 표기가 정식)
주의: 결측이 섞여 있습니다 — 실제 None/NaN 뿐 아니라 문자열 "None" 이
그대로 들어 있는 cell 도 있습니다. 어댑터는 둘 다 빈 값("")으로
정규화해야 합니다 (recipe_tat office adapter 의 _text 참고).

fac_id -> R3 (단일 value)
plan_catg_typ -> FULL, ADTPJT, MODULE, "" (플랜 카테고리 타입)
prod_catg_cd -> DRAM, Tech, Advanced, FLASH, NAND ()
tech_cd -> T1Z, S128, T1Y, C20, F12m, ""
den_typ -> 16G, 1T, 512G 등
prod_grp_typ -> DDR4, Memory Tech, Advanced, NAND, Raw NAND, HZBM2E, GDDR6, ""
gen_typ -> 2ND, 4TH, 1ST, 
lot_cd -> 3 or 4 Alphabets and Numbers, normally Starts with "R" like R7BU, RAEA, RAAJ
plan_grade_cd -> P1, P2, P3, P4, P5, ""
lake_load_tm -> datetime in string. yyyymmddhhmmss
ctn_desc -> 개발 디바이스에 대한 간략한 설명. **표준 포맷으로 통일 합의** (user-confirmed 2026-11-02, 곧 적용):
   "[(개발 phase) / (DRAM|NAND|기타)] (Tech 이름) (개발 phase) (Cell/Peri)"
   예: "[EV / DRAM] Cubit EV Cell&PEri", "[Pool제 / NAND] Petra PV Peri", "[TV / DRAM] Spica DPEX PV Peri",
       "[TV / 기타] SC-MRAM TV Cell&Peri", "[RTC / DRAM] VIRGO RTC Cell&PEri", "[요소기술 / NAND] SSL Cut Cell",
       "[EV / NAND] AI-N B EV Cell", "[TV / DRAM] PMG1.0 TV Peri"
   - 괄호 phase: EV / tEV / DTV / TTV / TV / PV / Pool제 / RTC / 요소기술 / Cubic …
   - 괄호 메모리: DRAM / NAND / 기타 (DRAM·NAND 모두 아닌 경우)
   - 본문 phase 가 괄호 phase 와 다를 수 있습니다(위 Spica 예시). 이유는 추후 설명 예정 — 룰은 괄호만 봅니다.
   - Tech 이름이 없으면 과제 설명을 씁니다("SSL Cut").
   - 꼬리: Cell / Peri / Cell&Peri (분리 안 할 때) / CellDummy / PeriDummy. 표기가 흔들립니다("Cell&PEri").
   계측 룰 축(family·phase·memory)은 괄호에서만 파생합니다(backend desc_format.py). 괄호가 없는 옛 포맷
   (예: "DRAM Pool제 (@Spica PV)")은 전환기 동안 섞여 있고, 룰 미정(Gray)으로 판정되며 칩은 "?" 입니다.
   OFFICE-VERIFY: 전환 속도, 괄호·슬래시가 반각인지.



========================================================================
사무실(Office) 실데이터 소스 — Redis
========================================================================

사무실에서는 이 R3/R&D 카탈로그가 Redis 에 pandas DataFrame 으로 저장됩니다.
device_desc 와 형태가 비슷하며 fac_id 는 항상 "R3" 입니다.

Key    -> "r3_device_grp" (DataFrame, parquet 직렬화)
          R3 연구개발(R&D) 카탈로그입니다. (user-confirmed 2026-07-31)
Column -> fac_id, plan_catg_typ, prod_catg_cd, tech_cd, den_typ,
          prod_grp_typ, gen_typ, lot_cd, plan_grade_cd, lake_load_tm, ctn_desc

정정 사항

- 두 카탈로그(device_desc, r3_device_grp)는 device-statistics 의 initial
  setup 카탈로그입니다. 화면 요청에 따라 여기서 device code 를 추출해
  사용합니다.
- tech_cd 와 device_desc 의 tech_nm 은 서로 다른 컬럼입니다. 이름이 비슷해
  혼용하기 쉬우나, 어댑터에서 alias 로 묶지 않습니다. (2026-07-30)

실제 컬럼/행 수/결측 분포는 사무실에서 아래로 확인합니다 (OFFICE-VERIFY):

    .venv/bin/python -m scripts.probes.inspect_device_info_keys

사용 방법

- recipe_tat 디바이스별 화면: lot_cd -> prod_catg_cd 로 R3/R&D device 의
  제품 카테고리를 채웁니다. (M fab device 는 device_desc.tech_nm,
  R3/R&D device 는 r3_device_grp.prod_catg_cd — device 당 둘 중 하나만
  채워짐.)
- device-statistics 기능에서도 이 DB 를 그대로 활용할 수 있습니다.

r3_device_grp 와 device_desc 의 겹침 (office 확인 2026-10-13)

device_desc 는 R3/R4 행도 담고 있어, 두 카탈로그의 lot_cd 교집합이 458 개
입니다. prod_catg_cd 는 r3_device_grp 에만 있으므로, 겹치는 lot 에서
device_desc 행을 우선하면 그 값이 ""로 지워집니다 (memory_class_auto 가
"unknown" 이 되어 계측 룰 셀이 미매칭). RX1A 는 원본 값이 "Advanced" 라
어느 쪽이든 unknown 이어서 드러나지 않았습니다.

device_statistics 어댑터의 규칙: device_desc 행의 fac_id 가 **R 계열** 이면
r3_device_grp 행이 남고(_yields_to_r3), 실제 M fab 이면 종전대로 M-fab 이
이깁니다 (user-confirmed 2026-08-10).
