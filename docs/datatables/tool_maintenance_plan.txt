사무실(Office) OpenSearch index — 장비 정비(BM/PM) 예정 작업 계획

BM/PM 중 "앞으로 할 일(future work)"을 담습니다. 실제 발생·수행 기록은
fab_inform_notes 이고, 이 index 는 그 계획 쪽입니다. 두 index 는 짝을 이루므로
화면에서 함께 다룰 때 어느 쪽이 계획이고 어느 쪽이 실적인지 구분해야 합니다.

Index -> tool_maintenance_plan (alias)
  backing index  : tool_maintenance_plan-000001
                   (rollover family tool_maintenance_plan-*)
  shards/replicas: 2 / 1
  rollover       : write index 가 1,000,000 docs 도달 시
  retention      : backing index 를 1095d(3년) 후 삭제
  setup script   : ops_index_mgmt/tool_maintenance_plan.py
  _id            : doc_id (bulk_index_dataframe(id_field="doc_id",
                   op_type="create"))

field 목록 (현재 ops mapping 기준, 7개)

  tool_start_tm  -> date : 작업 시작 시각.
  tool_end_tm    -> date : 작업 종료 시각.
  ll_dt          -> date : 미확인.
  limit_dt       -> date : 미확인(기한으로 추정되나 확인 필요).
  org_dt         -> date : 미확인(최초 계획일로 추정되나 확인 필요).
  chg_tm         -> date : 미확인(변경 시각으로 추정되나 확인 필요).
  work_item_nm   -> text : 작업 항목 이름. 엔지니어 서술이므로 nori analyzer +
                          .keyword subfield(ignore_above: 8192)로 mapping 되어
                          있습니다.

주의 — 현재 mapping 은 template 선언 field 뿐입니다

  위 7개는 ops_index_mgmt/tool_maintenance_plan.py 가 template 에 명시한 field 와
  정확히 같고, 그 외에는 아무것도 없습니다. dynamic mapping 은 문서가 들어올 때
  field 를 만들기 때문에, 이는 아직 이 index 에 적재가 이뤄지지 않았다는 신호로
  읽힙니다(비교: fab_inform_notes 는 적재 후 dynamic field 12개가 함께 보임).

  따라서 실제 column 집합은 아직 확정되지 않았습니다. 특히 다음이 없습니다.

    - eqp_id / fab_name : 장비·fab 조회 키. fab_inform_notes 는 이 둘로
      필터하므로, 계획과 실적을 같은 장비 기준으로 묶으려면 적재 dataframe 에
      반드시 있어야 합니다.
    - doc_id : _id 로 쓰이지만 field 로도 색인됩니다(fab_inform_notes 에는
      존재). 적재 시 자동으로 생깁니다.

  적재 후에는 mapping 을 다시 확인해서 이 문서를 갱신해야 합니다.

  새로 들어오는 ISO timestamp column 이 있으면 tool_maintenance_plan.py 의
  DATE_FIELDS 에 추가하고 재색인해야 date 로 잡힙니다 — dynamic date detection
  은 yyyy/MM/dd 계열만 인식하므로 그대로 두면 text 가 됩니다. 반대로 긴 서술형
  column 이 생기면 NOTE_FIELDS 에 넣어 nori + .keyword(8192) 를 받게 합니다.

조회 방법(적재 후 예상)

  기간 필터의 time_field 는 tool_start_tm(작업 시작 예정) 입니다.
  text field 의 정확 일치·집계에는 .keyword subfield 를 씁니다. dynamic 으로
  생기는 text 는 ignore_above 256, work_item_nm 만 8192 입니다.
