사무실(Office) Redis — SEM 장비 fleet 명부(roster)

전사 SEM 장비 목록입니다. 이 프로젝트에서 **가장 먼저 사무실에 연결된 소스**이며
(office 확인 2026-07-20), 장비 identity 의 단일 진실 원천입니다. storage,
lateral_recipe, sharpness 어댑터가 모두 여기로 eqp_id <-> eqp_ip 를 해결합니다.
각 feature 가 자기만의 명부를 들고 있으면 같은 fab 인데 화면마다 장비 수가 달라지고
어느 쪽이 맞는지 판별할 방법이 없으므로, 명부는 반드시 이 소스 하나만 씁니다.

저장 형태: Redis, pandas DataFrame 을 parquet 직렬화(df.to_parquet(), 값 선두
4바이트가 b"PAR1"). 세 개의 key 로 나뉘어 있습니다.

Key 1 -> "v3_df_sem_list"    : 전사 전체 명부. 모든 tool type 을 포함하며
                               VeritySEM 과 Provision 도 들어 있습니다.
                               (user-confirmed 2026-07-30)
Key 2 -> "v3_df_sem_avail"   : 위 명부 중 접속이 확인된 부분집합입니다.
                               version 컬럼이 **없습니다**.
Key 3 -> "v3_df_sem_version" : 컬럼 [eqp_ip, version] 두 개짜리 보조 table.

장비 lifecycle (user-confirmed 2026-07-30)

모든 장비는 fab 에 반입되는 시점에 eqp_ip 를 부여받고, 그 순간부터 네트워크
방화벽에 막혀 있습니다. IT 서비스팀이 해당 IP 를 열어 준 뒤에야
v3_df_sem_avail 에 들어옵니다. 따라서

    v3_df_sem_list - v3_df_sem_avail  =  방화벽 해제 요청 대기 목록

이며, "명부에 있으나 접속되지 않음"은 오류가 아니라 모든 장비가 반드시 한 번
거치는 정상 초기 상태입니다. GET /api/sem-list/pending 이 이 차집합을
eqp_id 기준으로 계산합니다.

v3_df_sem_list 는 스냅샷입니다 (user-confirmed 2026-07-30)

v3_df_sem_list 는 현재 fab 에 실제로 설치되어 네트워크에 연결되어 있는
장비의 **현재 스냅샷**입니다. 시간이 지나며 쌓이는 누적 이력이 아니므로,
폐기되거나 방치된 채 남아 있는 row 가 명부에 존재하지 않습니다. 따라서
v3_df_sem_list - v3_df_sem_avail 차집합에 있는 모든 row 는 반입 시점과
무관하게 전부 방화벽 해제가 필요한 대상입니다. 반입일이 오래되었다는 사실은
방화벽 요청이 필요한지 여부에 아무 신호도 주지 않으므로, 이 차집합에 반입일
기준 threshold 필터링(예: N 일 이상 경과 시 제외·흐리게 표시)을 적용하지
않습니다.

Key 2 와 Key 3 은 eqp_ip 를 기준으로 LEFT merge 합니다(fleet 이 왼쪽). fleet
row 는 한 건도 버리지 않으며, version 이 없는 row 는 빈 문자열("")이 됩니다.
version table 에 같은 eqp_ip 가 여러 건 있으면 fleet row 가 복제되므로, merge
전에 eqp_ip 기준으로 중복 제거(마지막 값 유지)합니다.

Key 1 의 정확한 컬럼 목록은 아직 확인되지 않았습니다(OFFICE-VERIFY). Key 2 와
같은 identity 컬럼을 가지며 available 컬럼이 없다고 가정하고 있습니다.
확인 방법:

    .venv/bin/python -m scripts.inspect_redis_key v3_df_sem_list

컬럼 정보 (merge 후 기준, 10개 전부 필수 — 하나라도 없으면 어댑터가 에러)

fac_id -> string: fab 대표 코드. 예: M11, M14, M15, M16, R3
eqp_id -> string: 장비 ID. 예: 6MCDE305, 4CCD6701
eqp_model_cd -> string: 장비 모델. 예: CG6300, CG6380, GT2000, TP4000
eqp_grp_id -> string: 장비 그룹 ID
vendor_nm -> string: vendor. HITACHI 또는 AMAT 두 값만 허용됩니다.
                     그 외 값이 오면 어댑터가 에러를 냅니다(조용히 넘기지 않음).
eqp_ip -> string: 장비 IP. 두 key 의 merge 기준이자 타 feature 의 join 기준입니다.
fab_name -> string: 화면에서 선택하는 세부 fab 이름. 예: M16A, M16B, R3, R4
                    fac_id 보다 granular 하며, 필터의 정식 키입니다.
updt_dt -> string(ISO): **장비가 fab 에 최초 반입된 시각**입니다.
                        명부 갱신 시각이 아닙니다 (user-confirmed 2026-07-30).
                        오래된 장비의 값은 정확하지 않으나 최근 장비의 값은
                        신뢰할 수 있습니다. 위 스냅샷 사실 때문에 신규 반입
                        여부를 판단하는 근거로는 더 이상 쓸 수 없습니다 —
                        미연결 장비 화면에서는 참고용 정보일 뿐이며 어떤
                        판단의 근거도 아닙니다. pandas Timestamp 로 오면
                        isoformat() 으로 변환합니다.
available -> string: 장비 사용 가능 여부. 소스는 on/off/true/false/1/0 중 아무
                     표기나 올 수 있고, 어댑터가 "On"/"Off" 로 정규화합니다.
                     정규화 불가 값이면 에러를 냅니다.
version -> string: 장비 SW version. 숫자와 문자가 섞인 자유 형식 문자열입니다
                   (예: "1A"). **숫자가 아니라 문자열입니다** — 비교·정렬 시
                   주의합니다. v3_df_sem_version 에서 붙습니다.

주의

1. version 은 별도 key 이므로, v3_df_sem_avail 만 읽으면 KeyError 가 납니다.
   두 key 를 함께 읽어 merge 하는 것까지가 이 소스의 계약입니다.
2. 텍스트가 bytes 로 돌아올 수 있습니다. str() 로 감싸면 "b'...'" 가 되어 한글이
   깨지므로 UTF-8 로 decode 합니다.
3. TP 계열(HV-SEM) 장비는 **HITACHI** 입니다. 홈 mock 데이터와 프론트 fixture
   일부에 AMAT 으로 적힌 곳이 있는데 그것은 잘못된 값입니다. 실데이터를 기준으로
   판단합니다.
4. tool_type(cd-sem / hv-sem)은 이 명부에 컬럼으로 없습니다. eqp_model_cd 로
   판별합니다 — CG/GT 계열은 cd-sem, TP 계열은 hv-sem
   (back_dev_home/ebeam/hitachi/_tool_specs.py 의 model_to_tool_type).
5. VeritySEM / Provision 은 v3_df_sem_list 에 포함됩니다
   (user-confirmed 2026-07-30). 백엔드 model_to_tool_type() 은 이 모델들에
   None 을 반환하지만 프론트 classifyToolType() 은 verity-sem / provision 으로
   해석합니다. 미연결 장비 화면은 프론트 분류기를 사용하므로 이 장비들도
   자기 필터 chip 아래에 표시됩니다.

연결 설정

REDIS_HOST / REDIS_PORT / REDIS_PASSWORD (back_dev_home/.env).
_runtime/office_redis.py 가 .env 를 self-load 하므로 어댑터에서 따로 읽지 않습니다.
