사무실(Office) Redis — fab 별 recipe 이름 목록

Recipe 검색 화면의 **검색 대상**입니다. 측정 이력(meas_hist)을 검색하는 것이 아니라,
이 목록의 recipe 이름 문자열만 검색합니다. 측정된 적 없는 recipe 도 목록에는 존재하기
때문입니다.

저장 형태: Redis **hash**, tool family 별로 하나씩.

Key -> "v3_cdsem_unique_rcp_list"  : CD-SEM
Key -> "v3_hvsem_unique_rcp_list"  : HV-SEM

hash field -> fab 이름의 **소문자** 표기. 예: "m14a", "m16b", "r3"
hash value -> 그 fab 의 recipe 이름 list

  {"m14a": ["1/AC_M2_TAT", "1/AC_M3_CD", ...], "r3": [...]}

주의

1. field 가 소문자입니다. 화면과 routes 는 대문자(M14A)를 쓰므로, 소문자 변환은
   Redis 경계(어댑터)에서만 일어나고 그 위 계층으로는 새어나가지 않습니다.
   응답은 호출자가 보낸 대문자 표기를 그대로 되돌려 줍니다.
2. value 의 직렬화 형식이 고정되어 있지 않습니다. 적재 job 에 따라 JSON
   (["a", "b"]) 일 수도 Python repr (['a', 'b']) 일 수도 있어 어댑터가 둘 다
   파싱합니다. 마지막 수단으로 콤마 분리도 시도합니다 — recipe 이름에는 "/" 와
   "_" 는 있어도 콤마는 없으므로 안전한 fallback 입니다.
3. recipe 이름은 "class/recipe" 형태를 포함합니다. meas_hist 의 full_name 과 같은
   체계입니다.

recipe 자세히 보기 / 비교는 이 소스가 아닙니다

Recipe 검색 결과에서 "자세히 보기"를 누르면 IDP 원본 구조가 필요합니다
(docs/datatables/recipe_idp.txt). 그 원본은 아직 사무실에서 준비되지 않아,
office 어댑터의 get_recipe_open_data / get_recipe_compare_data 는 mock 을 그대로
re-export 하고 있습니다. 비교(compare)는 열람(open)에서 파생되는 관계이므로
재구현하지 않고 re-export 하여 그 불변식을 유지합니다.

연결 설정

REDIS_HOST / REDIS_PORT / REDIS_PASSWORD (back_dev_home/.env).
