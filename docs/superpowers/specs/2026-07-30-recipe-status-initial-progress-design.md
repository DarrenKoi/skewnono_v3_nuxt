# Recipe 현황 초기 로딩 진행 표시 설계

- 날짜: 2026-07-30
- 상태: 승인됨
- 영역: `front-dev-home` Recipe 현황의 최초 백엔드 데이터 로딩

## 문제

Recipe TAT와 Fail 화면은 `useAsyncData`가 제공하는 pending 상태에 맞춰
로딩 패널을 가지고 있습니다. 그러나 두 화면의 setup에서
`useAsyncData`를 await하므로, 최초 진입 시에는 자식 컴포넌트 자체가
렌더링되기 전에 비동기 setup이 완료되기를 기다릴 수 있습니다. 이 경우
자식 내부의 로딩 패널은 최초 백엔드 대기 시간을 사용자에게 알리지
못합니다.

회사 백엔드 응답이 오래 걸리면 상단의 Recipe 현황 헤더와 탭 아래 영역이
바로 표시되지 않아 페이지가 멈춘 것처럼 보일 수 있습니다.

## 목표

Recipe 현황의 최초 데이터 요청이 완료될 때까지 Nuxt UI의 진행
컴포넌트를 표시합니다. 사용자는 현재 탭과 페이지 맥락을 계속 확인하면서
데이터를 불러오는 중임을 명확히 알 수 있어야 합니다.

이번 변경에서 만드는 로딩 표현은 다른 느린 페이지에서도 재사용할 수
있는 공용 컴포넌트로 구성하되, 실제 적용 범위는 Recipe 현황으로
제한합니다.

## 선택한 설계

`RecipeStatusView.vue`의 Recipe TAT / Align Fail / Meas Fail 자식 영역을
Vue `Suspense`로 감쌉니다. 기존 Recipe 현황 `EbeamMetaBar`와 세 탭은
`Suspense` 바깥에 유지합니다.

활성 자식 화면의 비동기 setup이 완료되지 않은 동안 `Suspense`의 fallback
slot에서 공용 로딩 컴포넌트를 표시합니다. 따라서 진행 표시는 브라우저
상단의 전역 표시가 아니라, Recipe 현황 헤더와 탭 바로 아래에서 실제
대시보드가 표시될 자리를 차지합니다.

```text
┌ Recipe 현황                  [TAT] [Align] [Meas] ┐
└──────────────────────────────────────────────────┘

┌ 로딩 패널 ───────────────────────────────────────┐
│  ━━━━━━━ 움직이는 UProgress bar ━━━━━━━━━━━━━   │
│       Recipe 현황 데이터를 불러오는 중입니다.       │
└──────────────────────────────────────────────────┘
```

Vue가 두 built-in 컴포넌트를 함께 사용할 때 권장하는 순서에 따라
`KeepAlive`가 `Suspense`를 감쌉니다. `Suspense`에는 `timeout="0"`을
지정하여 아직 로드하지 않은 탭으로 전환할 때 이전 탭 콘텐츠를 남기지
않고 로딩 패널을 즉시 표시합니다. 탭 전환 시 이미 로드한 화면의 필터,
표 상태, 응답 데이터를 보존하는 현재 동작은 변경하지 않습니다.

## 공용 로딩 컴포넌트

공용 컴포넌트는 `front-dev-home/app/components/AppLoadingState.vue`에
둡니다. 자동 import 이름은 `AppLoadingState`입니다.

컴포넌트는 다음 책임만 가집니다.

- 기존 `dashboard-surface` 스타일을 사용하는 독립된 로딩 패널을
  렌더링합니다.
- 호출자가 전달한 제목과 선택적 설명을 표시합니다.
- Nuxt UI `UProgress`를 indeterminate 상태로 렌더링합니다.
- `animation="carousel"`을 사용해 요청이 진행 중임을 보여줍니다.
- `role="status"`와 `aria-live="polite"`를 제공해 보조 기술에도 로딩
  상태를 전달합니다.

백엔드가 완료 비율을 제공하지 않으므로 가짜 퍼센트나 예상 남은 시간을
표시하지 않습니다. `UProgress`에는 숫자 값을 전달하지 않고 indeterminate
애니메이션만 사용합니다.

Recipe 현황에서는 제목으로
`Recipe 현황 데이터를 불러오는 중입니다.`를 사용합니다. 설명은 최초
적용에서 생략하여 패널을 간결하게 유지합니다.

## 상태 흐름

최초 Recipe 현황 진입 시의 흐름은 다음과 같습니다.

1. Recipe 현황 헤더와 현재 선택된 탭을 즉시 표시합니다.
2. 활성 자식 화면이 백엔드 요청을 시작합니다.
3. 비동기 setup이 대기 중이면 해당 자식 대신 공용 로딩 패널을
   표시합니다.
4. 요청과 setup이 완료되면 fallback을 제거하고 기존 대시보드를
   표시합니다.
5. 이후 방문 중 같은 탭으로 돌아오면 `KeepAlive`가 보존한 화면을
   재사용합니다.

날짜 범위나 디바이스 필터 변경처럼 자식 화면이 이미 렌더링된 뒤 발생하는
재요청에는 `Suspense` fallback을 사용하지 않습니다. 이 구간은 각 자식의
기존 pending 처리와 이전 응답 마스킹 정책을 유지합니다. 이번 변경은
최초 화면 표시가 지연되는 문제만 다룹니다.

## 오류와 경계 상태

진행 표시는 요청 성공을 가정하거나 완료 시간을 추정하지 않습니다.
비동기 요청의 오류 처리와 빈 결과 처리는 기존 자식 화면과 Nuxt 오류
경계를 그대로 사용합니다. 별도의 timeout, 자동 retry, 오류 토스트는
추가하지 않습니다.

탭을 빠르게 전환할 때 새 탭의 자식 화면이 아직 로드되지 않았다면 같은
fallback 위치에서 로딩 패널을 표시합니다. 이미 `KeepAlive`에 보존된
탭에는 로딩 패널을 다시 표시하지 않습니다.

## 검증

이 저장소에는 Vue 컴포넌트 mounting test harness가 없으므로
`AppLoadingState.vue` 자체를 위한 새 단위 테스트는 추가하지 않습니다.
구현 후 다음 검증을 수행합니다.

- `npm test`로 기존 frontend 순수 함수 테스트를 실행합니다.
- `npm run lint`로 Vue 템플릿과 TypeScript lint를 확인합니다.
- `npm run typecheck`로 `Suspense`, `KeepAlive`, `UProgress` 사용과
  컴포넌트 props를 확인합니다.
- `git diff --check`로 공백 오류를 확인합니다.
- 실행 중인 앱에서 Recipe 현황의 최초 응답을 의도적으로 지연시키고,
  헤더와 탭은 보이면서 바로 아래에 로딩 패널이 표시되는지 확인합니다.
- TAT, Align, Meas 각 탭의 최초 로딩과 이미 로드한 탭으로 돌아갈 때의
  `KeepAlive` 동작을 확인합니다.
- 밝은 테마와 어두운 테마에서 패널과 진행 표시의 대비를 확인합니다.

## 범위 제한

- 이번 변경에서 다른 frontend 페이지에 공용 로딩 컴포넌트를 적용하지
  않습니다.
- 전역 `NuxtLoadingIndicator`를 추가하거나 변경하지 않습니다.
- Recipe 현황 API, 캐시 key, `useAsyncData` 요청 병렬화와 응답 형태를
  변경하지 않습니다.
- 최초 로딩 속도를 개선하거나 백엔드 작업량을 줄이는 최적화는 포함하지
  않습니다.
- 진행률 퍼센트, 남은 시간, timeout, retry 기능을 추가하지 않습니다.
