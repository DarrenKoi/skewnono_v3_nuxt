# 장비간 스큐(Tool-to-Tool Skew) 관리 방법론 설계

- 작성일: 2026-05-31
- 대상: CD-SEM 함대(fleet), 팹(fab) 단위
- 원천 이슈: `docs/issues/hardware_mgmt/skew_btw_tools.txt`
- 관련 방법론: `docs/issues/smart_sampling/smart_sampling_methodology.md` (앵커+borrow-strength·신뢰도 라벨 철학 동형)

## 1. 목적과 북극성

이 방법론은 측정 장비 간 스큐를 **모니터링·관리·개선**하기 위한 것입니다. 최종
산출물(북극성)은 다음 한 문장으로 요약됩니다.

> 어떤 Recipe(=어떤 CD 대역·빔 조건)를 측정할 때, 장비 스큐가 결과를 오염시키지
> 않는(즉 Wafer 본연의 산포만 드러나는) **측정 장비 조합**은 무엇인가를 데이터로
> 도출하고, 공정팀 문의나 대시보드에서 **측정 장비 추천**으로 즉답한다.

이 추천이 서기 위해 세 층을 순서대로 세웁니다. (C) 스큐를 일관된 지표로
**정량화**하고, (A) 대역·조건별로 **어떤 장비끼리 스큐가 작은지** 검증 가능하게
만들며, (B) 이를 **시계열로 관제**합니다.

MDC(Measure Data Correction)는 한 장비에서 측정하는 모든 샘플 결과에 영향을 주는
고위험 노브이며, 보통 연 1~2회 PM(H/W 조정 동반) 때만 변경됩니다. 따라서 스큐
관리의 주 레버는 "MDC 재조정"이 아니라 **이미 잘 맞는 장비 조합으로 측정을
라우팅**하는 것입니다. (PM 시점의 MDC·CD_MONITORING 목표값 사전 산출은 같은 코어를
공유하는 **별도 후속 spec**으로 분리합니다 — 본 문서 범위 밖.)

## 2. 핵심 불변식

- **셀(cell) 단위 추론.** 모든 통계의 최소 단위는
  `(beam_condition × scan_axis[X/Y] × cd_band × mdc_epoch)` 셀입니다.
- **팹 스코프 · 교차 금지.** consensus·스큐 행렬·군집·epoch은 항상 한 팹 내부에서만
  계산합니다. 개발 팹(예: R3)과 양산 팹(예: M11·M14·M16)은 절대 섞지 않습니다.
- **양팹 공용.** 엔진과 계약은 두 팹 모두에서 동일하게 동작합니다. 팹 간 차이는
  코드 분기가 아니라 **tier별 데이터 밀도 차이**로만 나타나며, 신뢰도 라벨이 이를
  투명하게 드러냅니다.
- **데이터 신뢰 등급 혼합 금지.** 아래 3등급 신호는 절대 한 점수로 합치지 않습니다.
- **MDC 변경은 epoch 경계.** epoch을 넘는 비교는 명시적으로만 허용합니다.

## 3. 코어 — 스큐 정량화 엔진

### 3.1 측정 신호 3등급 (혼합 금지)

| 등급 | 신호 | 성격 | 가용성 |
| --- | --- | --- | --- |
| 직접 | 라운드로빈(같은 Wafer 다수 장비) — CD_MONITORING 전장비 매일 + MI 샘플 3~4종 | 순수 장비 스큐 | X/Y·제한 대역 |
| 프록시 | MDC 값 유사도 + BSM(빔 형상 radar) 유사도 | 직접 없는 셀의 예측 근거 | 항상 / PM 시점 |
| 방증 | 양산(같은 공정·다른 Wafer) 분포 중첩 | Wafer·장비 스큐 교란 | 풍부하나 참고용 |

직접 신호만이 추천의 1차 근거입니다. 프록시는 직접 데이터가 없는 셀의 **예측**
근거이고, 방증은 군집에 반영하지 않는 **참고 신호**입니다.

### 3.2 지표 파이프라인 (셀 내부)

1. **C-정규화** — 그날 fleet consensus(로버스트 중앙값)를 구하고, 각 장비 잔차
   `residual = tool − consensus` 를 계산합니다.
2. **skew 지표** — 장비의 셀 skew = 잔차의 계통 평균(nm). 장비쌍 skew =
   `|skew_i − skew_j|`. (용어는 "skew"로 통일하며 "bias"는 쓰지 않습니다.)
3. **epoch 스코프** — MDC 변경(BM/PM)이 epoch 경계이며, 모든 통계는 현재 epoch
   내에서만 계산합니다. epoch 경계에서 baseline을 리셋합니다.
4. **안정성(보조)** — epoch 내 skew의 시간 분산을 "흔들리는 장비" 건강 플래그로
   둡니다(추천 점수엔 미반영).

### 3.3 군집화

군집화는 **서버가 아니라 클라이언트**에서 수행합니다. 엔진은 raw 장비쌍 skew
행렬과 현재 tolerance만 내려주고, UI가 tolerance로 절단해 상호 연결된 장비를
그룹으로 묶습니다. tolerance는 **엔지니어 knob(조절 가능) + 기본값(우리가 지정)**
이므로, knob을 돌릴 때 재요청 없이 즉시 군집을 다시 그립니다.

## 4. 추천 (2-tier) 과 finder

### 4.1 데이터 계보

finder는 **`meas_hist`를 추적 기점**으로 삼습니다. `msr` 파일에 계측값이, `idp`
파일에 계측 빔 조건이 있으므로, 한 Recipe가 점유하는 셀 집합
`{(beam_condition × axis × cd_band)}` 를 측정 이력에서 도출할 수 있습니다. cd_band는
실측 CD 분포로 추정합니다(recipe 메타에 nominal CD가 없을 수 있으므로).

### 4.2 흐름

1. 공정팀이 Recipe(또는 oper/layer) 입력.
2. `meas_hist`로 점유 셀 집합 도출.
3. 각 셀에서 군집 근거 산출:
   - **직접 tier** — 셀에 라운드로빈 데이터 있음 → 실측 장비쌍 skew, 신뢰도
     `High·직접`.
   - **예측 tier** — 없음 → MDC·BSM 유사도로 예측 skew, 신뢰도 `예측·Low/Med`,
     "대역/각 외삽" 라벨.
4. **셀 교집합** — 모든 셀을 동시에 만족하는 장비 그룹을 1차 답으로 제시하고, "셀별
   펼쳐 보기"를 드릴다운으로 둡니다.
5. 그룹은 **최약 신뢰도를 상속**합니다(직접+예측 혼합 시 그룹 신뢰도 = 예측).

### 4.3 특수각과 방증

- **특수각(예 32·64·218도):** X/Y 코일 복합 작용의 물리적 해석이 미검증이므로 v1은
  1급 차원에서 제외합니다. Recipe가 특수각을 포함하면 "특수각 포함 — X/Y+MDC+BSM
  유사도 기반 *예측만 가능*" 플래그를 답니다. 특수각 전용 Wafer 검증 트랙은 데이터
  모델에 자리만 예약하고(수집·표시는 deferred), 가설 "X/Y 스큐 작고 + MDC 유사 +
  BSM 유사 → 특수각도 저스큐"를 *나중에 검증*합니다.
- **방증(양산):** 추천 옆에 "양산 분포 정합도"를 참고 신호로 표시만 하고 군집엔
  반영하지 않습니다.

## 5. 대시보드

경로 `/ebeam/cd-sem/[fab]/skew-check` 의 단일 대시보드(팹 스코프), 위에서 아래로 구성합니다.
헤더는 기존 `EbeamMetaBar` 패턴을 따릅니다.

1. **측정 장비 추천 finder** — 군집(cluster) 1차 답 + 장비쌍 행렬(heatmap) 근거
   드릴다운 + tolerance knob.
2. **오늘 함대 skew 현황** — 장비쌍 행렬 + consensus 편차.
3. **트렌드 & epoch** — 장비별 skew 시계열, BM/PM 마커에서 baseline 리셋.
4. **MDC 이력** — 빔 조건 × 축별 MDC 변경 타임라인.

## 6. API 계약 & swap surface (Phase-1 ↔ office)

- 신규 피처 폴더 `back_dev_home/ebeam/<...>/skew/` 에 `routes.py` + `data.py` +
  `contracts.py` + `__fixtures__/` 를 두며, 기존 hitachi 피처 패턴을 그대로 따릅니다.
- 계약은 3-tier 구조를 그대로 노출합니다: 셀별 `direct_skew_matrix`(nullable),
  `predicted_skew_matrix` + `confidence`, `production_corroboration`(참고),
  `current_tolerance`(기본값), `epoch_markers`, `mdc_history`.
- **BSM·MDC는 기존 hardware 피처 데이터를 입력으로 재사용**합니다(중복 생성 금지).
  계약으로 연결합니다.
- 군집화에 필요한 raw skew만 내려보내고, 군집 계산은 클라이언트가 수행합니다.
- Phase-1은 mock 출력 + 계약 + UX만 증명합니다. 실제 통계 구현은 office에서
  `data.py` 스왑으로 교체하며, "추천이 옳다"는 검증은 office 실데이터로 별도
  수행합니다(Phase-1이 증명하는 것은 계약·UX뿐).

## 7. 범위 경계

### 7.1 v1 포함

- 코어 엔진(skew 지표 · 3-tier 신호 · epoch 스코프).
- finder(셀 교집합 추천, 2-tier 신뢰도).
- 대시보드 4섹션, **X/Y 축만**, 양팹 공용.

### 7.2 Deferred (후속 spec)

- 특수각 전용 Wafer 수집·검증(자리만 예약).
- 스큐 = f(CD 크기) 회귀 모델(office 데이터 충분 시 예측 tier 승급).
- 패턴/uniformity 성분 분리(현재는 오프셋 skew만; uniformity는 smart_sampling 책임).
- 응용 ②: PM MDC·CD_MONITORING 목표값 사전 산출(별도 spec, 같은 코어 공유).
- 알람 발송 채널.

### 7.3 열린 결정

- tolerance 기본값 수치.
- 군집 연결 규칙(완전연결 vs 단일연결).
- cd_band bin 경계 정의.
- 방증(양산) 신호의 표시 방식.

## 8. 고려된 대안

| 접근 | 내용 | 판정 |
| --- | --- | --- |
| 전이가정 단일 엔진 | 16nm 앵커 군집을 전 대역·전 조건에 그대로 적용 | 기각 — 문서의 미검증 가정 그 자체, 정직성 위반 |
| 합성 점수 단일 랭킹 | 직접+MDC+BSM+양산을 가중합한 한 숫자로 순위 | 기각 — 미검증 가중치를 엔진에 박고 교란 데이터를 황금과 혼합 |
| 골든 장비 대비 | 한 대를 황금 기준으로 나머지 편차 측정 | 기각 — 특정 장비 신성화 리스크, 조합 추천과 간접적 |
| 셀 기반 2-tier 엔진 | consensus 정규화·skew 기준·epoch 스코프, 직접 군집 / 예측 폴백 + 신뢰도 | **채택** |

## 9. 되돌리기 어려운 이유

이 방법론은 **엔진 출력 계약과 backend 데이터 접근 형태**를 결정합니다. 3-tier
신호 분리(직접/예측/방증)와 셀 단위 구조가 한 번 mock·office 양쪽과 Nuxt 페이지에
자리 잡으면, 단일 점수로 합치거나 팹 교차를 허용하는 방향으로 되돌리는 일은
계약·UI·backend를 함께 갈아엎는 비용을 부릅니다. 특히 "직접 vs 예측을 절대 섞지
않는다"는 원칙은 맥락 없이는 과해 보이므로 — 왜 한 숫자로 안 합치는가 — 그 근거(미검증
가정을 사실처럼 쓰지 않기 위함)를 여기 명시해 둡니다.
