# 라이브 알람 보드 — 종류 필터 + 측정 실패 그룹핑 설계

작성일: 2026-08-03
대상: `front-dev-home` 라이브 알람 보드 (cd-sem / hv-sem)

## 1. 배경과 문제

현재 라이브 알람 보드는 최근 10분간 발생한 Align 실패와 측정 실패를
하나의 시간순 목록으로 보여줍니다. 알람 한 건은 한 줄이고, 그 이상의 구조는
없습니다.

이 형태에서 드러나지 않는 사실이 하나 있습니다. **같은 장비의 같은 PPID가
반복해서 측정 실패를 내고 있다**는 상황입니다. 시간순 목록에서 이 패턴은
서로 떨어진 여러 줄로 흩어지고, 보는 사람이 머릿속에서 다시 묶어야만
보입니다. 실제로 조치가 필요한 것은 개별 알람이 아니라 그 PPID이므로,
화면이 그 단위를 직접 보여주어야 합니다.

Align 실패는 성격이 다릅니다. lot 하나가 정렬에 실패한 사건이고, 대응
단위도 개별 lot입니다. 따라서 두 종류를 같은 모양으로 묶는 것은 맞지
않습니다.

## 2. 범위

**프런트엔드 전용 변경입니다.** 백엔드, 컨트랙트, 응답 페이로드는 건드리지
않습니다.

이 결정의 근거는 다음과 같습니다. 서버는 폴링마다 10분치 보드 전체를
보내고, 클라이언트의 `applyPoll`은 병합이 아니라 **치환**합니다. 따라서
그룹핑은 기존 `events` 배열 위에서 계산되는 파생 뷰이며, 누적 상태를
새로 만들 필요가 없습니다.

보드의 시간 지평은 그대로 10분입니다 (`BOARD_WINDOW_SEC = 600`).
이 화면은 **실시간 트리아지 보드**이지 장기 집계 뷰가 아닙니다. 건수는
"지금 이 순간 이 PPID가 터지고 있다"는 라이브 신호로 읽혀야 하며,
교대 단위 누적치가 아닙니다. 더 긴 지평의 집계가 필요해지면 그것은 별도
엔드포인트를 가진 별도 화면이며, 이 설계의 대상이 아닙니다.

## 3. 종류 필터

보드 상단, `EbeamMetaBar` 아래이자 목록 위에 3분기 세그먼티드 컨트롤을
둡니다.

```text
[ 전부 보기 ] [ Align Fail만 ] [ 측정 실패만 ]
```

### 3.1 위젯

NuxtUI 4.10 레지스트리에는 `UButtonGroup`이 없습니다. 이 저장소가 같은
컨트롤에 대해 이미 쓰고 있는 방식은 네이티브 버튼으로 만든
`role="tablist"` + roving tabindex이며, 선례는
`app/components/ebeam/skewvoir/views/TimeSeries.vue`와
`app/components/ebeam/skewvoir/fdc/SequenceWorkbench.vue`입니다. 같은
패턴을 따릅니다.

색은 `--sk-chip-bg`, `--sk-surface`, `--sk-ink`, `--sk-ink-muted` 토큰만
사용합니다. 인라인 hex는 쓰지 않습니다.

### 3.2 상태

`useLiveAlarmFilter()` 컴포저블이 `usePersistedState`로 선택을
보존합니다.

| 항목 | 값 |
| --- | --- |
| stateKey | `live-alarm:filter` |
| storageKey | `skewnono:live-alarm.filter` |
| default | `'all'` |
| isEmpty | `value => value === 'all'` |

키는 **하나**이며 fab과 tool을 가로질러 공유됩니다. 사용자는 오늘 align
트리아지를 하거나 PPID 트리아지를 하는 것이지, fab마다 다른 모드를 원하는
것이 아니기 때문입니다.

`isEmpty`를 기본값에 맞춰 둔 이유는 기본 상태가 localStorage에 남지 않게
하기 위함입니다. `usePersistedState`는 비어 있다고 판정된 값의 키를
제거합니다.

### 3.3 헤더 통계는 필터의 영향을 받지 않습니다

`EbeamMetaBar`의 `Align Fail` / `측정 실패` / `관련 lot` 세 숫자는 필터와
무관하게 **항상 보드 전체**를 셉니다.

필터가 이 숫자까지 좁히면, 측정 실패만 보는 동안 align 실패가 존재한다는
사실 자체가 화면에서 사라집니다. 필터는 무엇을 보고 있는지를 바꾸는
것이지, 무엇이 일어나고 있는지를 바꾸는 것이 아닙니다.

## 4. 세 가지 모드

| 모드 | 렌더링 |
| --- | --- |
| `all` | 현재와 동일한 시간순 평면 목록. align과 meas가 섞입니다. **변경 없음.** |
| `align` | align 알람만의 시간순 평면 목록. |
| `meas` | `(eqp_id, ppid)` 기준 그룹 목록. |

`all`이 기본값이며 오늘의 동작을 그대로 유지합니다. 그룹핑은 `meas`
모드에서만 나타납니다.

## 5. 측정 실패 그룹 뷰

### 5.1 그룹의 정체성

그룹 하나는 `(eqp_id, ppid)` 한 쌍이며 키는 `` `${eqp_id}|${ppid}` `` 입니다.

키가 배열 인덱스가 아니라 값에서 파생되어야 하는 이유는 폴링 때문입니다.
15초마다 `applyPoll`이 배열 전체를 치환하므로, 위치 기반 키를 쓰면 펼침·접힘
상태가 매 폴링마다 초기화됩니다.

### 5.2 정렬

1차 기준은 **건수 내림차순**, 동수일 때 2차 기준은 **최근 발생 시각
내림차순**입니다. 가장 심한 것이 첫 줄에 옵니다.

### 5.3 헤더 (접힌 상태)

```text
TP-0142 · RECIPE_ABC        7건    2분 전    관련 lot 3
```

건수가 이 화면의 핵심 신호이므로 시각적으로 가장 강하게 표시합니다.

### 5.4 특수 케이스

- **1건 그룹**은 헤더도 chevron도 없이 기존 `AlarmRow` 한 줄로 그대로
  렌더링합니다. 한 줄을 감싸는 그룹 헤더는 정보가 아니라 잡음입니다.
- **`ppid`가 빈 문자열인 알람**은 버리지 않고 `(PPID 없음)` 그룹으로
  묶습니다. 서버는 없는 값을 `""`로 보내므로 빈 값은 부재가 아니라 하나의
  값입니다.

### 5.5 펼친 상태

기존 `AlarmRow` 컴포넌트를 그대로 사용하며, 그룹 안에서는 최신순으로
나열합니다. `AlarmRow.vue`는 **수정하지 않습니다** — 레시피 링크,
AL_TEXT, 상세 줄이 모두 그대로 유지됩니다.

### 5.6 신규 알람 신호

접힌 그룹 안으로 새 알람이 들어오면, 그 그룹 **헤더**가
`--sk-accent-tint` 강조를 8초간 받고 건수가 올라갑니다.

기존 `highlightIds` 메커니즘은 개별 행을 강조합니다. 그룹이 접혀 있으면 그
강조는 보이지 않는 DOM에서 일어나고, 신호가 가장 필요한 순간에 사라집니다.
따라서 강조를 한 단계 위로 올립니다. 그룹의 이벤트 중 하나라도
`highlightSet`에 있으면 헤더가 강조됩니다.

**자동 펼침은 하지 않습니다.** 사용자가 의도적으로 접은 그룹이 스스로
열리는 것은 사용자와 싸우는 동작이고, 바쁜 fab에서는 화면이 계속
흔들립니다.

## 6. 파일별 변경

| 파일 | 변경 |
| --- | --- |
| `app/utils/liveAlarm.ts` | `AlarmFilter` 타입, `filterEvents()`, `groupMeasEvents()` 추가. 순수 함수이며 시계에 의존하지 않습니다. |
| `app/utils/liveAlarm.test.ts` | 정렬 순서, 1건 그룹 통과, 빈 ppid 버킷, `all` 모드의 항등성 테스트 추가. |
| `app/composables/useLiveAlarmFilter.ts` | 신규. 약 15줄. |
| `app/components/live-alarm/MeasGroup.vue` | 신규. 헤더 + 접기 + `AlarmRow` 슬롯. |
| `app/components/ebeam/LiveAlarmView.vue` | tablist, 모드 분기, 모드별 빈 상태. |
| `app/components/live-alarm/AlarmRow.vue` | **변경 없음.** |

### 6.1 경계

로직의 무게중심은 `liveAlarm.ts`의 순수 함수에 둡니다. 이 프로젝트에는
컴포넌트 마운팅 테스트 하네스가 없으므로, 테스트 가능한 코드는 곧
`node --test`로 돌릴 수 있는 순수 함수를 뜻합니다. `groupMeasEvents()`는
이벤트 배열을 받아 정렬된 그룹 배열을 반환하며, Vue에도 시계에도
의존하지 않습니다.

`MeasGroup.vue`는 계산하지 않고 표시만 합니다. 펼침·접힘 여부만이 그
컴포넌트가 소유하는 유일한 상태입니다.

## 7. 빈 상태

모드마다 다른 문구를 씁니다. "이 팹은 조용하다"와 "이 필터에 해당하는
것이 없다"는 서로 다른 사실이기 때문입니다.

| 모드 | 문구 |
| --- | --- |
| `all` | `최근 10분간 알람이 없습니다.` (현행 유지) |
| `align` | `최근 10분간 Align 실패가 없습니다.` |
| `meas` | `최근 10분간 측정 실패가 없습니다.` |

`feed_status === 'not_configured'`인 경우의 문구는 필터보다 우선하며 현행을
유지합니다. 수집 대상이 아닌 팹에서는 어떤 필터를 골라도 같은 사실이기
때문입니다.

## 8. 검증

| 단계 | 명령 |
| --- | --- |
| 순수 함수 | `npm test` |
| 타입 | `npm run typecheck` |
| 린트 | `npm run lint` |
| 문서 | `npm run lint:md` (저장소 루트) |

브라우저 검증은 Playwright MCP로 직접 수행합니다
(`/ebeam/cd-sem/<fab>/live-alarm`, `/ebeam/hv-sem/<fab>/live-alarm`).
확인 항목:

1. 세 모드가 각각 올바른 목록을 렌더링한다.
2. 그룹이 건수 내림차순으로 정렬된다.
3. 펼침·접힘이 동작하고, **폴링 1회를 지나도 상태가 유지된다**.
4. 헤더 통계가 필터와 무관하게 보드 전체를 센다.
5. 필터 선택이 새로고침 후에도 유지된다.
6. 키보드로 tablist를 좌우 화살표로 이동할 수 있다.

스크린샷은 `.playwright-mcp/screenshots/` 아래에 저장합니다.

## 9. 명시적으로 하지 않는 것

- 보드 시간 지평 확장 — 10분을 유지합니다.
- PPID 단위 장기 집계 엔드포인트 — 별도 화면의 몫입니다.
- `AlarmRow.vue` 재설계.
- align 알람 그룹핑 — align은 개별 lot 단위 사건입니다.
- fab·tool별 필터 기억 — 키 하나를 공유합니다.
