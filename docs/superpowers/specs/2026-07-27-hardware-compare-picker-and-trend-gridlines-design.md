# Hardware 비교 장비 선택기 전체 선택·해제 및 시계열 가로 눈금선 제거

- 날짜: 2026-07-27
- 상태: 승인됨

## 문제

Hardware 페이지에서 두 가지 문제를 확인하였습니다. 사무실에서 MDC office
어댑터를 연결하여 실제 데이터를 확인하는 과정에서 드러난 문제입니다.

첫째, `장비 ID 검색` 드롭다운에 전체 선택·해제 수단이 없습니다. 현재
`전체`·`해제` 버튼은 드롭다운 바깥의 바 우측 끝에 있으며 검색어를 전혀
반영하지 않습니다. 따라서 fab 장비 수가 많을 때 특정 계열만 골라 한 번에
선택할 수 없습니다.

둘째, 시계열 차트의 가로 눈금선이 데이터 판독을 방해합니다. Hardware
파라미터는 대부분 안정적이므로 y축이 좁은 범위로 잡히며, 이때 배경의 곧은
가로선이 거의 평평한 계열과 섞여 데이터로 오인됩니다. MDC는 `tightYRange`가
±0.55% 드리프트 대역을 의도적으로 좁게 잡으므로 특히 심합니다.

## 선택한 설계

### 1. 검색어를 반영하는 전체 선택·해제

`CompareToolPicker.vue` 한 파일만 수정합니다. 이 컴포넌트는 `MdcPanel`과
`ScePanel`이 `hw-compare-tools` 상태 하나를 공유하며 함께 사용하므로 수정이
두 패널에 동시에 반영됩니다.

필터링 주체를 `USelectMenu`에서 부모 컴포넌트로 옮깁니다.

| 항목 | 설정 |
| --- | --- |
| 검색어 | `v-model:search-term="searchTerm"` |
| 내부 필터 | `ignore-filter`로 비활성화 |
| 목록 | `:items="filteredItems"` (직접 계산) |

이 구조에서는 필터가 하나뿐이므로 화면에 보이는 목록과 `전체 선택`이
선택하는 집합이 원리적으로 어긋날 수 없습니다. Nuxt UI의 `useFilter`는
공개 자동 임포트 대상이 아니어서 `dist/runtime` 내부 경로를 직접 참조해야
하며, 이는 버전 업그레이드에 취약하므로 선택하지 않습니다.

필터 함수는 순수 함수로 분리하여 `app/utils/hardwareCompare.ts`에 추가합니다.
이 파일은 이미 MDC/SCE 비교 선택기 전용 공유 헬퍼 모듈이므로 새 파일을
만들지 않습니다.

```ts
export const filterToolIds = (ids: readonly string[], term: string): string[]
```

대소문자를 구분하지 않는 부분 일치이며, 검색어가 비었거나 공백뿐이면 전체
목록을 그대로 반환합니다. 장비 ID는 ASCII 영숫자이므로 부분 일치로 충분합니다.

동작 버튼은 드롭다운 내부 `#content-bottom`에 기존 `닫기` 버튼과 같은 행에
배치합니다. `#content-top`은 검색 입력창보다 위에 렌더링되므로, 검색 결과에
작용하는 버튼을 검색창 위에 두는 어색한 배치가 됩니다.

```text
┌ 장비 ID 검색… ─────────────────┐
│  ☑ TP0301   ☐ TP0302   …       │
├────────────────────────────────┤
│ [전체 선택 12] [해제]   [닫기] │
└────────────────────────────────┘
```

선택과 해제 모두 검색 결과를 범위로 삼습니다.

| 동작 | 결과 |
| --- | --- |
| 전체 선택 | `기존 선택 ∪ 검색 결과` |
| 해제 | `기존 선택 − 검색 결과` |

`전체 선택`이 합집합인 이유는 검색 범위 밖에서 이미 고른 장비를 잃지 않기
위함입니다. `해제` 역시 검색 결과만 대상으로 하며, 검색창이 비어 있으면
검색 결과가 전체 목록이므로 기존의 전체 해제 동작이 그대로 유지됩니다.

선택 버튼 문구는 검색어가 없으면 `전체 N대 선택`, 검색어가 있으면
`검색 결과 N대 선택`으로 바뀌어 어떤 집합에 작용하는지 드러냅니다. `N`은
현재 검색 결과의 개수입니다. 선택 버튼은 검색 결과가 모두 이미 선택되어
있을 때, 해제 버튼은 검색 결과 중 선택된 것이 없을 때 비활성화합니다.

바 우측의 기존 `전체`·`해제` 버튼은 제거합니다. 동일해 보이는 두 조작
수단이 서로 다르게 동작하는 상태를 만들지 않기 위함입니다.

### 2. 시계열 차트 가로 눈금선 제거

y축에 `splitLine: { show: false }`를 지정합니다. Hardware 차트는 테마
furniture(`echartsThemes.ts`)에서 `splitLine`을 물려받으므로 기본값이
표시입니다.

| 파일 | 위치 | 차트 |
| --- | --- | --- |
| `BsmTrendChart.vue` | yAxis | BSM · MDC 시계열 · SCE · Sharpness 추세 (공유 컴포넌트) |
| `FdcPanel.vue` | ratio 축 (grid 0) | FDC 비율 시계열 |
| `FdcPanel.vue` | % vs baseline | FDC 기준선 대비 |
| `FdcPanel.vue` | 온도 축 | FDC 온도 시계열 |
| `ResoCenterPanel.vue` | nm 축 | Reso 드리프트 시계열 |

`ScePanel`의 시계열 축과 `FdcPanel`의 grid 1 축은 이미 꺼져 있으므로
수정하지 않습니다.

시계열이 아닌 차트는 그대로 둡니다. MDC 박스플롯과 0°/90° 궤적, SCE 프로파일,
Sharpness 프로파일, ResoCenter CenterX/Y 산점도, FDC 쌍 산점도, FDC SPM 인덱스
프로파일, BSM 레이더가 이에 해당합니다. 산점도와 박스플롯은 값을 읽을 때
눈금선에 더 의존하기 때문입니다.

시간축(세로) 눈금선은 유지합니다. 세로선은 타임스탬프를 짚어 주는 역할을
하며, 좁은 y축에서 데이터로 오인되는 선은 가로선이기 때문입니다.

공용 헬퍼 함수는 만들지 않습니다. 해당 파일들은 이미 축 설정을 인라인으로
전개(`...ratioAxis`, `...yRange`)하고 있고 `FdcPanel`·`ScePanel`이 같은
인라인 형태로 `splitLine`을 끄고 있으므로, 래퍼를 추가하면 기존 코드보다
간접 참조만 늘어납니다.

## 구현 중 확인한 사항

구현 과정에서 두 가지를 확인하여 설계를 조정하였습니다.

첫째, `USelectMenu`의 `reset-search-term-on-select` 기본값이 `true`입니다.
항목을 고를 때마다 검색어가 지워지므로 계열별로 여러 대를 고르는 흐름이
끊깁니다. 이 값을 `false`로 지정합니다.

둘째, 트리거 라벨은 별도 처리가 필요하지 않습니다. `getDisplayValue`는
`:items`에서 값을 찾지 못하면 `foundItem ?? value`로 원래 값을 그대로
문자열화하므로, 검색으로 걸러진 선택 항목도 트리거에 정상 표시됩니다.
필터링을 부모로 옮겨도 이 부분은 영향을 받지 않습니다. 브라우저에서
`PCD685`·`PCD697`을 고른 뒤 `PCD4`로 검색하여 확인하였습니다.

항목은 `{label, value}` 객체가 아니라 장비 ID 문자열 배열을 그대로
넘깁니다. 라벨과 값이 같으므로 객체로 감쌀 이유가 없습니다.

셋째, 동작 버튼이 listbox 안에 있으므로 키보드 입력을 막아야 합니다. 버튼에
포커스를 두고 Enter 를 누르면 이벤트가 Reka 로 올라가 버튼의 기본 동작이
취소되고 하이라이트된 항목이 대신 토글됩니다. 실제로 `전체 5대 선택` 버튼에서
Enter 를 눌렀을 때 5대가 아니라 하이라이트된 1대만 선택되는 것을 브라우저에서
확인하였습니다. 푸터에서 `@keydown.enter.stop` 과 `@keydown.space.stop` 으로
키를 멈춰 버튼이 버튼답게 동작하게 합니다. 마우스 클릭으로는 드러나지 않는
경로입니다.

알려진 상위 라이브러리 문제(수정하지 않음): 검색 결과가 0건이면 Reka 가
이전 하이라이트를 지우지 않아 `aria-activedescendant` 가 사라진 요소를
가리킵니다. 필터를 누가 계산했는지와 무관하게 렌더링된 목록이 비면 동일하게
발생하므로 이번 변경으로 생긴 문제가 아닙니다.

## 후속: SCE 버전 선택기도 같은 형태로

비교 장비 선택기를 바꾸자 같은 화면의 SCE `버전 선택` 선택기와 어긋났습니다.
이쪽은 `전체`·`최근 3개` 버튼이 메뉴 바깥에 남아 있어, 겉보기가 같은 두
선택기가 서로 다르게 동작하였습니다. 사용자 요청으로 이것도 맞추었습니다.

두 선택기의 차이 때문에 그대로 복사할 수는 없었습니다.

| 항목 | 비교 장비 | SCE 버전 |
| --- | --- | --- |
| label 과 value | 같음 (장비 ID) | 다름 (`2026-07-01 ~ 07-23 · 12회` vs 첫 날짜) |
| 항목 형태 | 문자열 배열 | `{label, value}` 객체 |
| 축소 동작 | 해제 | 최근 3개 |
| 푸터 배치 | 한 줄 | 두 줄 |

따라서 필터 헬퍼를 `filterByTerm(items, term, text)` 로 일반화하였습니다.
`text` 로 검색 대상 필드를 고르며, SCE 는 label 을 넘깁니다. label 은
USelectMenu 가 기본으로 쓰는 필드(`filterFields = [labelKey]`)이므로 기존
검색 동작이 그대로 유지됩니다.

해제 버튼은 추가하지 않았습니다. SCE 는 선택이 비면 "비교할 설정 버전을
선택하세요" 안내만 남으며, `최근 3개` 가 이미 되돌아가는 수단입니다.

푸터가 두 줄인 이유는 폭입니다. 비교 장비 선택기의 트리거는 `flex-1` 이라
넓지만 버전 선택기는 17rem 이어서, 한글 라벨 3개를 한 줄에 두면 단어 중간에서
줄바꿈이 일어납니다(`전체 3개 선 택`). 첫 줄에 동작 2개, 둘째 줄에 `닫기` 를
둡니다.

## 검증

- `filterToolIds` 단위 테스트를 `hardwareCompare.test.ts`에 추가합니다.
  빈 검색어, 공백 검색어, 대소문자 혼용, 부분 일치, 무매칭을 확인합니다.
- `npm test`, `npm run lint`, `npm run typecheck`를 실행합니다.
- 브라우저에서 Hardware 페이지의 MDC·SCE 탭을 확인합니다. 검색어 입력 후
  `전체 선택`이 검색 결과만 추가하는지, `해제`가 검색 결과만 제거하는지,
  시계열 차트에서 가로선이 사라졌는지 확인합니다.
