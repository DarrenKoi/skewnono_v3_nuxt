# 03: 스토리지·장비 리스트에서 "파일 열기"로 진입

**What to build:** 장비 관리자가 `장비 상태`의 `스토리지` 표나 `장비 리스트` 표에서 장비 행의 "파일 열기"를 누르면, 그 장비의 탐색기가 바로 열립니다. URL을 직접 입력할 필요가 없어집니다.

**Blocked by:** 02 (관리자 전용 파일 탐색기)

**Status:** done (2026-10-17)

- [x] 스토리지 표와 장비 리스트 표의 각 행에 "파일 열기" 액션을 둡니다
- [x] 액션은 해당 행의 tool, fab, eqp_id로 탐색기 URL을 엽니다. 대상 장비는 서버가 sem_list에서 다시 해석합니다
- [x] 스토리지 행에 남은 장비 정보가 이미 오래되어 서버 해석이 실패하면(404·409), 탐색기 화면에 그 이유를 표시합니다
- [x] 액션은 권한과 관계없이 보입니다. 권한 판정은 탐색기 페이지가 합니다
- [x] 기존 표의 레이아웃·정렬·필터 동작이 바뀌지 않습니다
- [x] `browser-verify` 스킬로 두 표에서 진입하는 것을 각각 확인합니다

## Comments

- 두 표 모두 기존 행 버튼 패턴(장비 리스트의 `H/W 상태`·`스큐보아` 버튼)을 따라 Equipment ID 칸 안에 `파일 열기` 버튼(NuxtLink `to`)을 두었습니다. 새 열은 만들지 않았습니다.
- URL은 `/ebeam/<toolType>/<fabSegment(행의 fab_name)>/tool-files?eqp=<eqp_id>`입니다. 다중 fab 화면(`r3,m16a`)에서도 행 자신의 fab으로 갑니다. 한 줄 식이라 별도 helper·테스트는 만들지 않았습니다.
- 장비 리스트는 VeritySEM·Provision에서도 쓰이는데 탐색기 페이지는 cd-sem·hv-sem에만 있으므로, 그 두 계열에서만 버튼을 그립니다(`SEM_TOOL_TYPES`). 권한은 보지 않습니다.
- 404·409 안내는 02의 `toolFilesErrorMessage`가 이미 표시하므로 ToolFilesView·toolFiles.ts는 바꾸지 않았습니다. 브라우저에서 `eqp=NOPE999`(404)와 중복 ID `HCDX356`(409) 모두 이유가 보이는 것을 확인했습니다.
