# opencode 연동 리뷰 스킬 3종

Status: 구현 완료 · 수용 테스트 진행
작성: 2026-08-10

## 배경

리뷰와 단순화 판단을 Claude 혼자 내리면, 그 코드를 쓴 맥락과 가정을 그대로
안고 보게 됩니다. 같은 전제 위에서 다시 읽는 것이라 놓친 것을 놓친 채로
넘어가기 쉽습니다.

로컬에 `opencode` CLI 가 설치되어 있고 (v1.18.15), OpenCode Go·Zen 두 자격증명으로
78개 모델을 부를 수 있습니다. 이 대화의 맥락을 전혀 모르는 모델에게 diff 를
직접 읽히면, 프레이밍이 다른 제2의 시선을 얻을 수 있습니다.

기존 `/code-review` 와 `/simplify` 의 판단 구조는 그대로 두고, **판단의 주체만
opencode 모델로 옮기는 것**이 이 작업의 목표입니다.

## 모델 티어

사용자가 지정한 3단계입니다. 복잡도가 높은 쪽이 위입니다.

| 티어 | 모델 | 사용 기준 |
| --- | --- | --- |
| `heavy` | `kimi-k3` | 10개 파일 초과, 교차 feature 계약, 보안, mock→office 전환 관련 |
| `medium` | `glm-5.2` | 일반적인 feature 단위 변경 (3~10개 파일) |
| `light` | `gpt-5.6-luna` | 단일 파일, 문서, 테스트, 기계적 변경 |

**승급 규칙** — 크기와 무관하게 `providers/`, `contracts.py`,
`_runtime/`, `docs/datatables/` 를 건드리면 한 단계 올립니다. 이 표면들은
집에서 실패하지 않고 사무실에서만 실패하기 때문입니다.

## 구성

```text
.claude/skills/
  _opencode/          SKILL.md 이 없으므로 스킬로 로드되지 않습니다
    oc.sh             opencode 를 호출하는 유일한 지점
    models.md         티어 표와 승급 규칙
    smells.md         Fowler 냄새 기준 + 이 저장소 고유 항목
  oc-review/SKILL.md
  oc-simplify/SKILL.md
  oc-discuss/SKILL.md
```

### `oc.sh` — 단일 호출 지점

세 스킬이 주장하는 안전 속성은 전부 이 스크립트 한 곳에서 강제합니다.

- **읽기 전용** — 항상 `--agent plan` 으로 실행합니다. 이것은 프롬프트 관례가
  아니라 opencode 가 도구 권한으로 강제하는 샌드박스입니다. 실측으로
  확인했습니다: `plan` 에이전트에 파일 생성을 지시하면 계획만 내놓고 파일은
  만들지 않으며, 그러면서도 `git diff` 는 정상 실행합니다.
- **공급자 폴백** — `opencode-go/<model>` 를 먼저 시도하고, 실패하면
  `opencode/<model>` (Zen) 로 재시도합니다. 둘 다 실패하면 각각의 사유를
  출력하고 비정상 종료합니다. **더 약한 모델로 조용히 내려가지 않습니다.**
  들은 것과 다른 티어에서 돌아간 리뷰는, 아예 돌지 않은 리뷰보다 나쁩니다.
- **세션 id 반환** — `oc-discuss` 가 특정 대화를 이어갈 수 있도록 stderr 로
  `OC_SESSION=<id>` 를 출력합니다. `opencode run -c` 는 전역 최근 세션을
  잇기 때문에 토론이 겹치면 경합합니다.

### 구현 중 실측으로 드러난 것

문서보다 실행이 알려준 것들이라 남깁니다.

| 사실 | 영향 |
| --- | --- |
| **`--format json` 은 도구 호출이 끼면 최종 답변을 아예 내보내지 않습니다** | JSON 기반 초기 구현이 리뷰에서 빈 응답만 받았습니다. 기본 포맷으로 전환했습니다 |
| 기본 포맷은 stdout 에 답변 본문만, 배너와 오류는 stderr 로 보냅니다 | stdout 을 그대로 캡처해도 안전합니다 |
| `opencode run` 은 위치 인자가 없으면 **stdin 에서 프롬프트를 읽습니다** | 큰 diff 를 argv 로 넘길 때의 E2BIG·`ps` 노출·선행 `-` 문제를 모두 없앱니다 |
| 백그라운드 워치독이 stdout 을 물고 있으면 `$(oc.sh ...)` 가 타임아웃 전체 동안 멈춥니다 | 워치독의 두 스트림을 `/dev/null` 로 분리해야 합니다 |
| 종료 코드만으로는 워치독이 쐈는지 알 수 없습니다 | 워치독이 플래그 파일을 남기고, 그 존재로 판정합니다 |
| 세션 id 는 `--title` 로 태그를 달고 `session list` 에서 찾습니다 | 시도마다 태그를 달리해야 실패한 Go 세션을 잘못 집지 않습니다 |
| 없는 모델 id 는 진단을 남기지 않습니다 | 진단이 비면 "철자 확인" 안내로 대체합니다 |
| `opencode models` 는 권한이 아니라 카탈로그를 보여줍니다 | 목록에 있어도 호출 시 `Model is disabled` 가 납니다 |

### 모델 신뢰도 실측 (2026-08-10)

| 모델 | 단순 프롬프트 | 도구 사용 리뷰 |
| --- | --- | --- |
| `kimi-k3` | 정상 | **정상** (137s·194s, 지적이 구체적이고 정확) |
| `glm-5.2` | 정상 | **실패 2/2** (무관한 환각 문서 1회, 빈 최종 메시지 1회) |
| `gpt-5.6-luna` | 정상 | 장문 미검증 |

이 때문에 `oc-review` 와 `oc-simplify` 의 기본 티어를 `medium` 이 아니라
`heavy` 로 두었습니다. 리뷰는 도구를 쓰는 작업이고, `glm-5.2` 가 무너진 지점이
정확히 그 모양이었습니다. 티어 정의 자체는 사용자가 정한 대로 두고, 신뢰도
관찰만 `models.md` 에 표로 분리했습니다. 재측정해서 정상이면 되돌리면 됩니다.

`oc.sh` 는 빈 응답을 성공으로 출력하지 않고 비정상 종료하므로, 이 실패가
"지적 없음" 으로 조용히 보고되는 경로는 막혀 있습니다.

### 자기 리뷰로 잡은 것

구현한 `oc.sh` 를 `kimi-k3` 에게 읽히자 실제 결함 4건을 지적했고 전부
고쳤습니다. 프롬프트를 argv 로 넘기던 문제(E2BIG·`ps` 노출), SIGKILL 승격이
없던 워치독, 타임아웃을 공급자 실패로 오인해 Zen 에 재시도하던 흐름, 그리고
Go·Zen 두 시도가 같은 태그를 써서 세션 조회가 죽은 쪽을 집을 수 있던 문제입니다.
스킬의 존재 이유를 스킬 자신이 입증한 셈이라 남겨 둡니다.

### 세 스킬

| 스킬 | 질문 | 축 |
| --- | --- | --- |
| `oc-review` | 맞는가, 그리고 요청한 것인가 | Standards · Spec 병렬 실행 후 Claude 의 견해 |
| `oc-simplify` | 동작은 그대로 두고 더 깨끗해질 수 있는가 | 재사용 · 단순화 · 효율 · 고도 |
| `oc-discuss` | 이 판단이 공격을 견디는가 | 최대 3라운드 반박, AGREED / DISPUTED / I-WAS-WRONG |

`oc-review` 의 세 번째 절이 이 스킬의 핵심입니다. opencode 의 지적 중 틀렸다고
보는 것을 **명시적으로 반대 의견으로 적습니다**. 조용히 버린 지적은 사용자가
판단할 기회를 잃은 지적입니다.

## 안전 경계

- opencode 는 파일을 쓰지 않습니다. 수정은 Claude 가 `Edit` 로 적용하고,
  `CLAUDE.md` 규칙대로 **명시적 pathspec** 으로만 커밋합니다. 여러 파일에
  걸치면 `git worktree` 에서 작업합니다 — 리뷰 결과 수정은 대개 그렇습니다.
- 이 저장소는 여러 에이전트 세션이 작업 트리를 공유하므로, opencode 에
  쓰기 권한을 주는 선택지는 채택하지 않았습니다.
- 프롬프트 주입 — opencode 가 diff 를 직접 읽으므로 적대적 문자열이 리뷰
  결과를 왜곡할 수 있습니다. 파일을 쓰지는 못하므로 (`plan` 이 차단) 피해는
  "틀린 지적" 에 한정되며, Claude 가 결과를 읽고 판단하는 것으로 완화합니다.

## 열린 질문

- Go 플랜의 "(2x usage)" 표기는 사용량 2배 **허용**으로 이해하고 `light` 티어를
  가장 싼 것으로 두었습니다. 반대 의미라면 `models.md` 의 티어 표를 고쳐야
  합니다.
- 78개 모델 중 실제로 호출 가능한 것의 전수 목록은 만들지 않았습니다. 세 티어
  모델만 `opencode-go/` 에서 응답을 확인했습니다.
