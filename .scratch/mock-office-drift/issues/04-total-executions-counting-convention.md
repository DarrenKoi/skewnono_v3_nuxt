# total_executions 카운팅 규약이 한 파일 안에서도 혼용된다

Type: bug
Status: needs-triage
검증: 에이전트 보고(미확인) — 착수 전 원본 대조 필요

## 갈리는 지점

`recipe_tat` 과 `fail_issue` 의 office 어댑터는 "실행 건수"를 **두 가지 방식**
으로 셉니다:

- 요약 카드 — `value_count(meastime)`: `meastime` 필드가 **있는** 문서만
- 트렌드 / 순위 / 그리드 — `doc_count`: **모든** 문서

mock 은 어디서나 행을 셉니다(= `doc_count` 쪽).

## 결과

이건 집↔사무실 차이이면서 동시에 **사무실 화면 내부의 모순**입니다.

`meastime` 이 null 인 문서가 하나만 있어도

- 요약 카드의 총 실행 수가 **자기 트렌드 차트의 합과 어긋나고**,
- `avg_meastime` 이 부풀려집니다 (분모만 줄어드므로).

사용자가 "카드 숫자와 차트 합이 다르다"고 신고하면 원인 추적이 매우 어렵습니다.

## 필요한 판단

- 실행 건수의 정의는 **문서 수**인가 **측정시간이 기록된 문서 수**인가?
- `meastime` 이 null 인 문서가 실물에 존재하는가? (`OFFICE-VERIFY`)
  없다면 두 규약이 같은 값이므로 일관성만 맞추면 됩니다.
- `avg_meastime` 의 분모는 위 결정과 **같아야 합니다** — 지금은 다릅니다.

## 착수 시

이 규약은 두 feature 에 복제돼 있고 한 파일 안에서도 섞여 있습니다.
`_office_meas_hist.py` 에 카운팅 헬퍼를 하나 두고 모든 집계가 그것을 쓰게 하는
형태여야 재발하지 않습니다. 03번과 함께 결정하면 한 번에 정리됩니다.
